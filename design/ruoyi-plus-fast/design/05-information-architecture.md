# Skyroc Admin 信息架构

## 1. 文档目的

本文将功能地图转化为导航、页面层级和路由组织建议。当前信息架构是首期提案，需要在产品范围、角色和后端菜单契约确认后定稿。

## 2. 架构原则

1. 按用户任务和业务对象组织，不按前端包名或后端表名组织。
2. 一级导航保持稳定，不让低频技术功能占据主要位置。
3. 列表页通常作为模块入口，详情和编辑页可以不出现在菜单中。
4. 菜单可见、路由可访问和按钮可操作分别处理。
5. 不同角色共享一套信息架构，通过权限和首页内容表达差异。
6. 导航标题使用用户能理解的业务语言。

## 3. 当前路由事实

- 当前认证入口为 `/login`。
- 当前后台首页为 `/home`。
- 后台页面位于 `/(admin)` 布局组。
- 当前应用只有一个后台菜单分类 `admin`。
- 当前环境使用静态路由模式。
- 应用代码支持从后端加载动态路由树。
- 后端路由节点可以描述标题、图标、排序、隐藏菜单、活动菜单、角色、外链和页签等信息。

## 4. 目标一级导航提案

```text
工作台
组织与用户
角色与权限
系统配置
日志与审计
```

“个人中心”建议放在右上角用户菜单，不作为主要侧边栏一级模块。

如果首期范围缩小，可以将“组织与用户”和“角色与权限”合并为“系统管理”，但页面规格仍应保留清晰业务边界。

## 6. 页面层级与路由提案

路由名称是设计阶段建议，开发前需按项目路由约定和后端契约复核。

| ------------ | ----------------------------------- | -------- | -------- |

| 角色列表     | `/system/roles`                     | 是       | 角色管理 |

## 7. 隐藏页面规则

详情、新增、编辑和授权页面通常不单独显示在侧边栏，但需要：

- 进入页面时激活所属列表菜单。
- 面包屑显示从模块到当前对象的层级。
- 从详情返回列表时保留合理的筛选和分页上下文。
- 直接访问时仍执行路由权限校验。
- 页面不存在与无权限使用不同状态。

在动态路由模式下，可以使用后端路由元信息中的 `hideInMenu` 和 `activeMenu` 表达这一关系。

## 8. 全局导航区域

### 8.1 侧边栏

- 产品标识。
- 一级和二级导航。
- 展开与收起。
- 当前页面状态。
- 无权限模块不显示。
- 超长标题需要截断并提供完整内容。

### 8.2 顶部栏

建议保留：

- 侧边栏折叠控制。
- 面包屑。
- 全局搜索。
- 语言切换，若首期交付英文。
- 主题切换。
- 用户菜单。

通知入口只有在存在真实通知业务时加入。

### 8.3 页签

当前主题默认启用页签和缓存。正式产品需要确认：

- 是否保留多页签。
- 固定首页能否关闭。
- 切换角色或账号时如何清理页签。
- 参数不同的同一路由是否允许多开。
- 页签过多时的管理方式。

## 9. 面包屑规则

- 不显示路由分组等技术名称。
- 列表页：`模块 / 页面`。
- 详情页：`模块 / 列表 / 对象名称或详情`。
- 编辑页：`模块 / 列表 / 对象名称 / 编辑`。
- 新增页：`模块 / 列表 / 新增`。
- 对象名称过长时截断，但保留可访问的完整名称。

## 10. 搜索与快捷访问

全局搜索应优先搜索可导航功能，不默认搜索所有业务数据。

候选范围：

- 当前用户可访问的菜单。
- 最近访问页面。
- 常用操作。

跨业务数据搜索只有在后端提供统一搜索能力时再进入设计。

## 11. 权限与导航表现

| 场景                       | 建议表现                         |
| -------------------------- | -------------------------------- |
| 没有模块权限               | 不显示对应菜单                   |
| 通过旧链接访问无权限页面   | 展示 403                         |
| 页面存在但对象不存在       | 展示对象级不存在状态             |
| 页面路由不存在             | 展示 404                         |
| 有页面权限但无某操作权限   | 隐藏或禁用操作，并按规则说明原因 |
| 角色变化导致当前页失去权限 | 提示后跳转到新的可访问首页       |

## 12. 静态与动态路由决策点

### 静态路由适合

- 菜单随前端版本发布。
- 模块数量和角色变化较少。
- 不需要后台配置菜单。

### 动态路由适合

- 菜单和角色授权由后端管理。
- 不同用户获得不同菜单树。
- 需要隐藏页、外链、排序和角色配置。

当前代码两种模式都具备基础能力。正式方案需要结合后端菜单管理能力决定，并记录到 `decisions/`。

- 首页是否始终固定。
- 是否提供全局菜单搜索。
- 是否有真实通知中心。
- 个人中心包含哪些页面。
