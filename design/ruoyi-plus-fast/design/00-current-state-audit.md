## 5. 应用架构现状

### 5.1 应用职责

当前仓库采用应用薄壳与共享能力分层的结构：

- `apps/ruoyi-plus-fast`：负责应用启动、应用配置、页面、业务接口接入和模块装配。
- `packages/web/*`：提供后台布局、主题、Ant Design 适配、通知等 Web 共享能力。
- `packages/shared/ui-tokens`：提供跨平台颜色、间距、圆角和字体令牌。
- `packages/@core/types`：提供认证、路由等共享 API 类型。

### 5.2 当前主要技术约束

- 页面使用 React、TypeScript 和 TanStack Router。
- 服务端状态使用 TanStack Query。
- 应用状态使用 Jotai 及现有共享状态能力。
- Web UI 同时存在 Ant Design、自有 UI 组件和组合组件。
- 主题由 `@skyroc/web-admin-theme` 初始化和管理。
- 页面和菜单需要符合现有后台布局的路由元信息结构。

### 5.3 对设计工作的直接影响

1. 后续页面应优先复用现有后台布局，不重新设计一套无法落地的应用框架。
2. 新颜色、间距、圆角和字号应映射到现有令牌，不建立平行 Token 系统。
3. 页面规格需要覆盖 TanStack Query 对应的首次加载、后台刷新、错误和空数据状态。
4. 页面地图必须同时考虑前端真实页面文件和后端授权菜单树。
5. 组件规范需要明确 Ant Design、自有 UI 和组合组件的选用边界。

## 7. 认证、导航与权限现状

### 7.1 认证链路

当前登录成功后的主要链路为：

```text
提交账号密码
  → 获取 access token 和 refresh token
  → 保存认证信息
  → 获取当前用户信息
  → 初始化用户菜单
  → 使路由状态失效并重新计算
  → 跳转目标页或首页
```

当前用户信息类型已经包含：

- 用户 ID
- 用户名
- 角色列表
- 按钮权限列表

类型字段存在不代表正式产品权限规则已经确定。按钮权限如何在页面中使用，仍需结合后端返回和业务需求验证。

### 7.2 路由模式

- 当前 `.env` 配置为 `VITE_AUTH_ROUTE_MODE=static`。
- 应用代码同时装配了后端动态路由加载器。
- 后端路由模型支持路径、标题、图标、排序、隐藏菜单、活动菜单、外链、页签、角色等元信息。

因此，后续信息架构需要同时说明：

1. 当前阶段采用静态还是动态路由作为正式方案。
2. 后端菜单节点如何映射到前端真实页面。
3. 隐藏详情页如何激活所属列表菜单。
4. 外链、Iframe、多页签和固定页签是否进入产品范围。

### 7.3 权限层级

需要明确区分：

| 权限层级     | 当前状态                                 |

| 菜单可见权限 | 已有基础能力，待真实数据验证             |

## 15. 审计结论

`ruoyi-plus-fast` 已具备认证、路由、菜单、主题、布局、国际化和基础反馈能力，可以作为正式后台产品的技术基础。

当前应用仍以起步模板和基础框架为主，尚未形成完整业务页面体系。进入全量高保真设计前，应先完成用户角色、首期范围、功能地图、信息架构和真实接口审计。

登录页可以作为第一个设计试点，但需要先确认正式登录方式、安全策略和注册边界；当前演示账号入口不应未经评估直接进入正式产品。
