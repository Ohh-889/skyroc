# Skyroc Admin 产品范围

## 1. 文档目的

本文用于控制首期设计和开发范围，避免将所有传统后台功能一次性纳入。当前内容是基于产品简报和现有应用能力形成的范围建议，业务方确认后才成为正式版本范围。

## 2. 范围状态

| 标记     | 含义                         |
| -------- | ---------------------------- |
| 已有基础 | 当前应用已有可复用的基础能力 |
| P0 建议  | 建议进入第一阶段设计         |
| P1 候选  | 核心路径稳定后再设计         |
| P2 储备  | 有明确业务需求后再进入       |
| 暂不纳入 | 当前阶段不设计               |
| 待确认   | 缺少产品或后端结论           |

## 3. 第一阶段目标

第一阶段目标不是完成所有后台模块，而是建立一条可验证的产品主路径：

```text
用户完成登录
  → 进入与角色匹配的后台框架和首页
  → 管理用户
  → 配置角色和访问权限
  → 查看关键操作结果和审计记录
```

同时完成可复用的列表、详情、编辑、确认和状态反馈模式。

| 角色化首页     | P0 建议  | 建立登录后的任务入口               |

## 5. P0 设计范围

### 5.1 账号认证

建议包含：

- 密码登录。
- 登录错误和网络错误。
- 会话失效。
- 退出登录。
- 登录后重定向。

是否包含以下能力待确认：

- 图形验证码。
- 记住登录。
- 忘记密码和重置密码。
- 短信或邮箱验证码。
- 第三方登录。
- 多因素认证。
- 用户注册。

### 5.2 后台框架

建议包含：

- 侧边栏和顶部栏。
- 菜单展开、收起和多级状态。
- 面包屑。
- 页签。
- 全局搜索入口。
- 语言和主题入口。
- 用户菜单。
- 页面容器。
- 403、404、500、加载和错误状态。

### 5.3 首页

建议先完成一个可按角色组合的工作台母版：

- 欢迎和身份信息。
- 待办或风险摘要。
- 快捷入口。
- 近期操作。
- 必要的业务指标。
- 空状态和无权限状态。

不在没有真实数据时堆叠装饰性图表。

### 5.4 用户管理

建议包含：

- 用户列表。
- 用户详情。
- 新增用户。
- 编辑用户。
- 启用和停用。
- 重置密码。
- 分配角色。
- 必要的批量操作。

部门、岗位、租户和数据范围字段需以真实后端契约为准。

### 5.5 角色与权限

建议包含：

- 角色列表。
- 角色详情。
- 新增和编辑角色。
- 菜单或页面授权。
- 按钮权限授权。
- 数据范围配置入口。
- 查看角色成员。
- 启用和停用角色。

数据范围具体模型待确认。

### 5.6 审计

建议包含：

- 操作日志列表。
- 操作日志详情。
- 权限变更记录。
- 用户、时间、模块、结果和操作对象筛选。

是否支持日志导出、留存期限和敏感信息脱敏待确认。

## 6. 明确不在第一阶段解决

- 所有行业业务模块。
- 所有 RuoYi 生态功能。
- 完整移动端产品。
- 自定义低代码页面搭建。
- 自定义工作流引擎。
- 复杂实时监控大屏。
- 大规模 BI 报表。
- 与正式业务无关的组件展示页。

## 7. 横向能力范围

首期页面需要统一覆盖：

- 加载、刷新、空数据、失败和无权限。
- 表单校验和提交状态。
- 单条和批量危险操作确认。
- 路由和菜单权限。
- 中文界面。
- 明暗主题的技术兼容性。
- 桌面 Web 的基本响应式。

以下能力是否作为正式验收项待确认：

- 英文完整交付。
- 暗色主题完整视觉验收。
- 平板完整适配。
- WCAG 指定等级。

## 8. 范围变更规则

新增模块进入设计前，需要回答：

1. 服务哪个角色。
2. 解决什么高频或高价值任务。
3. 是否有真实接口和字段。
4. 是否复用现有页面母版。
5. 是否影响权限、导航和数据范围。
6. 是否挤占 P0 主路径。

范围变化应同步更新：

- [04-feature-map.md](./04-feature-map.md)
- [05-information-architecture.md](./05-information-architecture.md)
- [07-page-registry.md](./07-page-registry.md)
- 必要时新增设计决策记录
