# Skyroc Admin 页面注册表

## 1. 使用说明

本文是页面设计和开发进度的唯一索引。页面进入设计或开发时，应先在本表登记唯一 ID。

### 1.1 页面状态

```text
待定义 → 已定义 → 设计中 → 待确认 → 已确认
       → 开发中 → 已实现 → 已验收
```

### 1.2 范围等级

- P0：建议进入第一阶段。
- P1：核心路径完成后进入。
- P2：有明确需求后进入。
- 待定：产品范围尚未确认。

### 1.3 当前实现标记

- 基础实现：已有页面，但尚未达到正式产品规格。
- 已实现：已按确认规格完成。
- 未实现：当前应用中没有对应页面。

## 10. 第一批页面建议

在产品范围和接口确认后，建议按以下顺序建立页面规格：

1. `AUTH-001` 密码登录。
2. `SHELL-001` 后台全局框架。
3. `DASH-001` 角色化首页。
4. `USER-001` 用户列表。
5. `USER-002` 用户详情。
6. `USER-003` 新增用户。
7. `ROLE-001` 角色列表。
8. `ROLE-005` 角色权限配置。
9. `AUDIT-001` 操作日志列表。

该顺序用于先验证登录、导航、列表、详情、表单、权限树和日志等核心页面模式。

## 11. 注册规则

新增页面时必须同步记录：

- 页面 ID。
- 页面目标。
- 服务角色。
- 所属模块。
- 路由与菜单关系。
- 正常和异常状态。
- 设计稿链接或节点。
- 实现位置。
- 验收状态。

详情、编辑、弹窗和抽屉是否需要独立 ID，按其是否具有独立流程、权限或可复用规格决定。
