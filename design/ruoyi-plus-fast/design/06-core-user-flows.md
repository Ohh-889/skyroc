# Skyroc Admin 核心用户流程

## 1. 文档目的

本文定义首期关键流程的目标、主路径、异常分支和待确认规则。流程用于发现页面和状态，不替代接口文档。

## 2. 流程编写规则

每条流程至少描述：

- 触发角色。
- 前置条件。
- 主路径。
- 异常和无权限路径。
- 成功结果。
- 涉及页面。
- 待确认业务规则。

## 3. FLOW-AUTH-001 密码登录

**角色**

所有允许进入后台的用户。

**前置条件**

- 用户拥有有效账号。
- 登录服务可用。

**主路径**

```text
打开登录页
  → 输入账号和密码
  → 前端完成必要校验
  → 提交登录请求
  → 获取访问令牌和刷新令牌
  → 获取当前用户信息
  → 初始化用户菜单和首页
  → 跳转原目标页或用户首页
  → 显示登录成功反馈
```

**异常分支**

- 必填项为空：在字段附近显示校验信息，不发请求。
- 账号或密码错误：保留账号输入，按安全策略处理密码输入。
- 账号停用或锁定：说明无法登录和允许的恢复方式。
- 网络错误：保留用户输入，提供重试。
- 登录成功但用户信息加载失败：清理无效认证状态，避免进入半登录状态。
- 用户没有可访问菜单：进入明确的无可用功能状态，而不是空白页。
- 原目标页无权限：跳转可访问首页并说明原因。

**涉及页面**

- `AUTH-001` 登录页。
- `SYS-403` 无权限页。
- `SYS-ERROR` 全局错误状态。

**待确认**

- 登录账号类型。
- 验证码和多因素认证。
- 错误次数与锁定规则。
- 是否允许注册。
- 会话有效期。

## 4. FLOW-AUTH-002 会话失效与重新登录

**主路径**

```text
用户执行操作
  → 服务端返回令牌过期
  → 客户端尝试刷新令牌
  → 刷新成功
  → 重放原请求
  → 用户继续当前任务
```

**刷新失败**

```text
刷新失败
  → 清理认证和用户数据
  → 保存可安全恢复的目标地址
  → 跳转登录页
  → 用户重新登录
  → 返回目标页或新的可访问首页
```

**设计要求**

- 不重复弹出多个会话失效提示。
- 未保存表单如何处理需要单独定义。
- 重新登录后如果权限变化，不能强行返回无权限页面。

## 5. FLOW-USER-001 创建用户

**角色**

具有用户新增权限的企业管理员或系统管理员。

**前置条件**

- 用户拥有新增权限。
- 角色、部门等依赖数据已加载。

**主路径**

```text
进入用户列表
  → 点击新增用户
  → 填写基础信息
  → 选择组织、岗位和角色
  → 检查信息和权限影响
  → 提交
  → 后端校验成功
  → 返回列表或进入用户详情
  → 显示创建成功反馈
```

**异常分支**

- 账号、手机号或邮箱重复。
- 角色已失效。
- 部门被停用。
- 用户无权分配目标角色。
- 请求失败。
- 提交过程中重复点击。

**待确认**

- 初始密码如何生成和交付。
- 是否邀请用户自行设置密码。
- 手机号和邮箱是否必填。
- 是否支持跨租户创建。
- 创建后返回列表还是详情。

## 6. FLOW-USER-002 编辑、停用和恢复用户

### 编辑用户

```text
从列表或详情进入编辑
  → 修改允许编辑的字段
  → 提交
  → 后端校验
  → 更新成功
  → 刷新相关用户信息
```

### 停用用户

```text
选择用户
  → 点击停用
  → 展示用户身份和影响说明
  → 用户确认
  → 执行停用
  → 更新状态
  → 记录操作日志
```

**设计要求**

- 禁止停用自己、超级管理员或最后一个管理员等规则需由后端确认。
- 停用是否立即终止在线会话需要明确。
- 批量停用需要显示目标数量和失败明细。
- 恢复用户时需要说明原角色和权限是否恢复。

## 7. FLOW-USER-003 重置用户密码

```text
进入用户详情或列表操作
  → 选择重置密码
  → 展示账号和安全影响
  → 选择或确认重置方式
  → 提交
  → 显示安全的结果反馈
  → 记录操作日志
```

**待确认**

- 管理员设置临时密码还是发送重置链接。
- 是否要求下次登录修改密码。
- 是否使现有会话失效。
- 是否允许显示生成后的临时密码。

## 8. FLOW-ROLE-001 创建角色并授权

**角色**

具有角色和权限管理能力的管理员。

**主路径**

```text
进入角色列表
  → 新增角色
  → 填写名称、编码和说明
  → 配置菜单和页面权限
  → 配置按钮权限
  → 配置数据范围
  → 查看授权摘要和影响提示
  → 保存
  → 返回角色详情或列表
```

**异常分支**

- 角色名称或编码重复。
- 用户尝试授予自己没有的权限。
- 权限节点在编辑期间发生变化。
- 数据范围配置无效。
- 保存部分失败或全部失败。

**设计要求**

- 页面访问、操作权限和数据范围分区表达。
- 不用一个超长树形控件承载所有概念。
- 父子节点联动规则必须可预测。
- 保存前显示关键权限和数据范围摘要。

## 9. FLOW-ROLE-002 修改角色权限

```text
进入角色详情
  → 查看当前权限和成员数量
  → 进入权限编辑
  → 修改权限
  → 系统计算影响用户和高风险变化
  → 管理员确认
  → 保存
  → 记录变更
  → 按规则通知或刷新受影响用户会话
```

**待确认**

- 权限变化是否立即生效。
- 是否需要二次审批。
- 是否允许修改超级管理员角色。
- 是否记录权限差异。
- 是否向受影响用户发送通知。

## 10. FLOW-AUDIT-001 查询操作日志

```text
进入操作日志
  → 设置时间、用户、模块、类型和结果
  → 查询
  → 查看结果列表
  → 打开某条日志详情
  → 查看主体、对象、时间、结果和上下文
```

**设计要求**

- 首次进入提供合理默认时间范围。
- 空数据和筛选无结果使用不同说明。
- 请求参数、响应内容和敏感信息需要脱敏。
- 日志详情需要兼顾可读摘要和必要的技术数据。

## 11. FLOW-NAV-001 权限变化后的导航更新

```text
用户权限被修改
  → 当前会话按既定策略获知变化
  → 重新获取用户信息和菜单
  → 更新导航和可访问路由
  → 当前页面仍有权限：继续使用
  → 当前页面失去权限：提示并跳转可访问首页
```

**待确认**

- 权限更新触发机制。
- 是否强制用户重新登录。
- 已打开页签如何清理。
- 未保存表单如何处理。

## 12. 流程覆盖检查

每个页面规格建立后，需要确认：

- 正常入口。
- 返回和取消。
- 加载和重复提交。
- 后端校验失败。
- 网络失败和重试。
- 权限不足。
- 对象不存在或已被其他人修改。
- 操作成功后的数据同步。
- 关键操作日志。
