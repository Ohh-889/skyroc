## 2. 页面目标

为已经拥有 Skyroc 企业账号的用户提供无需输入密码的登录方式。用户可以主动选择手机或邮箱接收一次性验证码，在完成身份验证后进入后台。

页面需要做到：

1. 用户能够清楚选择手机验证码或邮箱验证码。
2. 用户能够完成接收目标校验、验证码发送、倒计时和重新发送。
3. 用户能够理解发送、校验、过期、限流和账号异常等状态，并知道下一步。
4. 验证码发送和登录反馈不能泄露手机号或邮箱是否已注册。
5. 未注册账号不能通过验证码登录自动创建账号。
6. 登录成功后复用既有认证初始化链路，返回原目标页或用户首页。
7. 用户可以随时返回密码登录或选择企业支持的第三方登录方式。

## 3. 范围与边界

### 3.1 本页面包含

- 手机验证码登录。
- 邮箱验证码登录。
- 手机和邮箱登录方式切换。
- 手机号或邮箱格式校验。
- 一次性验证码发送、倒计时和重新发送。
- 按风险策略出现的图形验证码。
- 验证码登录提交。
- 登录成功后的认证初始化和安全跳转。
- 密码登录、微信登录和飞书登录入口。
- 默认、加载、成功、错误、限流和账号异常状态。

### 3.2 本页面不包含

- 用户自主注册。
- 验证码登录后自动创建账号。
- 手机号或邮箱绑定与换绑。
- 找回无法使用的手机号或邮箱。
- 密码设置或重置。
- 多因素认证配置。
- 微信和飞书授权回调的详细状态。

以上能力分别由管理员创建账号、账号安全、密码重置或第三方登录流程承载。

### 3.3 与图形验证码的区别

一次性登录验证码和图形验证码是两种不同能力：

- 一次性登录验证码发送到用户的手机或邮箱，用于证明用户可以控制该登录标识。
- 图形验证码用于识别人机和降低批量发送、撞库及接口滥用风险。

图形验证码不能代替一次性登录验证码，也不能通过独立接口提前判断用户输入是否正确。

## 4. 用户与前置条件

### 4.1 目标用户

- 已由管理员创建账号的企业用户。
- 已通过组织邀请激活账号的企业用户。
- 已由企业身份源同步，并已经绑定手机号或邮箱的用户。

### 4.2 前置条件

- 用户拥有有效的 Skyroc 企业账号。
- 账号已经绑定可用于登录的手机号或邮箱。
- 对应短信或邮件服务可用。
- 认证服务、用户信息服务和菜单服务可用。

### 4.3 不可用情况

- 账号未注册。
- 账号没有绑定所选方式的手机号或邮箱。
- 账号停用、锁定或不允许验证码登录。
- 手机号或邮箱已变更，但账号信息尚未同步。
- 短信、邮件或认证服务不可用。

## 7. 登录方式选择

### 7.1 控件

使用等宽分段控件或页签：

```text
[ 手机验证码 ]  [ 邮箱验证码 ]
```

默认选中“手机验证码”。如果未来能够安全读取用户最近使用的登录方式，可以恢复最近选择，但不能保存手机号、邮箱或验证码。

### 7.2 切换规则

从手机验证码切换到邮箱验证码，或从邮箱切换到手机时：

- 保留两种方式各自已经输入的手机号或邮箱，方便用户切回。
- 不自动发送验证码。
- 清空一次性验证码输入。
- 清除上一种方式的字段错误和登录错误。
- 分别执行手机号和邮箱格式校验。
- 已开始的倒计时继续在对应渠道内部运行。
- 切回仍在倒计时的渠道时，恢复该渠道的剩余时间。
- 不能把一个渠道收到的验证码提交给另一个渠道。

前端显示倒计时只是交互反馈，真正能否重新发送始终由后端判断。

### 7.3 键盘与无障碍

- 分段控件使用正确的单选、页签或分段控件语义。
- 左右方向键可以切换选项。
- 焦点状态清晰。
- 屏幕阅读器能够读出当前选中方式。
- 切换后将焦点移动到新渠道的登录标识字段，或通过状态说明提示内容已经变化。

## 8. 手机验证码登录

### 8.1 手机号字段

**标签**

手机号。

**占位文案**

```text
请输入手机号
```

**规则**

- 必填。
- 去除首尾空格。
- 当前按中国大陆手机号格式校验。
- 当前不展示国家或地区区号选择器。
- 使用适合手机号输入的键盘和 `autocomplete="tel"`。
- 格式不正确时不允许发送验证码。
- 错误后保留手机号。
- 不在日志、埋点、URL或错误上报中记录完整手机号。

当前仓库已有 `REG_PHONE`，可以作为前端格式校验的实现参考；后端仍需独立校验，不能直接将前端正则作为最终业务契约。

### 8.2 国际手机号

首期不纳入国际手机号。未来支持时，需要单独确认：

- 国家或地区区号选择。
- 各地区号码格式。
- 短信服务覆盖范围。
- 费用和发送频率。
- 默认区号和本地化展示。

不能只在现有字段前增加 `+86` 文案便声称已经支持国际手机号。

## 9. 邮箱验证码登录

### 9.1 邮箱字段

**标签**

邮箱。

**占位文案**

```text
请输入邮箱
```

**规则**

- 必填。
- 去除首尾空格。
- 执行基础邮箱格式校验。
- 使用 `autocomplete="email"`。
- 格式不正确时不允许发送验证码。
- 错误后保留邮箱。
- 不在日志、埋点、URL或错误上报中记录完整邮箱。

前端只做快速格式反馈，邮箱是否真实可达以及是否属于有效账号由后端处理。

### 9.2 邮件内容依赖

验证码邮件由后端邮件服务生成，至少需要包含：

- 产品名称：Skyroc。
- 操作名称：验证码登录。
- 一次性验证码。
- 有效期说明。
- “如果不是本人操作，请忽略”提示。
- 不要求用户点击未知链接。

邮件模板、发件人、退信处理和国际化不属于本页面实现范围，但必须在验证码登录上线前完成验证。

## 10. 图形验证码与风险控制

### 10.1 出现策略

图形验证码按后端安全策略出现，支持以下两种模式：

- 配置模式：发送前始终要求图形验证码。
- 风险模式：正常情况下不显示，达到风险阈值后显示。

可能触发风险验证的情况包括：

- 同一 IP 短时间频繁发送。
- 同一目标短时间频繁发送。
- 连续多次输入错误验证码。
- 后端风控判断当前请求异常。

是否显示和是否通过必须以后端响应为准。前端环境变量只能控制初始展示，不能绕过后端验证。

### 10.2 交互

- 图形验证码包含输入框、图片和刷新入口。
- 点击图片或刷新图标重新获取。
- 图片加载时保留固定尺寸，避免布局跳动。
- 刷新后清空旧图形验证码输入。
- 图形验证码错误或过期后按后端规则刷新。
- 提供“看不清？换一张”的可访问文字说明。
- 不提供独立的“验证图形验证码是否正确”接口。

### 10.3 状态

- 加载中。
- 加载失败。
- 已加载。
- 已过期。
- 输入为空。
- 输入错误。
- 刷新频率过高。

## 11. 一次性验证码

### 11.1 字段

**标签**

验证码。

**占位文案**

```text
请输入验证码
```

```text
请输入 6 位验证码
```

### 11.2 输入规则

- 必填。
- 使用六位数字，与仓库现有 `REG_CODE_SIX` 保持一致。
- 使用数字键盘和 `autocomplete="one-time-code"`。
- 允许粘贴完整验证码。
- 输入时忽略非数字字符仅限后端确定验证码只包含数字后实施。
- 验证码不能展示为密码圆点，用户需要能够检查输入内容。
- 输入最后一位后不自动提交，避免误触和无意请求。
- 按 Enter 或点击“登录”提交。

### 11.3 生命周期

后端采用以下规则：

- 验证码为六位数字，有效期为 5 分钟。
- 验证码只能成功使用一次。
- 登录成功后立即消费。
- 新验证码发送成功后，旧验证码立即失效。
- 验证失败是否消耗验证码由后端安全策略决定。
- 连续输错达到阈值后，验证码或当前验证会话失效。

前端不能根据本地时间自行判断验证码仍然有效并绕过服务端校验。

## 12. 获取验证码

### 12.1 前置校验

点击“获取验证码”前依次检查：

1. 当前渠道是否明确。
2. 手机号或邮箱是否为空。
3. 手机号或邮箱格式是否正确。
4. 当前是否需要图形验证码。
5. 图形验证码是否已输入。
6. 是否正在发送。
7. 当前渠道是否仍在倒计时。

前端校验未通过时不发送请求，将焦点移动到第一个错误字段。

### 12.2 按钮状态

| 状态       | 按钮文案或表现          | 是否可点击 |
| ---------- | ----------------------- | ---------- |
| 默认       | 获取验证码              | 是         |
| 字段为空   | 获取验证码              | 是         |
| 格式错误   | 获取验证码              | 是         |
| 发送中     | 发送中…                 | 否         |
| 发送成功   | `59s 后重新获取`        | 否         |
| 倒计时结束 | 重新获取                | 是         |
| 发送失败   | 重新获取                | 是         |
| 服务不可用 | 重新获取                | 是         |

字段为空或格式错误时允许用户点击按钮以触发表单校验，不使用长期 Disabled 隐藏错误原因。

### 12.3 发送成功

发送成功后：

- 显示非阻塞成功提示。
- 当前渠道进入倒计时。
- 焦点移动到一次性验证码输入框。
- 不清空手机号、邮箱或已经完成的图形验证码状态。
- 不在成功提示中回显完整手机号或邮箱。

统一提示：

```text
如果该账号可用，验证码将发送至填写的手机号或邮箱。
```

页面不能通过“手机号未注册”“邮箱不存在”等发送结果暴露账号存在性。

### 12.4 倒计时

- 再次发送间隔为 60 秒，并以后端返回的剩余时间校准页面倒计时。
- 按钮首次显示“59s 后重新获取”，避免发送完成后停留在“60s”造成感知延迟。
- 页面切换渠道后，对应渠道的倒计时继续。
- 页面进入后台或切换标签页后，倒计时根据绝对结束时间恢复，不能简单依赖定时器累减。
- 页面刷新后的恢复策略以后端返回的重发时间为准；不能只依赖 Local Storage 决定服务端是否允许发送。
- 倒计时结束只表示允许再次尝试，不表示后端一定接受请求。

### 12.5 发送失败

- 网络错误时保留登录标识和图形验证码以外的安全输入。
- 后端明确要求刷新图形验证码时，清空并刷新图形验证码。
- 不自动连续重试，避免重复发送。
- 不进入倒计时，除非后端已经接收请求并返回明确重试时间。
- 返回 `retryAfter` 时，按服务端值显示倒计时。

### 12.6 频率限制

后端同时限制：

- 单手机号或邮箱。
- 单账号。
- 单 IP。
- 单设备或风险会话。
- 全局短信和邮件服务速率。

前端展示后端允许公开的等待时间，不展示内部阈值、风控规则或账号匹配结果。

建议文案：

```text
操作过于频繁，请稍后再试
```

后端返回安全的重试时间时：

```text
操作过于频繁，请在 60 秒后重试
```

## 13. 登录提交

### 13.1 主按钮

- 文案：“登录”。
- 使用 Primary、Large、Block。
- 高度 `40px`。
- 圆角 `8px`。
- 提交中显示“登录中…”或加载图标。
- 提交中防止重复提交。
- 支持 Enter 提交。
- 前端校验失败时不发请求。

### 13.2 提交参数

至少包含：

- 当前验证码渠道。
- 手机号或邮箱。
- 一次性验证码。
- 是否保持登录。
- 后端要求的风险验证标识。

不能提交另一个渠道缓存的验证码，也不能把验证码放入 URL。

### 13.3 成功流程

```text
提交验证码登录
  → 后端校验账号、验证码和风险状态
  → 获取访问令牌和刷新令牌
  → setAuth
  → 获取当前用户信息
  → initAuth
  → 初始化用户菜单
  → initMenus
  → 校验原目标地址
  → 跳转原目标页或用户首页
  → 显示登录成功反馈
```

验证码登录不能另建一套用户初始化和菜单初始化逻辑，应复用现有 `useInitLogin` 或其后续抽取出的共享认证入口。

### 13.4 初始化失败

如果已经取得令牌，但用户信息或菜单初始化失败：

- 清理不完整的认证状态。
- 不进入半登录状态。
- 保留安全的原目标地址。
- 显示服务异常提示。
- 允许用户重新登录。

### 13.5 无可用权限

登录成功但用户没有可访问页面时：

```text
账号已登录，但当前没有可访问的后台功能。
请联系管理员分配权限。
```

不能展示空白首页，也不能将其误报为验证码错误。

## 14. 保持登录

文案使用“保持登录”，与密码登录保持一致。

- 默认不选中。
- 不保存手机号、邮箱或验证码。
- 选中时只影响后端签发的刷新会话有效期。
- 具体期限由后端会话策略定义。
- 公共设备不建议保持登录，可提供弱提示。
- 高权限账号是否允许长期会话由后端策略决定。

如果后端尚未支持不同会话期限，应隐藏该选项，不能只在前端保留没有实际效果的控件。

## 15. 辅助登录入口

### 15.1 密码登录

主按钮下方提供文字按钮：

```text
使用密码登录
```

点击返回 `/login`，并保留经过安全校验的原目标地址。不要把手机号、邮箱或验证码通过 URL 带回密码登录页。

### 15.2 第三方登录

保留与密码登录一致的微信和飞书登录入口：

```text
──── 其他登录方式 ────
[ 微信登录 ]  [ 飞书登录 ]
```

第三方登录流程和回调状态由 `AUTH-007` 负责，本页面只提供入口。

### 15.3 联系管理员

企业后台不开放注册，底部显示：

```text
没有账号？请联系管理员
```

不提供“立即注册”按钮，也不通过验证码发送接口隐式创建账号。

## 16. 页面状态

### 16.1 默认

- 默认选中手机验证码。
- 手机号、验证码字段为空。
- 图形验证码按策略显示或隐藏。
- 获取验证码和登录按钮可操作。

### 16.2 发送中

- 获取按钮显示“发送中…”。
- 当前渠道、登录标识和图形验证码暂时不可修改，避免请求与界面状态不一致。
- 登录按钮保持不可提交状态。
- 不使用整页遮罩。

### 16.3 已发送并倒计时

- 显示统一发送成功提示。
- 获取按钮显示剩余秒数。
- 一次性验证码字段获得焦点。
- 允许修改手机号或邮箱；修改后当前验证码视为不适用于新目标。
- 用户改回原目标时是否恢复验证码状态，以后端验证会话为准。

### 16.4 验证码错误

- 验证码字段进入错误状态。
- 保留手机号或邮箱。
- 清空一次性验证码。
- 聚焦验证码字段。
- 发送倒计时继续。
- 不自动重新发送。

建议文案：

```text
验证码错误或账号不可用，请检查后重试
```

### 16.5 验证码过期

- 验证码字段进入错误状态。
- 保留手机号或邮箱。
- 清空一次性验证码。
- 获取按钮在后端允许时恢复为“重新获取”。

建议文案：

```text
验证码已失效，请重新获取
```

### 16.6 尝试次数过多

- 当前一次性验证码失效。
- 清空验证码。
- 按后端返回值进入等待状态。
- 必要时出现图形验证码。

建议文案：

```text
验证失败次数过多，请稍后重新获取
```

### 16.7 账号停用或锁定

只有在后端确认当前响应可以公开账号状态时，显示：

```text
该账号当前无法登录，请联系管理员
```

不展示内部停用原因、锁定阈值、权限编码或安全策略细节。

### 16.8 网络错误

- 保留手机号或邮箱。
- 保留尚未提交的一次性验证码。
- 显示“网络连接异常，请检查网络后重试”。
- 不自动连续请求。

### 16.9 服务异常

短信、邮件服务异常：

```text
验证码暂时无法发送，请稍后重试
```

认证服务异常：

```text
登录服务暂时不可用，请稍后重试
```

### 16.10 已登录用户访问

已登录用户访问 `/login/code` 时：

- 原目标地址安全且有权限时，进入原目标页。
- 否则进入用户首页。
- 不再次展示验证码表单。

## 18. 安全与隐私

### 18.1 前端要求

- 手机号、邮箱和验证码不得写入 URL。
- 验证码不得写入 Local Storage、Session Storage 或持久化状态。
- 验证码不得进入日志、埋点或错误上报。
- 发送和登录请求必须使用 HTTPS。
- Redirect 只允许安全的站内路径。
- 不根据前端倒计时决定后端是否允许发送。
- 不通过按钮 Disabled 代替后端限流。
- 不提供账号存在性查询或图形验证码验证接口。
- 页面卸载时清理验证码和风险验证相关的内存状态。
- 防止重复发送和重复登录提交。

### 18.2 后端依赖

- 手机号和邮箱规范化及独立校验。
- 账号存在性保护。
- 验证码安全随机生成。
- 验证码加密或不可逆存储。
- 验证码有效期、一次性消费和错误次数限制。
- 新验证码使旧验证码失效。
- 单目标、单账号、单 IP 和风险会话限流。
- 图形验证码或其他人机验证。
- 防重放和并发消费。
- 账号停用、锁定和登录权限校验。
- Refresh Token 生命周期。
- 登录日志和安全审计。
- 短信与邮件供应商错误隔离。

### 18.3 账号存在性保护

发送接口对以下情况使用一致的外部响应：

- 账号存在并允许发送。
- 手机号或邮箱未注册。
- 账号没有绑定当前渠道。
- 账号状态不允许发送。

统一反馈：

```text
如果该账号可用，验证码将发送至填写的手机号或邮箱。
```

后端可以在内部记录真实结果，但不能将账号匹配情况直接返回给匿名调用方。

### 18.4 验证码消费

验证码校验和消费必须由后端原子完成，不能采用“先查询是否正确，再单独删除”的可重放流程。前端不能通过先调用验证接口、再调用登录接口拆分验证码消费。

## 19. 无障碍

- 页面和表单使用正确的标题语义。
- 每个字段都有常驻可见标签和可访问名称。
- 错误信息与对应字段关联。
- 表单提交失败后聚焦第一个错误字段或错误摘要。
- 手机和邮箱切换不能只依赖颜色区分。
- 图形验证码图片、刷新按钮和获取验证码按钮都有可访问名称。
- 倒计时变化不能每秒打断屏幕阅读器。
- 发送成功、限流和服务错误使用合适的状态播报。
- 所有操作可通过键盘完成。
- Tab 顺序与视觉顺序一致。
- 焦点状态清晰。
- 文本和背景满足 WCAG AA 对比度要求。

## 20. 响应式布局

### 20.1 宽屏桌面 `>= 1200px`

- 使用品牌区和登录区左右分栏。
- 登录表单保持约 `400px` 宽。
- 品牌区不抢占表单注意力。

### 20.2 普通桌面 `992px - 1199px`

- 保留双栏。
- 缩小品牌区留白和装饰范围。
- 登录表单宽度保持稳定。

### 20.3 平板 `768px - 991px`

- 可弱化或隐藏品牌视觉。
- 保留 Logo、产品名和核心表单。
- 获取验证码按钮仍与输入框同行。

### 20.4 窄屏 `< 768px`

- 使用单列布局。
- 隐藏品牌视觉，只保留 Logo 和产品名称。
- 表单宽度为容器宽度。
- 页面左右安全间距建议 `24px`。
- 获取验证码按钮宽度固定在可容纳倒计时文案的范围。
- 极窄屏或英文长文案下允许验证码输入框和获取按钮上下排列。
- 主题和语言入口不能遮挡标题或表单。

## 21. 主题、语言与动效

### 21.1 主题

- 支持浅色和深色主题。
- 输入框自动填充样式不能破坏主题。
- 错误、成功和焦点状态在两种主题下均清晰。
- 短信、邮箱、微信和飞书图标不能依赖不适配深色主题的固定背景。

### 21.2 国际化

- 页面文案不得直接硬编码。
- 中文和英文纳入设计验收。
- 获取验证码按钮需为英文长文案预留宽度。
- 倒计时使用国际化插值，不拼接固定中文单位。
- 手机号格式和国际区号首期仍按已确认业务范围处理，不能因界面支持英文便自动扩展为国际手机号。

### 21.3 动效

- 页面切换使用轻量淡入或位移动效。
- 手机和邮箱内容切换不使用大幅滑动。
- 尊重系统减少动态效果设置。
- 不为倒计时添加持续闪烁、脉冲或进度动画。

工程边界：

- `ImageCaptchaField` 与密码登录复用同一个业务组件。

- 认证成功后的用户信息和菜单初始化复用现有认证链路。
- 不在组件中自行实现请求缓存、自动重试或并发去重。

## 23. 接口影响

当前仓库只有密码登录和图形验证码类型，没有验证码发送与验证码登录契约。验证码登录确定使用 `challengeId` 绑定渠道、目标、验证码和风险上下文，以下是待后端实现的目标契约。

### 23.1 发送验证码

```ts
type LoginCodeChannel = 'email' | 'sms';

interface SendLoginCodeParams {
  /** 图形验证码内容，仅风控要求时提交 */
  captchaCode?: string;

  /** 图形验证码唯一标识，仅风控要求时提交 */
  captchaUuid?: string;

  /** 验证码发送渠道 */
  channel: LoginCodeChannel;

  /** 手机号或邮箱 */
  target: string;
}

interface SendLoginCodeResponse {
  /** 是否需要补充图形验证码 */
  captchaRequired?: boolean;

  /** 服务端生成的验证码登录会话标识 */
  challengeId: string;

  /** 验证码过期秒数 */
  expiresIn: number;

  /** 再次发送前需要等待的秒数 */
  retryAfter: number;
}
```

`challengeId` 用于绑定渠道、目标、验证码和风控上下文，避免客户端在登录请求中自行拼装可信状态。它不能包含可以被前端解码的手机号、邮箱或验证码。

### 23.2 验证码登录

```ts
interface CodeLoginParams {
  /** 服务端生成的验证码登录会话标识 */
  challengeId: string;

  /** 一次性验证码 */
  code: string;

  /** 是否保持登录 */
  remember?: boolean;
}

type CodeLoginResponse = Api.Auth.LoginToken;
```

### 23.3 错误语义

后端需要提供稳定、可映射但不过度暴露安全细节的错误语义：

- 参数格式错误。
- 需要图形验证码。
- 图形验证码错误或过期。
- 发送频率过高及安全的 `retryAfter`。
- 一次性验证码错误或过期。
- 验证尝试次数过多。
- 账号当前不可登录。
- 验证码服务不可用。
- 认证服务不可用。

前端展示文案由国际化资源控制，不直接显示后端异常信息。

## 24. 登录日志与可观测性

### 24.1 安全审计

后端建议记录：

- 验证码发送渠道。
- 发送结果分类。
- 登录成功或失败结果。
- 匿名化或脱敏后的目标标识。
- IP、设备和风险结果。
- 账号停用、锁定或无权限等内部原因。

验证码本身不得写入日志。

### 24.2 前端事件

如产品启用匿名行为分析，可以记录：

- 进入验证码登录页。
- 选择手机或邮箱渠道。
- 点击获取验证码。
- 验证码发送成功或失败的非敏感分类。
- 验证码登录成功或失败的非敏感分类。
- 返回密码登录。

事件中不得包含手机号、邮箱、验证码、`challengeId`、Token 或后端原始异常。

- 获取验证码按钮 Default、Loading、Countdown、Retry 和 RateLimited。
- 验证码字段 Default、Focus、Filled、Error 和 Disabled。
- 主按钮 Default、Hover、Pressed、Loading 和 Disabled。

## 26. 验收标准

### 26.1 功能

- 用户可以选择手机验证码或邮箱验证码。
- 手机和邮箱分别执行正确的格式校验。
- 切换渠道不会自动发送验证码。
- 用户可以获取验证码并看到发送状态。
- 发送成功后进入倒计时。
- 两个渠道分别维护倒计时和发送状态。
- 用户可以输入、粘贴和提交一次性验证码。
- 用户修改登录标识后不会误用旧目标的验证码。
- 提交中不能重复触发。
- Enter 可以提交登录。
- 用户可以返回密码登录。
- 用户可以选择微信或飞书登录。
- 登录成功后复用既有认证初始化链路。
- 登录成功后返回安全的原目标页或用户首页。
- 已登录用户访问页面时自动离开登录页。

### 26.2 状态

- 覆盖字段校验、发送中、倒计时、发送失败、限流、验证码错误、验证码过期、尝试次数过多、账号不可登录、网络错误和服务异常。
- 风控要求时能够出现图形验证码。
- 所有错误都有明确下一步。
- 登录失败不清空无关字段。
- 网络错误不会触发自动连续发送。
- 无可用权限时不展示空白页。

### 26.3 安全

- 未注册账号不能自动创建账号。
- 发送结果不暴露手机号或邮箱是否注册。
- 验证码、手机号和邮箱不进入 URL、日志、埋点或持久化状态。
- 验证码由后端校验并原子消费。
- 后端独立执行有效期、错误次数和发送频率限制。
- 新验证码与旧验证码的失效关系明确。
- Redirect 仅允许安全站内路径。
- 前端不提供账号或图形验证码验证预言接口。

### 26.4 视觉与无障碍

- 使用 [Design System](../../design-system.md) 中的颜色、间距、圆角和控件高度。
- 登录页大号输入框和按钮统一使用 `8px` 圆角。
- 页面标题居中，字段标签和表单内容左对齐。
- 桌面端和窄屏布局完整。
- 浅色和深色主题可用。
- 中文和英文长文案不会破坏布局。
- 表单可通过键盘完成。
- 错误与字段正确关联。
- 手机和邮箱选中状态不只通过颜色表达。
- 倒计时不会每秒打断屏幕阅读器。
