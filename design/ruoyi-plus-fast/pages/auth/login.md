## 2. 页面目标

为企业后台用户提供安全、清晰、低干扰的登录入口，并在登录失败、需要验证码、忘记密码或使用企业第三方身份时提供连续、可恢复的流程。

页面需要做到：

1. 用户能够快速完成账号密码登录。
2. 图形验证码清晰可用，并支持主动刷新。
3. 用户可以选择是否保持登录状态。
4. 用户能够进入验证码登录和密码重置流程。
5. 用户能够通过微信或飞书完成第三方身份认证。
6. 所有失败状态都能说明下一步，而不是只显示“登录失败”。
7. 已登录用户访问登录页时自动返回目标页或首页。

## 4. 页面族范围

登录不是一个孤立页面，本轮按一套账号入口设计。

| 页面 ID  | 页面           | 建议路径                   | 本轮要求     |
| -------- | -------------- | -------------------------- | ------------ |
| AUTH-001 | 密码登录       | `/login`                   | P0，完整设计 |
| AUTH-006 | 验证码登录     | `/login/code`              | P0，完整设计 |
| AUTH-002 | 忘记密码       | `/forgot-password`         | P0，完整设计 |
| AUTH-003 | 重置密码       | `/reset-password`          | P0，完整设计 |

## 7. 密码登录功能

### 7.1 账号输入

**标签**

账号。

**占位文案**

账号支持用户名、手机号和邮箱三种标识。

占位文案：

```text
请输入用户名、手机号或邮箱
```

当前接口字段只有 `userName`，实现前需要将其扩展为统一登录标识，或者增加新的 `account` 字段。

**规则**

- 必填。
- 标签始终显示在输入框上方。
- 去除首尾空格。
- 不自动修改用户输入的大小写。
- 支持浏览器和密码管理器自动填充。
- 错误后保留账号输入。
- 不在正式环境预填演示账号。

### 7.2 密码输入

**标签和占位文案**

- 标签：“密码”。
- 占位文案：“请输入密码”。

**规则**

- 必填。
- 标签始终显示在输入框上方。
- 默认隐藏。
- 提供显示和隐藏按钮。
- 支持密码管理器。
- 检测 Caps Lock 并提供非阻塞提示。
- 不对用户输入自动去除空格。
- 不在前端暴露具体账号是否存在。

### 7.3 图形验证码

图形验证码由验证码输入框、验证码图片和刷新入口组成。

**标签和占位文案**

- 标签：“图形验证码”。
- 占位文案：“请输入图中字符”。
- 标签始终显示在输入框上方。

**交互**

- 是否显示图形验证码通过环境变量配置。
- 点击图片或刷新图标重新获取。
- 图片加载时显示固定尺寸占位，避免表单跳动。
- 刷新后清空旧验证码输入。
- 验证码一次使用。
- 登录失败后是否自动刷新由后端安全策略决定。
- 提供“看不清？换一张”的文字入口。
- 支持键盘刷新并提供可访问名称。

**状态**

- 加载中。
- 加载失败。
- 已过期。
- 输入为空。
- 输入错误。
- 刷新频率过高。

**配置**

```dotenv
# 是否启用登录图形验证码：Y | N
VITE_AUTH_CAPTCHA_ENABLED=Y
```

前端环境变量只控制页面显示和请求参数组装。后端必须独立执行验证码校验，不能依赖前端开关保证安全。

**建议文案**

- 空值：“请输入图形验证码”。
- 错误：“验证码错误，请重新输入”。
- 过期：“验证码已失效，请刷新后重试”。
- 加载失败：“验证码加载失败，点击重试”。

### 7.4 保持登录

“保持登录”比“记住我”更准确地表达行为。

**安全规则**

- 不能保存明文密码。
- 未选中时使用普通会话策略。
- 选中时只延长受保护的刷新会话，具体期限由后端定义。
- 公共设备不建议保持登录，可提供弱提示。
- 高风险权限账号是否允许长期会话需要单独确认。

如果当前后端只支持保存账号，应改为“记住账号”，不能继续使用“保持登录”。

### 7.5 忘记密码

- 放在“保持登录”同行右侧。
- 文案：“忘记密码？”。
- 点击进入 `AUTH-002`。
- 保留安全的原目标地址。
- 不在当前页面直接展开复杂重置表单。

### 7.6 主登录按钮

- 文案：“登录”。
- 使用 Primary、Large、Block。
- 高度 40px。
- 圆角 8px，不使用胶囊形按钮。
- 提交中显示加载状态并阻止重复提交。
- 支持 Enter 提交。
- 验证未通过时不发起登录请求。
- 登录成功后跳转原目标页或用户首页。

## 8. 验证码登录

`AUTH-006` 同时支持短信和邮箱一次性验证码登录，由用户自行选择。一次性验证码登录与图形验证码不是同一功能。

### 8.1 入口

密码登录主按钮下方使用文字按钮：

```text
使用验证码登录
```

### 8.2 登录方式选择

使用分段控件或页签切换：

```text
[ 手机验证码 ]  [ 邮箱验证码 ]
```

切换登录方式时：

- 保留当前方式中已经输入的内容。
- 不自动发送验证码。
- 清除上一种方式的错误提示。
- 分别执行手机号和邮箱格式校验。

### 8.3 字段

- 手机号或邮箱。
- 必要时先完成人机验证。
- 一次性验证码。
- 获取验证码按钮。

### 8.4 获取验证码

- 默认文案：“获取验证码”。
- 发送中：“发送中…”。
- 成功后进入倒计时，例如“59s 后重新获取”。
- 倒计时结束后允许重新发送。
- 频率过高时说明稍后重试。
- 不通过文案暴露手机号或邮箱是否已注册。

### 8.5 已确认规则

- 手机验证码和邮箱验证码都支持。
- 用户在页面中主动选择登录方式。
- 未注册账号不能通过验证码登录自动创建账号。

### 8.6 待确认

- 是否先输入图形验证码。
- 验证码长度和有效期。
- 单个账号和 IP 的频率限制。

## 9. 第三方登录

### 9.1 支持方式

本轮支持：

- 微信登录，使用个人微信账号体系，不使用企业微信。
- 飞书登录。

### 9.2 展示方式

桌面端优先使用带品牌图标和文字的等宽按钮：

```text
[ 微信登录 ]  [ 飞书登录 ]
```

不建议只显示两个无文字圆形图标，因为企业后台用户可能无法快速识别。

分隔文案：

```text
其他方式登录
```

### 9.3 交互流程

```text
点击第三方登录
  → 显示跳转中状态
  → 进入微信或飞书授权
  → 授权成功返回回调页
  → 后端交换本系统令牌
  → 获取用户和菜单
  → 返回原目标页或首页
```

### 9.4 状态

- 跳转中。
- 用户取消授权。
- 授权失败。
- 第三方服务不可用。
- 第三方账号未绑定企业账号。
- 当前组织不允许该方式登录。
- 回调状态过期。

第三方身份未绑定时优先提示：

```text
该账号尚未关联 Skyroc 企业账号，请联系管理员完成绑定。
```

企业后台不自动创建未知账号，也不允许用户自助绑定。微信或飞书账号未绑定时，只允许联系管理员处理。

## 10. 忘记与重置密码

### 10.1 AUTH-002 忘记密码

推荐三步流程：

```text
验证账号
  → 验证身份
  → 设置新密码
```

页面包含：

- 返回登录。
- 账号输入。
- 图形验证码。
- 手机或邮箱验证码。
- 获取验证码。
- 下一步。
- 无法验证时联系管理员。

安全规则：

- 不明确提示账号是否存在。
- 手机号或邮箱脱敏展示。
- 身份验证码限时、限频和一次使用。

### 10.2 AUTH-003 重置密码

页面包含：

- 新密码。
- 确认新密码。
- 密码显示与隐藏。
- 密码规则说明。
- 密码强度提示。
- 提交按钮。

成功后：

- 提示“密码已重置”。
- 说明其他会话是否失效。
- 提供“返回登录”按钮。
- 不自动使用新密码登录，除非产品明确决定。

### 10.3 密码规则

具体规则以后端为准。设计需要支持展示：

- 最小和最大长度。
- 大小写、数字和特殊字符要求。
- 不能与近期密码相同。
- 不能包含账号信息。

密码强度只能用于辅助说明，不能代替实际校验规则。

## 11. 注册策略

企业后台不允许开放注册，登录页不展示注册按钮。

建议采用：

- 管理员创建账号。
- 邀请链接激活。
- 企业微信、飞书或统一身份源同步。

邀请链接只能用于激活管理员已经创建或导入的账号，不能借此创建新的未知账号。

## 12. 页面状态

### 12.1 默认

- 字段为空。
- 图形验证码已加载。
- 登录按钮可用。
- 微信和飞书按钮可用。

### 12.2 自动填充

- 浏览器或密码管理器填充账号密码。
- 标签和背景不能与自动填充样式冲突。
- 图形验证码仍需用户输入。

### 12.3 提交中

- 主按钮显示“登录中…”或加载图标。
- 输入框和辅助入口保持稳定。
- 防止重复提交。
- 不使用整页遮罩。

### 12.4 账号或密码错误

- 表单顶部显示统一错误摘要。
- 密码字段进入错误状态。
- 保留账号。
- 是否清空密码由安全策略决定。
- 按规则刷新图形验证码。

### 12.5 验证码错误或过期

- 验证码字段显示错误。
- 聚焦验证码输入。
- 刷新验证码图片。
- 不清空账号。

### 12.6 账号停用或锁定

- 明确说明账号当前不可登录。
- 提供联系管理员或等待解锁的下一步。
- 不展示内部权限或安全策略细节。

### 12.7 网络错误

- 保留所有非敏感输入。
- 显示“网络连接异常，请检查网络后重试”。
- 提供重试，不自动连续请求。

### 12.8 无可用权限

登录成功但没有可访问页面时，展示专用状态：

```text
账号已登录，但当前没有可访问的后台功能。
请联系管理员分配权限。
```

不要显示空白首页。

## 14. 响应式布局

### 14.1 宽屏桌面 `>= 1200px`

- 左侧品牌区约 55%。
- 右侧登录区约 45%。
- 表单宽度 400px。
- 登录区垂直居中。
- 标题和说明居中，表单内容左对齐。

### 14.2 普通桌面 `992px - 1199px`

- 左侧约 45%，右侧约 55%。
- 减少品牌文案和装饰面积。
- 表单仍保持 400px。

### 14.3 平板 `768px - 991px`

- 隐藏大面积品牌插图。
- 保留简化 Logo 和品牌文案。
- 登录表单居中。
- 页面左右安全间距至少 32px。

### 14.4 窄屏 `< 768px`

- 单列布局。
- 隐藏品牌区，只保留顶部 Logo。
- 页面左右间距 20px。
- 表单宽度使用可用空间，最大 400px。
- 微信和飞书按钮可以纵向排列。
- 不使用固定高度，允许页面滚动和软键盘出现。

## 15. 主题、语言与动效

### 15.1 主题

- 支持浅色和深色。
- 复用现有 `ThemeSchemaSwitch`。
- 入口放在登录区右上角。
- 登录页必须保留主题切换入口。
- 登录页只切换浅色和深色，不展示完整主题色选择面板。
- 使用太阳和月亮图标表达当前模式。
- 图标按钮尺寸 32px，点击目标不能小于 32px。
- Hover 或键盘聚焦时显示“切换主题”提示。
- 背景插图同时具备浅色和深色适配。
- 深色主题需要重新检查边框、遮罩和验证码可读性。

### 15.2 语言

- 当前支持中文和英文。
- 复用现有 `LangSwitch`。
- 登录页必须保留语言切换入口，并与主题切换组成横向操作组。
- 默认只显示语言图标，点击后通过下拉菜单显示“中文”和“English”。
- 当前语言在下拉菜单中显示选中状态。
- 图标按钮尺寸 32px，并提供“切换语言”可访问名称。
- 英文长文案需要预留空间。
- 第三方品牌名称使用官方译名。

### 15.3 顶部操作组

- 桌面端位于登录区右上角，距离顶部和右侧各 24px。
- 窄屏位于页面右上角，距离顶部和右侧各 16px。
- 主题与语言按钮横向排列，间距 4px。
- 默认使用透明背景；Hover 使用轻量中性填充。
- 两个按钮不得挤占标题区域，也不与 Logo 形成新的视觉中心。
- Tab 顺序先主题、后语言，再进入登录表单。

### 15.4 动效

- 页面首次进入：登录区 200ms 淡入和轻微上移。
- 登录方式切换：180ms 至 240ms 的水平切换。
- 不使用持续漂浮或高频粒子动画。
- 表单错误不使用剧烈抖动。
- 尊重减少动态效果设置。

## 16. 安全要求

### 16.1 前端

- 密码不得写入日志、URL、Local Storage 或错误上报。
- “保持登录”不能保存明文密码。
- Redirect 只允许站内安全路径。
- 第三方登录使用 `state` 防止跨站请求伪造。
- 回调参数不能长期保留在地址栏。
- 登录失败不能暴露账号是否存在。
- 图形验证码不提供独立的“是否正确”验证接口。

### 16.2 后端依赖

- 登录频率限制。
- 图形验证码生成、过期和一次性消费。
- 账号锁定和解锁策略。
- Refresh Token 生命周期。
- 微信和飞书 OAuth 配置。
- 密码重置令牌的一次性和有效期。
- 敏感操作和登录日志。

## 17. 无障碍

- 页面标题和表单标题使用正确语义。
- 每个输入框都有可访问标签。
- 错误信息与字段关联。
- 第一个错误字段自动聚焦或进入视口。
- 密码显示、验证码图片和刷新按钮有可访问名称。
- 所有操作可通过键盘完成。
- Enter 提交，Tab 顺序符合视觉顺序。
- 焦点状态清晰。
- 微信和飞书不能只通过颜色区分。
- 文本和背景满足 WCAG AA 对比度要求。

- 登录页不能绕过 `setAuth → initAuth → initMenus → navigate`。

## 19. 接口影响

当前登录请求只有：

```ts
interface LoginParams {
  password: string;
  userName: string;
}
```

实现图形验证码后建议由后端契约明确增加：

```ts
interface LoginParams {
  code?: string;
  password: string;
  remember?: boolean;
  userName: string;
  uuid?: string;
}
```

当前继续使用 `userName` 作为统一登录标识字段，它可以承载用户名、手机号或邮箱。图形验证码字段与现有
`skroc-fast` 验证码契约保持一致，分别使用 `code` 和 `uuid`。

还需要新增或确认：

- 获取图形验证码。
- 验证码登录发送接口。
- 验证码登录提交接口。
- 忘记密码身份验证接口。
- 重置密码接口。
- 微信登录地址和回调接口。
- 飞书登录地址和回调接口。

以上是页面依赖建议，最终字段以真实后端契约为准。

## 21. 验收标准

### 21.1 功能

- 用户可以输入账号、密码和图形验证码。
- 用户可以显示和隐藏密码。
- 用户可以刷新图形验证码。
- 用户可以选择是否保持登录。
- Enter 可以提交。
- 提交中不能重复触发。
- 用户可以进入验证码登录。
- 用户可以进入忘记和重置密码流程。
- 用户可以选择微信或飞书登录。
- 登录成功返回原目标页或用户首页。
- 已登录用户访问登录页时自动离开登录页。

### 21.2 状态

- 覆盖字段校验、账号密码错误、验证码错误、验证码过期、账号停用、账号锁定、网络错误和服务错误。
- 所有错误都有明确下一步。
- 登录失败不清空无关字段。
- 无可用权限时不展示空白页。

### 21.3 视觉

- 使用 [Design System](../design-system.md) 中的颜色、间距、圆角和控件高度。
- 登录页 40px 大号输入框和按钮统一使用 8px 圆角。
- 页面标题居中，字段标签和表单内容左对齐。
- 桌面和窄屏布局完整。
- 浅色和深色主题可用。
- 英文长文案不会破坏布局。
- 正式环境不保留演示账号。

### 21.4 安全与无障碍

- 不保存明文密码。
- Redirect 仅允许安全站内路径。
- 核心流程可通过键盘完成。
- 错误与字段关联。
- 颜色不是唯一状态表达。
