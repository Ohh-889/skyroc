## 2. 页面目标

为无法继续使用原密码的企业用户提供安全、清晰、可恢复的密码重置流程。用户需要先通过已绑定的手机或邮箱证明身份，再设置新密码。

页面需要做到：

1. 用户能够使用用户名、手机号或邮箱发起密码恢复。
2. 用户能够主动选择手机或邮箱完成身份验证。
3. 身份验证码校验与密码重置由后端一次性完成。
4. 页面反馈不能泄露账号是否存在、是否绑定某个手机号或邮箱。
5. 用户能够理解验证码发送、校验、过期、限流和重置失败等状态。
6. 用户无法完成验证时有明确的联系管理员入口。
7. 重置成功后清楚说明后续登录方式和其他会话处理结果。

## 3. 设计结论

忘记密码采用同一页面内的渐进式恢复流程：

```text
获取身份验证码
  → 填写验证码和新密码
  → 重置完成
```

整个流程只使用 `/forgot-password`，不新增 `/reset-password` 页面，也不签发中间重置凭证。用户最终提交身份验证码和新密码时，后端在同一个操作中完成验证码校验、密码修改、验证码消费和会话撤销。

不单独增加“检查账号”或“校验验证码”接口。拆分接口不会天然提高安全性，反而需要额外维护跨页面恢复凭证。

## 4. 范围与边界

### 4.1 本流程包含

- 账号输入。
- 手机验证和邮箱验证方式选择。
- 图形验证码。
- 身份验证码发送、倒计时和重新发送。
- 身份验证码与新密码的原子提交。
- 新密码和确认密码。
- 密码规则和强度辅助提示。
- 重置成功状态。
- 返回登录和联系管理员入口。
- 浅色、深色、中文和英文状态。
- 桌面端和窄屏响应式布局。

### 4.2 本流程不包含

- 用户自主注册。
- 未知账号自动创建。
- 手机号或邮箱绑定、换绑。
- 用户修改已经遗失的手机或邮箱。
- 管理员代替用户直接查看或设置明文密码。
- 微信、飞书等第三方身份的绑定与解绑。
- 已登录用户在个人中心主动修改密码。
- 多因素认证设备恢复。

手机号或邮箱已经不可用时，用户只能联系管理员按企业流程核验和恢复身份，不能通过本页面绕过原有账号安全策略。

## 6. 页面架构

忘记与重置密码复用密码登录页的 `LoginLayout`、品牌区、主题语言入口和页脚，只替换右侧认证内容。

```text
LoginLayout
├── BrandPanel
│   ├── ProductLogo
│   ├── ProductStatement
│   └── BrandVisual
├── LoginHeaderActions
│   ├── ThemeSchemaSwitch
│   └── LangSwitch
└── RecoveryPanel
    ├── RecoveryHeader
    ├── PasswordRecoveryForm
    │   ├── AccountField
    │   ├── VerificationChannel
    │   ├── ImageCaptchaField
    │   ├── VerificationCodeField
    │   ├── NewPasswordField
    │   ├── ConfirmPasswordField
    │   └── PasswordRuleList
    ├── ResetSuccess
    └── RecoveryFooter
```

业务边界：

- `LoginLayout` 只负责认证页面的公共布局，不持有恢复流程业务状态。
- `PasswordRecoveryForm` 负责发送验证码以及最终提交验证码和新密码。
- 前端不单独调用“校验身份验证码”接口。
- 后端必须在一个原子操作中完成验证码校验、密码修改、验证码消费和会话撤销。
- `ImageCaptchaField` 与登录页复用同一业务组件和验证码契约。
- 验证码倒计时可以复用现有验证码 Hook，但后端仍是是否允许发送的唯一判断来源。

## 8. 获取身份验证码

### 8.1 页面文案

**标题**

```text
找回密码
```

**辅助说明**

```text
验证身份后重新设置密码
```

页面不使用“账号不存在”“未注册”等能够确认账号状态的说明。

### 8.2 信息层级

页面从上到下排列：

1. 页面标题和辅助说明。
2. 账号字段。
3. 手机验证和邮箱验证分段控件。
4. 按风险策略显示的图形验证码。
5. 身份验证码字段和获取按钮。
6. 验证码发送后展示的新密码和确认密码。
7. 主按钮“重置密码”。
8. 返回登录。
9. 无法完成验证时联系管理员。
10. 隐私政策、服务条款和版权。

### 8.3 账号字段

**标签**

账号。

**占位文案**

```text
请输入用户名、手机号或邮箱
```

**规则**

- 必填。
- 去除首尾空格。
- 不自动修改用户输入的大小写。
- 使用与密码登录一致的统一登录标识语义。
- 支持浏览器自动填充用户名，但不保存验证码。
- 格式明显不正确时不允许获取身份验证码。
- 错误后保留账号输入。
- 不在 URL、日志、埋点或错误上报中记录完整账号。

账号字段发生变化后：

- 清空已经输入的身份验证码。
- 清除上一账号的字段错误。
- 终止前端显示的旧验证码倒计时。
- 已经签发的验证码和挑战是否失效由后端决定。

### 8.4 验证方式

使用等宽分段控件：

```text
[ 手机验证 ]  [ 邮箱验证 ]
```

默认选择手机验证。用户切换方式时：

- 保留账号字段。
- 不自动发送验证码。
- 清空身份验证码输入。
- 清除上一验证方式的字段错误。
- 图形验证码是否刷新由后端挑战策略决定。
- 不展示未经验证的完整手机号或邮箱。
- 不将手机验证码用于邮箱验证，反之亦然。

如果用户输入的账号本身是手机号或邮箱，页面仍允许用户选择另一个已经绑定的验证方式。最终是否匹配由后端判断，前端不能根据账号格式推断绑定关系。

### 8.5 图形验证码

图形验证码按认证服务的风险策略显示，并与密码登录复用相同组件。

字段组成：

- 图形验证码输入框。
- 固定尺寸验证码图片。
- “换一张”刷新入口。

交互规则：

- 点击图片或刷新入口重新获取。
- 图片加载时保留固定尺寸，避免表单跳动。
- 刷新成功后清空旧图形验证码输入。
- 提供加载中、加载失败、已过期和刷新过于频繁状态。
- 图形验证码不能通过独立接口提前判断是否正确。
- 关闭前端展示时，后端仍必须执行自己的风险控制。

### 8.6 获取身份验证码

获取按钮默认文案：

```text
获取验证码
```

发送前置条件：

- 账号已经填写并通过基础格式校验。
- 已经选择验证方式。
- 需要图形验证码时，图形验证码已经填写。
- 当前没有发送请求正在进行。

发送中：

- 按钮显示加载状态。
- 阻止重复提交。
- 保持表单尺寸稳定。

发送请求被接受后：

- 显示统一成功反馈。
- 身份验证码输入框获得焦点。
- 开始 `60` 秒倒计时。
- 按钮显示“重新发送 59s”等剩余时间。

统一成功文案：

```text
如果账号信息匹配，验证码将发送至绑定的手机或邮箱。
```

不能使用以下文案：

```text
该账号不存在
该账号未绑定手机号
该邮箱尚未注册
验证码已发送至 138****5678
```

前端倒计时结束不代表后端一定允许再次发送。重新发送时必须再次请求后端，由后端根据账号、目标、挑战、IP 和设备等维度判断。

### 8.7 身份验证码

**标签**

身份验证码。

**占位文案**

```text
请输入 6 位验证码
```

**规则**

- 必填。
- 仅接受 6 位数字。
- 支持适合一次性验证码的自动填充语义。
- 不将验证码写入 URL、日志、Local Storage 或错误上报。
- 输入完整后不自动提交，避免用户无法检查账号和验证方式。
- 验证失败时保留账号和验证方式。
- 是否清空错误验证码由后端安全策略决定。

### 8.8 联系管理员

页面底部提供：

```text
无法使用绑定的手机或邮箱？联系管理员
```

联系管理员入口只进入企业已经确认的帮助渠道。没有真实帮助地址时使用普通说明，不展示虚构客服电话、邮箱或在线客服。

管理员恢复身份时仍需要执行企业内部核验流程，不能在后台直接读取用户原密码。

## 9. 填写验证码和新密码

### 9.1 显示时机

验证码发送请求被接受后，在当前 `/forgot-password` 页面继续展示身份验证码、新密码、确认密码和密码规则。

此时只代表发送请求已被接受，不代表账号一定存在，也不代表身份验证码已经通过校验。页面不能在提交新密码前单独请求“验证码是否正确”。

用户修改账号或验证方式后：

- 清空身份验证码、新密码和确认密码。
- 隐藏密码设置区域。
- 重新执行验证码发送流程。

### 9.2 区块文案

**区块标题**

```text
设置新密码
```

**辅助说明**

```text
请设置一个新的安全密码
```

### 9.3 页面结构

```text
身份验证码
[                  ][重新发送 42s]

新密码
[                              ][显示]

确认新密码
[                              ][显示]

密码要求
✓ 至少 8 位
○ 包含英文大写字母、小写字母和数字
○ 不能使用常见弱密码

[          重置密码          ]
← 返回登录
```

### 9.4 新密码

**标签**

新密码。

**占位文案**

```text
请输入新密码
```

**规则**

- 必填。
- 默认隐藏。
- 提供显示和隐藏按钮。
- 不自动去除首尾空格。
- 不允许浏览器将旧密码误填入该字段。
- 不在日志、URL、Local Storage、埋点或错误上报中记录。
- 密码规则随输入逐项反馈。
- 前端规则必须与后端下发或共同维护的真实规则一致。

### 9.5 确认新密码

**标签**

确认新密码。

**占位文案**

```text
请再次输入新密码
```

**规则**

- 必填。
- 默认隐藏。
- 提供独立的显示和隐藏按钮。
- 只判断两次密码是否一致，不重复展示全部密码规则。
- 不一致时显示“两次输入的密码不一致”。
- 用户修改新密码后，需要重新检查确认密码。

### 9.6 密码规则

密码规则：

- 密码长度至少为 8 位。
- 至少包含一个英文大写字母 `A-Z`。
- 至少包含一个英文小写字母 `a-z`。
- 至少包含一个数字 `0-9`。
- 允许使用中文和特殊字符，但不强制要求。
- 不能包含完整账号等明显的用户身份信息。
- 不能使用常见弱密码、连续字符、重复字符或已知泄露密码。

弱密码识别不只使用正则表达式。前端可以使用成熟的密码强度评估能力提供“弱、中、强”提示，后端必须使用弱密码禁用词库和已泄露密码库执行最终拦截。

最大长度、历史密码不可重复次数和最终弱密码库由后端安全实现确定，前后端必须使用一致的公开规则文案。

规则反馈使用文字和状态图标，不能只通过红色或绿色区分。

密码强度可以显示“弱、中、强”，但只能作为辅助信息，不能代替具体规则，也不能声称密码绝对安全。

### 9.7 提交重置

- 主按钮文案：“重置密码”。
- 使用 Primary、Large、Block。
- 表单校验未通过时不发起请求。
- 提交中显示“重置中…”或加载图标。
- 提交期间阻止重复提交。
- 请求同时提交 `challengeId`、身份验证码和新密码。
- 后端在同一个原子操作中校验验证码、修改密码、消费验证码并撤销全部登录会话。
- 任何一步失败都不能只完成部分操作。
- 验证码错误或过期时不修改密码，也不撤销登录会话。
- 重置成功后验证码立即失效，重复提交不能再次修改密码。
- 网络失败不能默认视为重置失败。前端需要查询或根据幂等结果确认最终状态，不能盲目重复提交。

## 10. 重置完成

重置成功后使用结果状态替换表单：

```text
        ✓
     密码已重置

你现在可以使用新密码登录。
为了保障账号安全，其他已登录会话已经退出。

[        返回登录        ]
```

规则：

- 不自动使用新密码登录。
- 不再次展示账号、新密码或验证码。
- 主按钮文案：“返回登录”。
- 点击进入 `/login`。
- 登录页可以保留安全的原目标地址，但不能保留恢复流程敏感参数。
- 重置成功后撤销该账号的所有其他登录会话。

## 11. 页面状态

### 11.1 身份验证默认

- 账号为空。
- 默认选择手机验证。
- 图形验证码按风险策略加载。
- 身份验证码为空。
- 获取验证码按钮可用状态取决于前置字段。
- 密码设置区域默认隐藏。

### 11.2 图形验证码加载中或失败

- 加载中保留验证码图片尺寸。
- 加载失败显示“验证码加载失败，点击重试”。
- 不允许在需要图形验证码时绕过后继续发送。

### 11.3 身份验证码发送中

- 获取按钮显示加载状态。
- 阻止重复发送。
- 不使用整页遮罩。
- 账号、验证方式和已有输入保持可见。

### 11.4 身份验证码已发送

- 显示统一的中性成功反馈。
- 身份验证码字段获得焦点。
- 开始重新发送倒计时。
- 展示新密码、确认密码、密码规则和“重置密码”按钮。
- 不确认账号是否真实存在。

### 11.5 身份验证码错误或过期

- 错误显示在身份验证码字段附近。
- 焦点回到身份验证码字段。
- 保留账号和验证方式。
- 提供重新发送入口。
- 不显示剩余允许错误次数等内部安全策略。

### 11.6 发送或验证过于频繁

- 显示明确的稍后重试说明。
- 使用后端返回的安全等待时间时，不暴露内部限流维度。
- 不自动连续重试。
- 不通过刷新页面绕过等待状态。

### 11.7 身份验证码已失效

- 保留账号和验证方式。
- 清空身份验证码。
- 不提交新密码。
- 显示“验证码已失效，请重新获取”。
- 提供重新发送验证码和返回登录。

### 11.8 密码不符合规则

- 在对应规则附近显示未满足项。
- 后端拒绝时同步展示后端允许公开的规则说明。
- 不清空用户已经输入的新密码，除非命中特定安全策略。

### 11.9 网络错误

- 保留所有非敏感表单上下文。
- 显示“网络连接异常，请检查网络后重试”。
- 提供手动重试。
- 不自动重新发送短信、邮件或重复提交密码。

### 11.10 服务异常

- 显示“密码恢复服务暂时不可用，请稍后重试”。
- 提供返回登录和联系管理员入口。
- 不显示异常堆栈、接口地址或内部错误码。

## 13. 响应式布局

### 13.1 宽屏桌面 `>= 1200px`

- 左侧品牌区约 `55%`。
- 右侧认证区约 `45%`。
- 表单宽度 `400px`。
- 认证内容垂直居中。

### 13.2 普通桌面 `992px - 1199px`

- 左侧约 `45%`，右侧约 `55%`。
- 减少品牌装饰面积。
- 表单仍保持 `400px`。

### 13.3 平板 `768px - 991px`

- 隐藏大面积品牌插图。
- 保留简化 Logo 和品牌文案。
- 表单居中。
- 页面左右安全间距至少 `32px`。

### 13.4 窄屏 `< 768px`

- 使用单列布局。
- 隐藏品牌区，只保留顶部 Logo。
- 页面左右间距 `20px`。
- 表单使用可用宽度，最大 `400px`。
- 获取验证码按钮需要为英文倒计时文案预留空间。
- 图形验证码区域空间不足时允许合理换行。
- 不使用固定页面高度，允许软键盘出现后滚动。
- 验证码发送后展开的密码区域保持单列排列。

## 14. 主题、语言与动效

### 14.1 主题

- 复用登录页的浅色和深色主题。
- 复用 `ThemeSchemaSwitch`。
- 入口保持在认证区右上角。
- 深色主题需要检查输入框、步骤线、错误状态和验证码图片的可读性。
- 不为忘记密码页创建独立颜色体系。

### 14.2 语言

- 支持中文和英文。
- 复用 `LangSwitch`。
- 英文账号占位文案、倒计时、密码规则和错误文案需要预留足够空间。
- 验证方式切换后的标签长度不能造成布局跳动。

### 14.3 动效

- 页面进入使用与登录页一致的 `200ms` 淡入和轻微上移。
- 密码设置区域展开使用 `180ms` 至 `240ms` 的透明度和轻微位移。
- 不使用剧烈抖动表达错误。
- 不使用持续动画制造安全感。
- 尊重减少动态效果设置。

## 15. 安全要求

### 15.1 前端

- 账号、验证码和新密码不写入日志、埋点或错误上报。
- 验证码和新密码不进入 URL。
- 新密码不写入 Local Storage、Session Storage 或其他持久化缓存。
- 页面刷新后不能依赖前端状态恢复已经失效的安全上下文。
- 不提供独立的账号存在性检查接口。
- 不提供独立的图形验证码或身份验证码正确性查询接口。
- 身份验证码和新密码只通过最终重置接口一起提交。
- 不在未经身份验证前展示绑定手机号或邮箱。
- 提交中阻止重复操作，但不能只依赖前端按钮禁用保证幂等。
- Redirect 只允许站内安全路径。

### 15.2 后端依赖

- 账号、IP、设备和验证目标等维度的发送频率限制。
- 图形验证码生成、过期和一次性消费。
- 身份验证码生成、发送、过期、错误次数限制和一次性消费。
- 不泄露账号存在性的统一响应。
- 安全随机且不可预测的 `challengeId`。
- 身份验证码与 `challengeId`、账号、验证方式和密码重置用途绑定。
- 验证码校验、密码修改、验证码消费和会话撤销必须原子执行。
- 密码强度、历史密码和弱密码校验。
- 密码重置成功后撤销该账号的全部登录会话。
- 密码重置安全日志和邮件通知。
- 企业身份源托管密码的识别和拦截。

### 15.3 安全通知

密码重置成功后，只通过已经绑定的邮箱发送通知：

```text
你的 Skyroc 账号密码已于指定时间完成重置。
如果不是你本人操作，请立即联系管理员。
```

没有绑定邮箱时不降级发送短信，重置结果仍正常完成，并记录安全日志。

邮件不能包含新密码或验证码。

## 16. 无障碍

- 页面只有一个主标题。
- 每个输入框都有常驻可见标签和可访问名称。
- 错误信息与对应字段建立关联。
- 提交失败后将焦点移动到第一个错误字段或错误摘要。
- 分段控件具有正确的选中语义并支持键盘操作。
- 图形验证码图片和刷新按钮具有可访问名称。
- 密码显示和隐藏按钮说明当前操作。
- 成功状态通过图标、标题和文字共同表达。
- 所有操作可以通过键盘完成。
- Tab 顺序与视觉顺序一致。
- 文本和背景满足 WCAG AA 对比度要求。
- 状态变化通过适当的 Live Region 通知屏幕阅读器，但不重复播报倒计时每一秒。

## 17. 建议接口契约

以下字段用于明确页面依赖，最终以真实后端契约为准。

### 17.1 发送身份验证码

```ts
interface SendPasswordResetCodeParams {
  account: string;
  captchaCode?: string;
  captchaUuid?: string;
  channel: 'email' | 'sms';
}

interface SendPasswordResetCodeResponse {
  challengeId: string;
  expiresIn: number;
  retryAfter: number;
}
```

接口无论账号是否存在都应返回不可区分的可接受结果。`challengeId` 不能包含可解码的账号、手机号或邮箱信息。

### 17.2 重置密码

```ts
interface ResetPasswordParams {
  challengeId: string;
  code: string;
  newPassword: string;
}

interface ResetPasswordResponse {
  sessionsRevoked: boolean;
}
```

确认密码只用于前端交互校验，不需要作为重复敏感字段提交给后端。接口必须原子完成以下操作：

1. 校验 `challengeId`、验证码、账号和验证方式的绑定关系。
2. 校验验证码是否正确、是否过期和是否超过错误次数。
3. 校验新密码规则。
4. 修改密码。
5. 消费验证码。
6. 撤销该账号的全部登录会话。

任意一步失败时，不能提交部分结果。

### 17.3 接口错误语义

后端需要提供前端能够安全展示的稳定错误类型，例如：

- 图形验证码错误或过期。
- 身份验证码错误或过期。
- 请求过于频繁。
- 新密码不符合规则。
- 企业身份源托管密码。
- 服务暂时不可用。

接口不能将账号是否存在、绑定目标完整信息或内部安全策略通过错误信息泄露给前端。

## 19. 验收标准

### 19.1 身份验证

- 用户可以输入用户名、手机号或邮箱。
- 用户可以选择手机或邮箱验证。
- 用户可以获取、刷新和输入图形验证码。
- 用户可以发送和重新发送身份验证码。
- 用户可以在当前页面输入 6 位身份验证码和新密码。
- 页面不能通过成功或失败文案确认账号是否存在。
- 账号和验证码不会进入 URL 或持久化存储。

### 19.2 设置新密码

- 用户可以输入和确认新密码。
- 密码规则能够随输入正确反馈。
- 两次密码不一致时不能提交。
- 提交中不能重复触发重置请求。
- 身份验证码校验和密码重置通过一个接口原子完成。
- 身份验证码失效时能够重新发送。

### 19.3 完成状态

- 重置成功后不自动登录。
- 页面提供明确的返回登录操作。
- 页面明确说明其他登录会话已经失效。
- 成功状态不展示账号、新密码或验证码。

### 19.4 通用

- 桌面端、平板和窄屏布局可用。
- 浅色、深色、中文和英文状态可用。
- 键盘可以完成全部操作。
- 错误状态、焦点状态和动态状态满足可访问性要求。
- 网络失败、服务失败、验证码错误、验证码过期和频率限制都有明确下一步。

## 20. 开发前待确认

- 密码最大长度、历史密码不可重复次数和后端采用的弱密码库。
- 身份验证码发送接口如何实现账号存在性不可区分响应。
- 企业身份源托管账号的识别字段和帮助入口。

以上问题不影响页面的基本结构，但会影响最终接口字段、状态文案和安全处理。
