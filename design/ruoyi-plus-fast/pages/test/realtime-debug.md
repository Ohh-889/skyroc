## 2. 产品定义

实时通道调试台不是聊天页面，也不是业务消息中心。它是一套面向内部人员的协议验收工具，用于快速回答四个问题：

| 问题           | 页面必须给出的证据                            |
| -------------- | --------------------------------------------- |
| 能否连接       | 当前状态、连接 ID、环境自检结果、最近关闭原因 |
| 能否发送       | 上行原始命令、客户端命令 ID、服务端回执       |
| 能否接收       | 下行原始信封、消息类型、`msg_id`、解析摘要    |
| 断线后怎样处理 | 关闭码、是否重连、令牌续签或终止原因          |

核心产出是可复制、可对账的原始帧。摘要只帮助扫描，不能替代原始 JSON。

## 3. 架构与职责

### 3.1 页面边界

```text
全应用 Effect
  └─ 管理连接生命周期与登录态
       ├─ WebSocketClient：连接、心跳、续签、重连、事件分发
       └─ SseClient：EventSource 连接、关闭事件、事件分发

实时通道调试台
  ├─ 读取连接快照与环境条件
  ├─ 订阅状态、收发与关闭事件
  ├─ 编辑并触发既有发送 API
  └─ 将原始帧组织成可筛选、可复制的事件流
```

- 页面不创建第二条连接，不自行实现重连、缓存或心跳。
- 页面操作的是全应用共用连接，断开会影响通知中心等其他实时消费者。
- WebSocket 上行继续复用 `features/message/api`。
- 后端主动推送继续复用 `/websocket/push` 与 `/sse/push`。
- 信封解析继续复用 `features/realtime/message.ts`。
- 权限由后端判定；前端不隐藏群发能力，因为权限拒绝本身也是验收场景。

### 3.2 两种传输的差异

| 能力     | WebSocket           | SSE                             |
| -------- | ------------------- | ------------------------------- |
| 方向     | 双向                | 单向接收                        |
| 上行命令 | 支持                | 不支持，使用普通 HTTP           |
| 心跳     | `ping` / `pong`     | 无                              |
| 重连     | 客户端指数退避      | 浏览器 `EventSource` 管理       |
| 主动关闭 | 关闭帧              | `system.connection.closed` 事件 |
| 连接 ID  | 从 `ready` 事件读取 | `getConnectionId()`             |

两个页面使用同一套工作台骨架，但不合并为一个路由。这样可以保留独立入口、独立日志上下文和明确的传输能力边界。

## 4. 已知事实、假设与根因

### 4.1 已知事实

- 统一信封为 `{ code, data, msg, msg_id?, request_id?, type }`。
- `system.connection.ready` 表示服务端已完成凭据校验，不能把浏览器握手成功等同于已连接。
- WebSocket 定向发送会产生上行命令、服务端回执和业务投递三类记录。
- 回执的 `request_id` 对应上行命令的 `id`。
- 通知中心按 `msg_id` 去重，调试台仍需展示原始下行帧。
- `buildRealtimeUrl` 在开关关闭、URL 为空或令牌缺失时返回 `null`，不会发起连接，也不会产生错误事件。
- `1008` 表示登录已结束，不重连；`4001` 表示令牌过期，续签成功后重连；`4000` 表示客户端心跳超时。
- 当前日志最多保留 50 条，新记录在前。
- `local_connections` 只代表当前后端实例，不等于集群总投递数。

### 4.2 设计假设

- 页面面向内部人员，允许信息密度高于普通业务页面。
- 原型数据仅用于演示状态和交互，不代表真实生产数据。
- 页面不新增后端接口。
- 路由是否在生产环境可见由部署策略决定，不在本 PRD 内处理。

### 4.3 症状与根因

| 症状                             | 根因                                 | 设计处理                                      |
| -------------------------------- | ------------------------------------ | --------------------------------------------- |
| 长时间显示“未启动”               | 开关、地址或令牌缺失，连接根本未创建 | 在首屏逐项展示环境自检，而不是只显示状态徽标  |
| 握手后仍未连接                   | 服务端尚未通过凭据校验               | 单独保留“连接中”，解释它与网络失败的区别      |
| 发送一次出现多条记录             | 命令、回执和投递是不同协议事件       | 使用 `id` / `request_id` 成组，并明确标记回执 |
| 通知中心只有一条，调试台看到多条 | 通知中心按 `msg_id` 去重             | 在事件流中展示 `msg_id`，不替用户隐藏原始帧   |
| 断开后有时恢复、有时终止         | 关闭码对应不同恢复策略               | 展示关闭码、原因和是否重连                    |
| 点击断开后其他页面也收不到通知   | 使用全应用单例连接                   | 常驻影响说明并要求二次确认                    |
| 日志早期记录消失                 | 50 条上限静默淘汰                    | 常驻上限说明，达到上限后高亮提示              |

## 5. 设计目标

1. 进入页面 3 秒内能判断连接是否可用，以及阻塞在环境、登录、握手还是关闭策略。
2. 一条上行命令可以快速定位对应回执和业务投递。
3. 每条事件都能看到摘要与完整原始帧，并支持复制。
4. 操作区不淹没诊断信息，事件流始终是页面主体。
5. WebSocket 与 SSE 视觉一致，但能力差异一眼可辨。

非目标：

- 不提供业务消息编辑器或富文本预览。
- 不在调试台实现通知中心的去重与展示逻辑。
- 不承诺跨刷新保存日志。
- 不提供服务端全链路日志检索。

## 6. 信息架构

```text
页面头部
├─ 页面名称与传输能力说明
└─ 切换另一种传输

诊断区
├─ 连接概览：状态、连接 ID、用户、心跳/重连、最近关闭
└─ 环境自检：开关、地址、令牌、clientid

动作区
├─ WebSocket 上行命令（仅 WebSocket）
└─ 后端主动推送（WebSocket / SSE）

事件流
├─ 方向筛选、类型筛选、暂停、复制、清空
├─ 事件摘要行
└─ 可展开原始帧
```

## 7. 页面布局

### 7.1 桌面端

- 页面使用全宽工作区，内容最大宽度约 1480px。
- “连接概览”和“环境自检”两列并排，占据首屏核心区域。
- WebSocket 的“上行命令”和“后端推送”两列并排。
- SSE 没有上行能力，“后端推送”保持单列适中宽度，不用空卡片补齐。
- 事件流独占整行，默认可见 8 至 12 条记录。
- 同级面板使用一致的 18px 内边距，不嵌套卡片。

### 7.2 响应式

| 断点             | 行为                                                 |
| ---------------- | ---------------------------------------------------- |
| `>= 1180px`      | 诊断区、WebSocket 动作区均为双列                     |
| `900px - 1179px` | 所有面板单列，事件摘要保留单行扫描能力               |
| `< 900px`        | 隐藏演示侧栏，按钮可换行，事件摘要与操作分行         |
| `< 768px`        | 长 ID 中间省略，原始 JSON 默认折叠，发送按钮允许整宽 |

## 8. 视觉方向

设计关键词：专业、克制、诊断优先、可扫描、一致。

- 严格复用岗位管理和角色管理原型的 Skyroc Admin 页面母版，不为开发工具创建独立主题。
- 页面采用 `#F5F6F8` 浅灰工作区、白色面板、`#171922` 深色导航与 `#6366F1` 靛蓝主操作。
- 侧栏宽度、顶栏高度、导航选中态、品牌标、用户区与现有管理页保持一致。
- 连接状态使用色点加文字，不只依赖颜色。
- 原始协议字段、ID、时间戳和 JSON 使用等宽字体；说明文字使用产品默认字体。
- 面板圆角为 10px，控件圆角为 8px，使用现有管理页的细边框与轻阴影。
- Success、Warning、Error 只表达语义，不作为装饰色。
- 页面标题保持后台尺度，不使用营销式大标题。
- 深色模式通过表面层级和边框区分，不简单反转颜色。

## 9. 功能规格

### 9.1 连接概览

| 字段     | 数据来源                                        | 规则                                 |
| -------- | ----------------------------------------------- | ------------------------------------ |
| 状态     | `useAppWebSocket().state` / `useAppSse().state` | 显示状态点、文本和状态持续时间       |
| 连接 ID  | `ready` 事件 / `getConnectionId()`              | 等宽显示，支持复制，未就绪时说明来源 |
| 用户     | `ready.data.user_id` 等                         | 未就绪时隐藏真实值                   |
| 心跳     | WebSocket 客户端配置                            | 未接入实测事件前标记“配置值”         |
| 重连     | 客户端或 EventSource 策略                       | 只展示可验证信息，不伪造重试次数     |
| 最近关闭 | 关闭事件                                        | 显示代码、原因和恢复策略             |

状态定义：

| 状态           | 文案   | 说明                             |
| -------------- | ------ | -------------------------------- |
| `idle`         | 未启动 | 环境不满足或尚未发起连接         |
| `connecting`   | 连接中 | 正在等待服务端确认或进行重连     |
| `connected`    | 已连接 | 已收到 `system.connection.ready` |
| `disconnected` | 已断开 | 连接失败、主动断开或会话结束     |

手动“重新连接”执行 `disconnect()` 后再 `connect()`。“断开”必须二次确认，并说明通知中心等其他实时消费者也会受影响。

### 9.2 环境自检

| 检查项                | 通过条件          | 失败文案             |
| --------------------- | ----------------- | -------------------- |
| `VITE_*_ENABLED`      | 值为 `Y`          | 当前环境未开启该传输 |
| `VITE_*_URL`          | 非空              | 未配置连接地址       |
| 登录令牌              | `getToken()` 有值 | 未登录，连接需要令牌 |
| `VITE_AUTH_CLIENT_ID` | 非空              | 未配置客户端标识     |

- 每项显示通过或失败图标、配置名、用途与脱敏值。
- 不展示完整实时 URL，避免令牌泄漏。
- 有失败项时总结缺失数量，并解释为什么状态会停留在“未启动”。

### 9.3 WebSocket 上行命令

- 收件人支持单个或多个 `userId`，以逗号、中文逗号或空白分隔。
- 消息体必须是合法 JSON 对象，不接受数组、字符串或 `null`。
- 提供通知消息、纯文本和非法 JSON 演示模板。
- “定向发送”调用 `sendDirectMessage`；“群发”调用 `sendBroadcast`。
- 未连接时禁用发送按钮。
- 权限失败作为正常协议事件写入事件流，不用通用错误页覆盖。

### 9.4 后端主动推送

- 字段包括标题、类型和正文。
- WebSocket 调用 `POST /websocket/push`；SSE 调用 `POST /sse/push`。
- 提交时按钮显示加载态，防止重复提交。
- 成功反馈包含 `local_connections`，并明确它只统计当前实例。

### 9.5 事件流

事件顺序为新到旧。每条摘要行包含：

- 方向：`IN`、`OUT`、`SYS`。
- 毫秒级时间。
- `type`；非信封事件显示“非信封”。
- `code`、命令 `id`、`request_id`、`msg_id` 等关联字段。
- 一行可扫描摘要。
- 展开/收起与复制操作。

交互规则：

- 方向筛选和类型筛选叠加生效。
- 暂停只暂停渲染，不断开连接；恢复时按正确时间顺序合并缓冲记录。
- 回执的 `request_id` 可定位对应上行命令。
- “复制全部”只复制当前筛选结果，并提示可能包含业务数据。
- “清空”只清理本地记录，不影响连接和服务端投递。
- 达到 50 条时明确提示更早记录已淘汰。

## 10. 页面状态

原型提供以下场景用于评审：

| 场景            | 预期表现                              |
| --------------- | ------------------------------------- |
| 正常已连接      | 显示连接 ID、用户、可用操作和种子事件 |
| 连接中          | 状态闪烁，解释等待服务端确认凭据      |
| 令牌过期 `4001` | 显示续签后自动重连                    |
| 登录结束 `1008` | 显示不会重连并引导重新登录            |
| 传输未开启      | 自检标出开关失败，操作禁用            |
| 未登录          | 自检标出令牌缺失，操作禁用            |
| 无事件          | 显示空状态和等待条件                  |
| 无筛选结果      | 显示清除筛选入口                      |
| 达到 50 条      | 高亮上限与淘汰说明                    |

## 11. 可访问性

- 状态使用颜色、图标和文字三重表达。
- 所有图标按钮提供可访问名称。
- 键盘焦点清晰，弹窗打开后应将焦点移入并在关闭后归还。
- 弹窗支持 `Escape` 关闭；危险确认不能依靠点击遮罩完成。
- 动态新增事件使用温和高亮；系统开启减少动效时关闭动画。
- 深浅主题文字、边框和状态色满足基本对比度要求。
- 原始 JSON 支持键盘滚动，不在移动端横向撑破页面。

## 12. 数据与安全

- 不展示或复制带令牌的完整连接地址。
- 连接 ID、消息正文和原始 JSON 可能包含业务数据，复制时给出提示。
- 页面日志仅存于当前内存，不写入 LocalStorage。
- 调试页面是否开放给生产用户应由环境或权限控制。
- 页面不得将权限不足改写成网络错误。

## 13. 实现依赖

| 编号      | 依赖                                   | 页面降级策略                         |
| --------- | -------------------------------------- | ------------------------------------ |
| RT-DEP-01 | WebSocket 重连次数与倒计时尚未公开     | 不显示假值，仅展示已知恢复策略       |
| RT-DEP-02 | `pong` 当前由客户端内部处理            | 心跳显示配置值并明确标注             |
| RT-DEP-03 | WebSocket 没有统一 `getConnectionId()` | 从 `ready` 事件缓存连接 ID           |
| RT-DEP-04 | WebSocket 关闭帧详情需透出             | 未接入前只展示状态迁移，不伪造关闭码 |

## 14. 验收标准

1. WebSocket 与 SSE 可以在各自页面查看四态连接状态，并切换到另一种传输。
2. 环境开关、地址、令牌和 clientid 可逐项判断，失败原因明确。
3. WebSocket 可发送定向消息和群发命令，并在事件流核对命令、回执与投递。
4. 两个页面都可调用对应后端推送接口并反馈本实例连接数。
5. 事件流支持方向/类型筛选、暂停、清空、逐条复制、复制当前结果和展开原始帧。
6. `request_id` 可以定位对应命令，`msg_id` 在摘要中可见。
7. 断开连接前明确告知影响范围并二次确认。
8. 达到 50 条时提示更早记录已淘汰。
9. 在 1440px、1024px、768px 和 390px 宽度下无内容重叠或横向溢出。
10. 深色模式与减少动效偏好均可正常使用。

## 15. 后续范围

- 若 `getStats()` 稳定开放，可增加真实重连次数与下次重试倒计时。
- 若客户端透出心跳事件，可在事件流增加可选的心跳噪声过滤。
- 若需要跨传输对账，再设计独立的双通道关联视图；本期不把两个连接强行合并。
