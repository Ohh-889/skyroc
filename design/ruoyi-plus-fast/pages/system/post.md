## 2. 架构结论

岗位是“部门中的任职位置”，不是角色或权限的同义词：

```text
部门组织树
  → 部门内岗位定义
  → 用户与岗位多对多关联
  → 用户档案、导入与业务流程引用

角色与数据权限
  → 决定用户能访问什么
  ≠ 岗位本身
```

页面职责：

- 前端负责部门上下文、条件查询、分页、多选、表单交互、权限显隐、危险操作确认和结果反馈。
- 岗位用例负责租户隔离、部门有效性、岗位名称与岗位编码唯一性、用户占用校验和事务边界。
- 部门模块负责部门树和部门名称，不在岗位页面复制组织树计算逻辑。
- 用户模块维护 `sys_user_post` 关联；岗位模块只通过窄接口判断岗位是否已分配。
- 操作日志记录新增、修改和删除，前端不提交操作者或审计字段。

页面采用：

```text
左侧部门树 + 右侧查询区与分页表格
  + 新增/编辑抽屉
  + 单个/批量删除确认
```

左侧树提供“当前部门及全部下级”的工作上下文，查询区中的“部门”提供精确部门筛选。两者同时出现时以精确部门为准，这是当前接口的真实语义。

## 3. 已知事实与设计假设

### 3.1 RuoYi 前端事实

参考页面已经包含：

- 左侧部门树，支持按部门名称过滤、选中部门及其下级岗位。
- 按岗位编码、类别编码、岗位名称、精确部门和状态查询。
- 分页表格展示岗位编码、类别编码、岗位名称、部门、排序、状态和创建时间。
- 新增、单选修改、多选删除、导出和行内修改/删除。
- 表单字段包括岗位名称、部门、岗位编码、类别编码、岗位顺序、岗位状态和备注。
- `deptId` 与 `belongDeptId` 互斥：选择查询表单中的精确部门时清空归属部门树条件。

参考页面用于确认业务覆盖面，不要求复制 Element Plus 的视觉、弹窗宽度或按钮布局。

### 3.2 RuoYi 控制器事实

| 能力       | 方法与路径                      | 权限                 |
| ---------- | ------------------------------- | -------------------- |
| 岗位列表   | `GET /system/post/list`         | `system:post:list`   |
| 岗位详情   | `GET /system/post/{postId}`     | `system:post:query`  |
| 新增岗位   | `POST /system/post`             | `system:post:add`    |
| 修改岗位   | `PUT /system/post`              | `system:post:edit`   |
| 删除岗位   | `DELETE /system/post/{postIds}` | `system:post:remove` |
| 导出岗位   | `POST /system/post/export`      | `system:post:export` |
| 岗位选项   | `GET /system/post/optionselect` | `system:post:query`  |
| 归属部门树 | `GET /system/post/deptTree`     | `system:post:list`   |

控制器和服务还明确：

- 岗位名称在同一部门内唯一，不同部门可以存在同名岗位。
- 岗位编码在当前租户内唯一，适合作为导入和系统对接标识。
- 已分配用户的岗位不能停用，也不能删除。
- 删除接口支持逗号分隔的多个岗位 ID。
- 新增和修改启用重复提交保护，写操作记录操作日志。

### 3.3 当前 FastAPI 事实

当前 `skroc-fast/app/modules/post` 已具备：

- 分页列表、详情、新增、修改、单个/批量删除、岗位选项和部门树接口。
- `deptId` 精确部门筛选和 `belongDeptId` 部门子树筛选；两者同时存在时以 `deptId` 为准。
- 同部门岗位名称唯一、租户内岗位编码唯一、部门存在性和用户占用校验。
- 批量删除的事务一致性：任一岗位不存在或被占用时整批不删除。
- 列表白名单排序和创建时间范围查询。
- RuoYi 格式字段、分页响应和 `R` 包装。

当前缺口：

- 没有 `POST /system/post/export`，页面首版应将导出标记为“待后端能力”，不能伪造成功下载。
- 权限点尚未接入，岗位接口暂由超级管理员门禁代管。
- 尚未实现部门数据权限过滤，能进入接口的管理员目前可见本租户全部岗位。
- 岗位编码依赖用例查重而非数据库唯一约束，极端并发创建仍存在重复风险。

### 3.4 设计假设

- 首期保持 RuoYi 的字段和单数接口路径，不另建一套岗位契约。
- 类别编码没有已验证的字典来源，查询和表单使用文本输入；接入字典后再替换为可搜索选择器。
- 首期使用数字排序，不做拖拽排序。
- 不设计行内状态开关；停用会受用户占用约束，必须通过编辑抽屉明确提交。
- 原型展示导出入口及未就绪状态，实际开发在导出接口完成前隐藏或禁用。
- “查看岗位成员”暂不作为本页操作，因为当前用户列表没有已验证的岗位筛选契约；待接口明确后再加入跳转。

## 4. 页面目标

页面需要让有权限的管理员：

1. 在部门组织上下文中快速定位岗位，而不是浏览无归属感的全量列表。
2. 区分岗位名称、岗位编码和类别编码各自用途，减少错误配置。
3. 通过多条件组合、分页和稳定排序定位目标岗位。
4. 新增或编辑岗位，并清楚知道部门变更会改变岗位归属。
5. 在停用或删除前理解已分配用户带来的约束。
6. 对单个或多个岗位执行可控删除，失败时知道具体阻塞项。
7. 在权限不足、重复编码、数据过期或接口失败时得到可执行反馈。

- 主内容使用 `240px + minmax(0, 1fr)` 双栏；左栏独立滚动，右栏承担主要宽度。
- 部门树和岗位工作区使用同级弱边框容器，不叠加强阴影。
- 查询区默认展示三个高频条件，低频条件进入“更多筛选”。
- 岗位名称列固定左侧，操作列固定右侧；表格允许横向滚动。
- 表格使用服务端分页，默认每页 10 条，可切换 20、50、100 条。
- 当前部门上下文显示在工具栏摘要中，避免只依赖树节点背景色。

### 6.2 中等宽度

- `992px - 1199px` 将部门树缩至 208px。
- 类别编码和创建时间默认隐藏，通过列设置恢复。
- 查询区保留岗位名称、岗位编码和状态，其他条件收进更多筛选。
- 工具栏低频操作收进“更多”，操作列保持可见。

### 6.3 窄屏

- `< 768px` 部门树改为顶部“组织范围”选择器，不与表格并排。
- 表格最小宽度 960px，在容器内横向滚动，不拆成信息密度失控的卡片。
- 新增/编辑抽屉占满屏幕，字段单列，底部操作固定。
- 批量选择栏固定在表格底部，删除仍需明确确认。

## 7. 部门树设计

### 7.1 节点与选择语义

- “全部部门”是页面级虚拟节点，选中后清除 `deptId` 与 `belongDeptId`。
- 选中真实部门树节点提交 `belongDeptId`，查询该部门及全部下级部门的岗位。
- 查询区选择“精确部门”提交 `deptId`，并清除树的当前选中态；接口以精确部门优先。
- 搜索部门只过滤树节点，不直接请求岗位列表。
- 搜索命中子部门时保留其祖先路径；清空搜索后恢复展开状态。
- 部门为空或树加载失败时，右侧仍可查询全量岗位，不让辅助导航阻断主任务。

### 7.2 展开与状态

- 首次进入默认展开前两级，选中当前节点时确保其祖先已展开。
- 部门节点显示名称，停用节点增加“停用”文字标签，不仅降低透明度。
- 选中停用部门仍可查看历史岗位，但新增岗位按钮不可预填为该部门。
- 树加载失败在左栏局部显示重试，不清空已经加载的岗位表格。

## 8. 查询设计

| 条件     | 控件         | 请求字段                    | 规则                               |
| -------- | ------------ | --------------------------- | ---------------------------------- |
| 岗位名称 | 文本输入框   | `postName`                  | 模糊匹配，去首尾空格，最多 50 字符 |
| 岗位编码 | 文本输入框   | `postCode`                  | 模糊匹配，去首尾空格，最多 64 字符 |
| 状态     | 单选下拉框   | `status`                    | 全部、正常 `0`、停用 `1`           |
| 类别编码 | 文本输入框   | `postCategory`              | 模糊匹配，最多 100 字符            |
| 精确部门 | 树选择器     | `deptId`                    | 只查询一个部门，不包含下级         |
| 创建时间 | 日期范围选择 | `params[beginTime/endTime]` | 开始时间不得晚于结束时间           |

交互规则：

- 点击查询或在文本输入框按 Enter 执行请求，并把页码重置为 1。
- 修改筛选值不自动请求，避免岗位表格频繁刷新。
- 重置清空查询条件、部门树选中、页码和行选择，重新加载全量岗位。
- 查询条件写入 URL；页码和每页条数可一并持久化，返回页面时恢复工作上下文。
- 已生效的隐藏条件以筛选标签展示，不能让“更多筛选”收起后条件不可见。

## 9. 岗位表格

### 9.1 列定义

| 列       | 展示规则                                      | 默认显示 |
| -------- | --------------------------------------------- | -------- |
| 选择     | 当前页多选；表头全选只选当前页                | 是       |
| 岗位名称 | 主信息，附岗位编码；超长省略并 Tooltip        | 是       |
| 岗位编码 | 等宽字体，可复制；租户内唯一                  | 是       |
| 类别编码 | 空值显示 `—`                                  | 是       |
| 所属部门 | 显示 `deptName`；空字符串显示“部门已失效”警告 | 是       |
| 排序     | 显示 `postSort`；支持白名单服务端排序         | 是       |
| 状态     | 正常、停用，使用文字和状态点                  | 是       |
| 创建时间 | `YYYY-MM-DD HH:mm`                            | 是       |
| 操作     | 编辑、删除                                    | 是       |

- 默认排序为 `postSort`、`postId` 的稳定组合；如接口当前默认不同，以后端真实顺序为准。
- 停用岗位保持完整可读性，不将整行降到无法辨认。
- 复制岗位编码成功后给轻量反馈；复制失败不能影响其他表格操作。
- 页码切换、刷新和查询后清空选择，避免对不可见旧数据执行批量操作。

### 9.2 分页与选择

- 分页使用后端返回的 `total`，切换每页条数后回到第 1 页。
- 表头全选只影响当前页，文案明确显示“已选 N 项”。
- 单选时可使用工具栏“编辑”；多选时编辑禁用并说明原因。
- 批量删除只提交当前已选 ID，不实现跨页隐式全选。

## 10. 工具栏与权限

| 操作     | 权限                 | 可用条件                                   |
| -------- | -------------------- | ------------------------------------------ |
| 新增岗位 | `system:post:add`    | 始终可用；选中正常部门时预填所属部门       |
| 编辑岗位 | `system:post:edit`   | 工具栏仅单选可用；行内编辑直接作用于当前行 |
| 批量删除 | `system:post:remove` | 至少选中一项                               |
| 导出     | `system:post:export` | 后端导出接口完成后开放                     |
| 刷新     | 列表查看权限         | 保留查询条件，清空行选择并刷新             |
| 列设置   | 列表查看权限         | 岗位名称、状态和操作列不可隐藏             |

- 无权限的操作不展示；业务条件不满足的操作展示禁用状态和原因。
- 原型中的导出按钮展示“接口待接入”提示，实际页面不得用前端 CSV 冒充后端审计导出。

## 11. 新增与编辑抽屉

抽屉宽度桌面端 `520px`，窄屏占满。打开编辑抽屉前请求详情，不直接把列表行当作完整详情。

| 字段     | 请求字段       | 必填 | 规则与说明                               |
| -------- | -------------- | ---- | ---------------------------------------- |
| 所属部门 | `deptId`       | 是   | 可搜索树选择；必须是当前租户有效部门     |
| 岗位名称 | `postName`     | 是   | 最多 50 字符；同部门内唯一               |
| 岗位编码 | `postCode`     | 是   | 最多 64 字符；租户内唯一；建议大写下划线 |
| 类别编码 | `postCategory` | 否   | 最多 100 字符；没有字典前使用文本输入    |
| 岗位顺序 | `postSort`     | 是   | 大于等于 0 的整数                        |
| 岗位状态 | `status`       | 是   | 正常 `0`、停用 `1`                       |
| 备注     | `remark`       | 否   | 最多 500 字符，显示剩余字数              |

交互规则：

- 从部门树上下文新增时预填当前部门；从全量视图新增时不预填。
- 新增默认状态为正常、岗位顺序为 0。
- 岗位编码输入自动去除首尾空格，不擅自改写大小写。
- 编辑时若修改所属部门，名称唯一性按目标部门重新校验。
- 编辑已分配用户的岗位并选择“停用”时，提交后由后端返回占用错误；页面保留表单内容并聚焦状态说明。
- 保存期间禁用重复提交；成功后关闭抽屉、刷新当前页并定位更新行。
- 关闭有未保存变更的抽屉时提示“放弃本次修改？”。

## 12. 删除设计

### 12.1 单个删除

确认弹窗展示岗位名称、岗位编码和所属部门：

```text
删除岗位“前端工程师”？
岗位编码：FE_DEV · 所属部门：研发一部

删除后不可恢复；若岗位已分配用户，系统将拒绝删除。
                                      [取消] [删除岗位]
```

### 12.2 批量删除

- 标题显示“删除已选的 N 个岗位？”，内容列出前 3 个岗位名称，其余折叠为数量摘要。
- 明确说明批量删除是原子操作：任一岗位不存在或被用户占用时整批失败。
- 失败反馈优先显示后端给出的岗位名称和阻塞原因，保留当前选择方便处理。
- 成功后清空选择并重新请求当前页；若当前页被删空且页码大于 1，回退一页。
- 删除为硬删除，不提供“恢复”文案或虚假的撤销入口。

## 13. 状态与反馈

### 13.1 页面状态

| 状态       | 设计要求                                                |
| ---------- | ------------------------------------------------------- |
| 首次加载   | 部门树骨架与表格骨架独立展示                            |
| 查询加载   | 保留表头与已有行，显示轻量加载遮罩，避免布局跳动        |
| 空岗位     | “当前范围还没有岗位”，有权限时提供新增岗位入口          |
| 查询无结果 | “没有找到符合条件的岗位”，提供清除筛选                  |
| 部门树失败 | 左栏局部错误与重试；右侧全量岗位仍可使用                |
| 列表失败   | 表格区域错误、重试和请求标识；保留查询条件              |
| 权限不足   | 页面级 403 或隐藏具体操作，不把后端权限错误伪装成空数据 |

### 13.2 业务错误映射

| 场景           | 页面反馈                                           |
| -------------- | -------------------------------------------------- |
| 岗位名称重复   | 定位“岗位名称”，提示“该部门已存在同名岗位”         |
| 岗位编码重复   | 定位“岗位编码”，提示“岗位编码已存在，请更换后重试” |
| 部门已删除     | 保留表单，刷新部门树并要求重新选择所属部门         |
| 岗位已分配用户 | 停用或删除失败，显示被占用的岗位名称和处理方向     |
| 数据已被删除   | 关闭详情抽屉、刷新列表并提示“岗位已不存在”         |
| 数据过期       | 批量操作整批失败，刷新当前页并保留可识别的有效选择 |

## 14. API 映射

基础前缀：`/api/v1/system/post`

| 页面行为   | 请求                | 成功处理                             |
| ---------- | ------------------- | ------------------------------------ |
| 加载列表   | `GET /list`         | 读取 `data.rows`、`data.total`       |
| 加载部门树 | `GET /deptTree`     | 构建树选择与左侧部门导航             |
| 获取详情   | `GET /{postId}`     | 填充编辑抽屉                         |
| 新增岗位   | `POST /`            | 使用 201 响应数据刷新当前页          |
| 修改岗位   | `PUT /`             | 使用响应数据更新或重新查询           |
| 删除岗位   | `DELETE /{postIds}` | 逗号拼接当前已选岗位 ID              |
| 岗位选项   | `GET /optionselect` | 用户表单等调用方使用，本页不重复请求 |
| 导出岗位   | `POST /export`      | 当前未实现，完成前隐藏或禁用         |

实现注意：

- 大整数 ID 使用项目既有的 `number | string` 类型边界，不做 `Number()` 强转。
- 列表参数沿用驼峰字段；`deptId` 与 `belongDeptId` 不同时提交。
- 后端真实 HTTP 状态和 `R.code` 都应进入统一请求层处理。
- 不在表格中逐行请求部门详情，直接使用 `deptName`。

## 15. 响应式、可访问性与主题

- 部门树支持键盘上下移动、左右展开/收起和 Enter 选择。
- 抽屉打开后焦点进入标题或首个字段，关闭后回到触发按钮。
- 弹窗使用焦点陷阱，Escape 只关闭当前最上层浮层。
- 状态使用文字与圆点共同表达，不能只依赖颜色。
- 所有图标按钮提供可访问名称和 Tooltip，可见焦点样式不得移除。
- 表头复选框提供“选择当前页全部岗位”的语义标签。
- 浅色、深色主题均使用设计系统语义 Token；原型提供主题切换用于检查。
- `prefers-reduced-motion` 下关闭抽屉位移和非必要动画。
