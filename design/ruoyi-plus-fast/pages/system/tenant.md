## 2. 架构结论

租户模块是平台级控制面，不是普通租户的企业资料页：

```text
平台超级管理员
├── 租户套餐：定义可授权的菜单边界
└── 租户管理：开通企业、维护生命周期、执行显式同步
    ├── 新增 → 租户 + 根部门 + 管理员角色 + 管理员账号 + 初始字典/参数
    ├── 停用 → 阻止后续登录，但不立即清理现有会话
    ├── 同步套餐 → 重算一家租户角色菜单，不更换 packageId
    └── 删除 → 软删租户记录，租户业务数据与编号保留
```

职责边界：

- 前端负责筛选、分页、选择、表单校验、菜单树交互、风险说明和结果反馈。
- `TenantService` 负责列表、详情、导出及登录侧的租户可用性判断。
- `TenantAdminService` 负责租户开通、修改、状态、软删除、套餐/字典/参数同步的事务边界。
- `TenantPackageService` 负责套餐列表、详情、状态、唯一性与“仍被租户使用”约束。
- 菜单模块提供套餐菜单树；租户套餐页面不自行拼树，也不能把“租户管理”分支授权给普通租户。
- 用户、部门、角色、字典和参数模块拥有各自数据；租户开通仅通过模块用例完成初始化。

拆成两个独立页面的原因：

1. 两者是两个动态菜单入口，权限边界不同。
2. 套餐是可复用授权模板，租户是企业生命周期对象。
3. 修改套餐不会自动同步存量租户，必须保留清晰的跨页面因果关系。
4. 套餐编辑需要大面积菜单树，不能塞进租户编辑表单。

### 3.2 Java 参考事实

- 租户查询字段：租户编号、联系人、联系电话、企业名称。
- 租户表格：租户编号、联系人、电话、企业名称、统一社会信用代码、过期时间、状态。
- 新增租户还需管理员用户名、密码和套餐；修改时套餐下拉被禁用。
- 租户支持新增、修改、批量删除、导出、状态变更、单租户套餐同步，以及超级管理员触发的全量字典/参数同步。
- 套餐按名称查询，展示名称、备注和状态；编辑时通过菜单树配置 `menuIds` 与 `menuCheckStrictly`。
- Java 控制器要求超级管理员角色，并为租户/套餐 CRUD 使用对应权限点；管理租户受保护，套餐被租户使用时不能删除。

Java 仅作为业务参考，不证明当前 FastAPI 权限或返回结构完全相同。

### 3.3 当前 FastAPI 事实

已实现：

- 路由只在 `TENANT_ENABLED` 开启时挂载；关闭时整个 `/system/tenant` 路由族返回 404。
- 租户列表与详情返回 `R[Page[TenantResponse]]`、`R[TenantResponse]`；套餐使用相同 `R` 信封和分页结构。
- 两个导出接口返回 xlsx 二进制流，不使用 `R` 信封，并导出全部筛选命中项。
- 新增租户请求使用加密路由；租户编号由服务端生成，成功响应会返回编号。
- 新增租户在一个事务内建立租户、根部门、管理员角色、管理员账号、初始字典和参数。
- 修改租户不接收 `tenantId` 和 `packageId`；换套餐不是普通编辑能力。
- 管理租户（默认编号或主键 1）不能修改、停用或删除，返回 403。
- 停用租户阻止后续登录，但当前 Redis 会话不会立即失效。
- 删除租户是软删除；其用户和业务数据不删除，租户编号不回收。
- 套餐名称、企业名称重复返回 409；不存在返回 404；参数不合法返回 422。
- 套餐被租户使用时删除返回 409，批量目标中任一项失败则整批不删除。
- 套餐停用只是不再出现在新租户套餐下拉中，不影响已经挂载的租户。
- 修改套餐菜单不会自动重算存量租户；租户页需显式调用 `syncTenantPackage`。
- 套餐菜单树接口为 `GET /system/menu/tenantPackageMenuTreeselect/{packageId}`，新增传 `0`；树排除租户管理分支。

权限现状：

- 租户路由当前全部只有超级管理员门禁，`system:tenant:*` 细粒度权限尚未接入。
- 套餐路由同时要求超级管理员和 `system:tenantPackage:list|query|add|edit|remove|export`。
- 套餐菜单树当前要求超级管理员，但没有独立套餐权限依赖。

### 3.4 当前 React 事实

- 已有 tenant 与 tenant-package 的类型、URL、请求函数、Query Key 和 TanStack Query hooks。
- 类型已对齐 `Page.records/current/size/total`、字符串状态、Long 序列化和 `menuIds: number[]`。
- 租户新增请求标记 `encrypt: true`；导出使用 blob；删除上限注释为 100 条。
- 当前不存在 `pages/(admin)/system/tenant` 或 `tenantPackage` 页面，生成路由树中也没有对应入口。
- 当前没有套餐菜单树的 React 请求封装被纳入本页面实现证据。

### 3.5 设计假设与明确不做

- 两个页面只面向平台超级管理员；套餐按钮继续按当前权限点显隐。
- 租户套餐名称通过 `selectList` 在前端映射；接口只返回启用套餐，因此停用套餐回显可能只能显示“套餐 #ID”，实施前需确认是否改用完整套餐列表缓存。
- 当前页概览只使用已加载页面数据并标注“当前页”，不伪装成全量统计。
- 不在租户操作列加入“动态切换租户”。该状态没有过期时间且会影响后续请求，应该由全局租户上下文控件承载，并持续显示“当前数据视角”。
- 不设计“更换套餐”；当前后端同步接口不会修改 `sys_tenant.package_id`。
- 不设计恢复软删记录、同步进度、影响人数和并发版本提示，因为当前没有对应接口。
- 原型数据只在浏览器内变化，不调用真实 API。

### 5.6 详情与操作

- 详情抽屉展示当前响应中的全部字段，不展示当前接口不存在的更新时间或在线人数。
- “同步套餐”说明：按当前 `packageId` 重算角色菜单；管理员角色整体替换，普通角色只移除套餐外菜单；不会更换套餐。
- “同步租户字典 / 参数”是全平台操作，只作用于正常租户，默认租户作为源且不作为目标；当前接口不返回进度或数量。
- 停用前说明：阻止后续登录；现有会话不会立即退出。
- 删除前说明：仅软删租户记录；业务数据保留、编号不回收；没有恢复接口。批量中包含管理租户或过期数据时整批不执行。

| 状态     | `status`                   | 正常 / 停用；不用行内开关                       |
| 创建时间 | `createTime`               | `YYYY-MM-DD HH:mm`                              |
| 操作     | -                          | 详情、编辑、更多                                |

### 6.4 新增与编辑字段

| 字段     | 请求字段            | 必填 | 默认值   | 校验与说明                                      |
| -------- | ------------------- | ---- | -------- | ----------------------------------------------- |
| 套餐名称 | `packageName`       | 是   | 空       | 1-20 字符；全平台唯一，冲突 409                 |
| 菜单     | `menuIds`           | 否   | `[]`     | 正整数数组；最多 500 个且编码后不超过 3000 字符 |
| 父子联动 | `menuCheckStrictly` | 是   | `true`   | 控制树选择与回显规则                            |
| 状态     | `status`            | 是   | 正常 `0` | 停用后不能用于新增租户                          |
| 备注     | `remark`            | 否   | 空       | 最多 200 字符                                   |

菜单树行为：

- 新增请求 `GET /system/menu/tenantPackageMenuTreeselect/0`；编辑使用真实 `packageId` 并回填 `checkedKeys`。
- 支持搜索、展开/折叠、全选/清空和父子联动；工具栏操作只改变本地草稿。
- 树中不出现“租户管理”分支，避免套餐将平台控制面授权给普通租户。
- 保存提交数字数组，不提交数据库逗号字符串。
- 编辑保存成功后提示“套餐已更新，存量租户不会自动同步”，并提供去租户页的链接。

### 6.5 状态与删除

- 停用套餐前说明：仅阻止新增租户选择，不影响当前使用它的租户与权限。
- 删除是软删除但无恢复接口，按不可恢复操作表达。
- 任一套餐仍被租户引用时返回 409，整批不删除；页面保留选择并引导到租户页筛选对应套餐。
- 修改套餐名称或菜单的并发冲突当前没有版本字段，页面不能承诺冲突检测。

## 9. 响应式与可访问性

- `>= 1200px` 使用 220px 侧栏、全宽表格和 640px 抽屉。
- `992px - 1199px` 收起侧栏，隐藏低频列，将维护/导出收进更多操作。
- `< 768px` 隐藏侧栏，筛选单列，表格在自身容器内横向滚动；页面根节点不横向溢出。
- 手机抽屉全屏，底部操作固定；菜单树拥有独立滚动区，不能被页面滚动吞掉。
- 所有按钮显式声明类型；图标按钮提供 `aria-label`；当前导航使用 `aria-current="page"`。
- 抽屉和弹窗使用可访问标题、焦点管理、Escape 关闭；未保存表单关闭前二次确认。
- 状态、保护、到期和风险均使用图标或文字，不只依赖颜色。
- 触控目标不小于 40px；动画尊重 `prefers-reduced-motion`。

## 10. 验收标准

1. 两个页面分别通过独立 URL 和独立 `index.html` 打开，彼此相对链接有效。
2. 租户页可完成查询、重置、选择、新增、详情、编辑、套餐同步、状态和删除的原型流程。
3. 新增租户明确显示账号密码仅用于开通、请求需加密、租户编号由服务端生成。
4. 编辑租户不能修改编号、管理员账号密码和套餐。
5. 管理租户不能被选择、修改、停用或删除，阻塞原因可见。
6. 停用租户明确说明现有会话不会立即失效；删除明确说明业务数据保留且编号不回收。
7. 套餐页可完成查询、重置、新增、详情、编辑菜单树、状态和删除的原型流程。
8. 套餐菜单树支持搜索、展开/折叠、全选/清空和父子联动，且不出现租户管理分支。
9. 修改套餐后明确提示存量租户不会自动同步；删除占用套餐时整批不执行。
10. 导出只表达服务端 xlsx 能力，不由前端生成假 CSV。
11. 1440×1000、1024×768、390×844 下主要任务可发现，页面无意外横向溢出。
12. 原型不调用真实写接口，控制台无未处理异常，本地资源无 404。

## 11. 风险与待确认项

| 项目           | 当前判断                         | 影响                             | 处理方式                                         |
| -------------- | -------------------------------- | -------------------------------- | ------------------------------------------------ |
| 租户细粒度权限 | FastAPI 尚未接 `system:tenant:*` | 前端按钮权限无法与后端逐项一致   | 当前只对超级管理员开放；后端补齐后再接按钮显隐   |
| React 页面路由 | 页面和最终菜单节点尚不存在       | `/system/tenantPackage` 可能改名 | 实施时以动态菜单与 TanStack Router 同步结果为准  |
| 停用会话       | 不会立即清理                     | 用户短期仍在线                   | 确认弹窗如实说明；需要即时生效时增加会话清理能力 |
| 套餐名称回显   | `selectList` 只返回正常套餐      | 停用套餐可能只显示 ID            | 实施时使用完整套餐列表或扩展详情映射接口         |
| 同步可观测性   | 接口无 dry-run、目标数和进度     | 全量同步期间反馈有限             | 只显示进行中与最终结果，不伪造百分比             |
| 并发覆盖       | 无版本号或更新时间写入校验       | 后保存可能覆盖先保存             | 当前标为风险；后续增加版本字段或冲突检测         |
| 唯一性竞态     | 企业名和套餐名是应用层软约束     | 并发新增可能产生重名             | 后端后续增加数据库唯一约束                       |
