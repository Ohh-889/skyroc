## 2. 架构结论

菜单管理不是普通的导航文案配置页，而是系统路由资源、页面入口和按钮权限的统一治理入口：

```text
资源树维护
  → 目录、菜单、按钮类型约束
  → 路由、组件、外链和缓存配置
  → 权限字符维护
  → 角色授权与租户套餐引用
  → 动态路由刷新、权限缓存失效和审计
```

页面职责：

- 前端负责层级浏览、条件检索、类型化表单、权限显隐、危险操作确认和结果反馈。
- 菜单管理用例负责树结构校验、同级排序、字段组合校验、循环依赖防护和事务边界。
- 动态路由服务负责把菜单资源转换为当前前端能够消费的路由协议，不由管理页面拼装运行时路由。
- 角色和租户套餐模块负责菜单引用关系；删除或停用前由后端返回影响摘要。
- 认证与权限模块负责菜单、按钮权限变化后的缓存失效策略。
- 操作日志记录新增、修改、移动、停用和删除等敏感变更，前端不提交审计字段。

页面采用：

```text
查询区 + 树形表格
  + 新增/编辑抽屉
  + 单节点删除确认
  + 级联删除弹窗
```

树形表格是主工作区，新增和编辑使用右侧抽屉保留当前层级上下文。级联删除使用独立弹窗展示选择范围和影响，不与普通删除共用一个模糊确认框。

## 3. 已知事实与假设

### 3.1 已验证事实

- RuoYi 参考实现按菜单名称和状态查询，结果使用树形表格展示。
- 参考实现支持新增根节点、新增子节点、修改、单节点删除和级联删除。
- 节点类型固定为 `M` 目录、`C` 菜单、`F` 按钮。
- 目录和菜单可配置图标、路由地址、显示状态和菜单状态。
- 菜单可配置组件路径、路由参数和缓存策略。
- 菜单和按钮可配置权限字符；目录不需要权限字符。
- 隐藏菜单可以配置激活路由，当前后端模型复用 `remark` 字段承载该值。
- 当前 React 应用具备后端动态路由加载基础设施，但尚未发现菜单管理页面。
- 当前 FastAPI 后端已有 `sys_menu` 模型、建表迁移和初始化数据，尚未形成完整菜单管理 Repository、Service 和 API。
- `sys_menu` 是平台级资源，不含 `tenant_id`；租户可用菜单应通过套餐或授权关系约束。

### 3.2 设计假设

- 首期沿用现有后端模型，不新增菜单版本、发布状态或拖拽排序字段。
- 首期使用数字排序输入，不提供拖拽重排；拖拽在大树中容易误操作，也需要额外的批量排序契约。
- 列表默认懒展开或按已加载数据构树，接口最终选择需以数据规模和后端实现为准。
- 修改成功后按后端策略刷新当前树节点；是否立即影响在线用户由权限缓存策略决定。
- `remark` 当前作为隐藏菜单激活路径使用，首期不再同时设计独立的普通备注输入。

以上假设在接口开发前需要由前后端共同确认，不应在页面中静默固化。

## 4. 页面目标

页面需要让有权限的管理员：

1. 快速理解系统菜单、页面和按钮权限的层级关系。
2. 通过名称、状态和类型定位资源，不必逐层展开整棵树。
3. 创建符合路由协议的目录、菜单、按钮和外链节点。
4. 修改节点时清楚知道变更会影响导航、访问权限还是页面缓存。
5. 在删除、移动或停用前看见子节点和引用影响。
6. 通过清晰的字段说明避免填反 RuoYi 的 `0/1` 枚举语义。
7. 在权限不足、并发修改、循环层级或引用约束拦截时得到可执行反馈。

### 6.1 桌面端

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 菜单管理                       维护导航结构、页面路由与按钮权限              │
├──────────────────────────────────────────────────────────────────────────────┤
│ 菜单名称 [输入名称________] 状态 [全部⌄] [更多筛选]     [查询] [重置]       │
├──────────────────────────────────────────────────────────────────────────────┤
│ 菜单资源  共 42 个节点     [新增根节点] [级联删除] [展开全部] [刷新]        │
├──────────────────────────────────────────────────────────────────────────────┤
│ 菜单名称        类型   排序  路由/组件         权限标识       状态    操作  │
│ v 系统管理      目录    1   /system            —              正常    + ··· │
│   v 用户管理    菜单    1   user               system:user:*  正常    + ··· │
│       用户查询  按钮    1   —                  system:user:list 正常   编辑  │
│   > 菜单管理    菜单    2   menu               system:menu:*  正常    + ··· │
├──────────────────────────────────────────────────────────────────────────────┤
│ 当前展示 4 / 42 个节点                         最近更新 2026-08-05 10:32    │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 使用全部可用宽度，不限制为固定 1440px 容器。
- 页面内边距遵循设计系统的 24px；紧凑模式使用 16px。
- 查询区和表格区使用两个弱边框容器，不堆叠强阴影。
- 菜单名称列固定左侧，操作列固定右侧；表格允许横向滚动。
- 树表不分页，底部展示当前已加载节点数和总节点数；大数据量时改为服务端懒加载。
- 行缩进每级 20px，展开按钮、节点图标和名称保持稳定对齐。
- 操作列只直接显示“新增子级”和“编辑”，删除等低频或危险操作进入更多菜单。

### 6.2 中等宽度

- `992px - 1199px` 隐藏创建时间和图标独立列。
- 路由地址与组件路径合并为“路由资源”两行展示。
- 查询区只保留名称、状态、查询和重置，类型进入更多筛选。
- 操作列固定在右侧，按钮改为图标加 Tooltip。

### 6.3 窄屏

- `< 768px` 保证查询、展开树和查看配置，复杂新增编辑建议在桌面端完成。
- 表格最小宽度为 920px，容器横向滚动，不把树形表格改造成失去层级的卡片流。
- 新增/编辑抽屉占满屏幕，底部操作固定，表单改为单列。
- 批量级联删除默认不在窄屏提供，避免树选择和影响确认被压缩。

## 7. 查询设计

### 7.1 默认条件

| 条件     | 控件       | 规则                                   |
| -------- | ---------- | -------------------------------------- |
| 菜单名称 | 文本输入框 | 模糊匹配，最多 50 字符，回车触发查询   |
| 状态     | 单选下拉框 | 全部、正常、停用                       |
| 节点类型 | 单选下拉框 | 全部、目录、菜单、按钮，放在更多筛选中 |

### 7.2 查询结果的树语义

- 搜索命中子节点时必须返回或在前端保留其祖先路径，否则无法理解节点归属。
- 祖先行仅用于展示路径时应标记为“路径节点”，不能被误认为自身命中。
- 状态筛选为“停用”时，若子节点停用但父节点正常，仍展示父级路径。
- 查询后默认展开到所有命中节点；清空条件后恢复查询前的展开状态。
- 重置清空全部条件、清除校验提示并重新加载完整根层级。
- 查询状态写入 URL 查询参数，刷新或返回页面后可以恢复。

## 8. 树形表格

### 8.1 列定义

| 列       | 展示规则                                         | 默认显示 |
| -------- | ------------------------------------------------ | -------- |
| 菜单名称 | 展开控件、图标、名称；超长省略并 Tooltip         | 是       |
| 类型     | 目录、菜单、按钮使用中性标签区分                 | 是       |
| 排序     | 显示 `order_num`，同级按排序值和菜单 ID 稳定排序 | 是       |
| 路由资源 | 第一行路由地址，第二行组件路径；按钮显示 `—`     | 是       |
| 权限标识 | 等宽字体；空值显示 `—`；支持一键复制             | 是       |
| 显示状态 | 显示、隐藏；按钮节点显示 `—`                     | 否       |
| 节点状态 | 正常、停用，使用文字加状态点                     | 是       |
| 创建时间 | `YYYY-MM-DD HH:mm`                               | 是       |
| 操作     | 新增子级、编辑、更多                             | 是       |

### 8.2 节点视觉

| 类型 | 图标与标签           | 主要识别信息                   |
| ---- | -------------------- | ------------------------------ |
| 目录 | 文件夹图标、目录标签 | 菜单名称、路由前缀、子节点数量 |
| 菜单 | 页面图标、菜单标签   | 菜单名称、路由地址、组件路径   |
| 按钮 | 权限点图标、按钮标签 | 菜单名称、权限字符             |

- 业务图标仅对目录和菜单有意义；按钮统一使用权限点图标。
- 隐藏节点在名称旁显示“隐藏”，不能只降低透明度。
- 停用节点保留完整可读性，不将整行置灰到无法辨认。
- 当前查询命中的文字高亮，路径祖先不高亮。

### 8.3 展开策略

- 首次进入默认只加载和展示根节点，不默认展开整棵树。
- 用户可逐节点展开，也可使用“展开全部”；节点较多时需二次提示加载成本。
- 懒加载失败在父行下方显示局部错误和重试，不清空整张表。
- 新增子节点成功后展开父节点并定位新节点。
- 编辑成功后保持当前展开状态和滚动位置。
- 删除最后一个子节点后，父节点的展开标识必须同步消失。

## 9. 工具栏与操作

### 9.1 页面级操作

| 操作       | 权限                 | 行为                                   |
| ---------- | -------------------- | -------------------------------------- |
| 新增根节点 | `system:menu:add`    | 打开抽屉，父级默认为“主类目”           |
| 级联删除   | `system:menu:remove` | 打开树选择弹窗，不直接执行             |
| 展开全部   | 列表查看权限         | 展开当前查询结果的所有可用节点         |
| 刷新       | 列表查看权限         | 保留筛选条件并刷新数据                 |
| 列设置     | 列表查看权限         | 控制非关键列显示，名称和操作列不可隐藏 |

### 9.2 行操作

| 操作     | 可用节点   | 行为                                     |
| -------- | ---------- | ---------------------------------------- |
| 新增子级 | 目录、菜单 | 打开新增抽屉，预填当前节点为上级         |
| 编辑     | 全部类型   | 拉取详情后打开抽屉                       |
| 复制配置 | 全部类型   | 首期可不实现；实现时不复制 ID 和审计字段 |
| 删除     | 全部类型   | 先请求影响信息，再进入单节点删除确认     |

- 按钮节点不允许新增子级。
- 无权限的操作不展示；因节点规则不可用的操作展示禁用状态及原因。
- 行内不提供状态开关，避免误触造成路由或权限立即失效。

## 10. 新增与编辑抽屉

### 10.1 抽屉结构

- 桌面端宽度 720px，窄屏占满。
- 标题区显示“新增菜单”或“编辑菜单”，副标题显示当前父级路径。
- 内容依次为“归属与类型”“基础信息”“路由配置”“权限与状态”。
- 底部固定“取消”和“保存”按钮；整个页面只保留一个主要按钮。
- 编辑时显示只读菜单 ID 和最近更新时间，便于排查并发修改。

### 10.2 菜单类型切换

顶部使用分段单选：

| 类型 | 面向对象            | 核心字段                                    |
| ---- | ------------------- | ------------------------------------------- |
| 目录 | 导航分组、父级容器  | 上级、名称、图标、排序、路由、显示、状态    |
| 菜单 | 可访问页面或外/内链 | 目录字段 + 组件、参数、缓存、权限、激活路由 |
| 按钮 | 页面内操作权限      | 上级、名称、排序、权限字符、状态            |

- 切换类型时保留各类型共有字段。
- 将变为无效且已填写的字段清空前必须提示；不能隐藏后继续把旧值提交。
- 编辑已有节点切换类型属于高影响操作，保存确认中列出将被清空的字段。

## 11. 字段规则

### 11.1 通用字段

| 字段     | 必填 | 规则                                 |
| -------- | ---- | ------------------------------------ |
| 上级菜单 | 是   | 根级使用 `0`；不能选择自身或自身后代 |
| 菜单类型 | 是   | `M`、`C`、`F`                        |
| 菜单名称 | 是   | 1-50 字符，去除首尾空格              |
| 显示排序 | 是   | 非负整数；只定义同级顺序             |
| 菜单状态 | 是   | `0` 正常、`1` 停用                   |

### 11.2 路由字段

| 字段     | 适用类型   | 规则                                                         |
| -------- | ---------- | ------------------------------------------------------------ |
| 菜单图标 | 目录、菜单 | 使用现有图标选择器；空值统一提交 `#` 或按接口约定            |
| 是否外链 | 目录、菜单 | `0` 是外链、`1` 不是外链；界面显示语义文字，不直接展示数字   |
| 路由地址 | 目录、菜单 | 最长 200；外链必须以 `http://` 或 `https://` 开头            |
| 组件路径 | 菜单       | 最长 255；普通页面必填，外链/内链按动态路由协议处理          |
| 路由参数 | 菜单       | 最长 255；要求为合法 JSON 对象或后端明确支持的查询字符串格式 |
| 是否缓存 | 菜单       | `0` 缓存、`1` 不缓存；组件名称需满足现有 keep-alive 协议     |
| 显示状态 | 目录、菜单 | `0` 显示、`1` 隐藏                                           |
| 激活路由 | 隐藏菜单   | 填写默认高亮的可见父菜单路径；当前模型映射到 `remark`        |

### 11.3 权限字符

- 目录不展示权限字符输入。
- 菜单权限字符可空；若填写，建议使用 `模块:资源:动作` 格式。
- 按钮权限字符必填，例如 `system:menu:add`。
- 最长 100 字符，只允许字母、数字、冒号、连字符、下划线和通配符。
- 权限字符需要全局唯一或按后端既定规则校验，不能只在当前父节点下校验。
- 编辑权限字符前提示其角色授权和前端按钮显隐可能同步变化。

### 11.4 父子类型约束

| 父节点 | 可新增子节点               |
| ------ | -------------------------- |
| 主类目 | 目录、菜单                 |
| 目录   | 目录、菜单                 |
| 菜单   | 菜单、按钮，按路由协议限制 |
| 按钮   | 不允许                     |

是否允许“菜单下再挂菜单”需要与 RuoYi 现有路由转换规则保持一致。后端必须执行最终校验，前端禁用只用于提前反馈。

## 12. 状态、显示与访问语义

| 配置            | 导航中显示 | 路由可访问 | 权限点可授予   | 说明                     |
| --------------- | ---------- | ---------- | -------------- | ------------------------ |
| 显示 + 正常     | 是         | 是         | 是             | 常规节点                 |
| 隐藏 + 正常     | 否         | 是         | 是             | 详情页、编辑页等辅助路由 |
| 任意显示 + 停用 | 否         | 否         | 否或按策略保留 | 停用是访问级禁用         |
| 按钮 + 正常     | 不适用     | 不适用     | 是             | 只控制操作权限           |

- “隐藏”不是“停用”，字段说明和结果反馈必须区分。
- 停用目录时，后端需要明确子节点是继承不可访问还是同步停用；前端不能自行批量修改子节点状态。
- 停用或恢复成功后提示动态路由和权限缓存的生效范围。

## 13. 单节点删除

### 13.1 删除前检查

点击删除后先获取影响摘要：

- 是否存在直接子节点。
- 被多少角色引用。
- 被多少租户套餐引用。
- 是否为系统保护节点。
- 删除后是否影响当前操作者正在使用的页面。

### 13.2 确认规则

- 无子节点且无引用时，显示菜单名称、类型和路径后确认删除。
- 存在子节点时，普通删除不可执行，引导使用级联删除或先迁移子节点。
- 存在角色或套餐引用时，默认阻止删除；若业务允许解除引用，必须由专门接口原子处理。
- 删除当前页面对应节点时，提示保存成功后可能被导航到安全页面。
- 系统保护节点不展示删除操作或明确返回不可删除原因。

## 14. 级联删除

级联删除是独立高风险流程：

1. 打开菜单树选择弹窗。
2. 勾选父节点时自动包含全部后代，并显示总节点数。
3. 请求后端计算角色、套餐和路由影响。
4. 展示将删除的目录、菜单、按钮数量及引用数量。
5. 用户输入根节点名称或明确勾选风险确认后提交。
6. 服务端在单一事务中完成校验、解除允许的引用和删除。
7. 成功后刷新树与权限缓存；部分失败不能留下半棵树。

弹窗不允许默认全选，不把“主类目”作为可删除节点。当前 RuoYi 参考代码中的空选择判断需要在本项目修正为 `length === 0`。

## 15. 业务规则

### 15.1 树结构

- `parent_id = 0` 表示根级节点，“主类目”只是选择器虚拟节点。
- 节点不能把自己或自己的后代设为父级。
- 移动节点后必须重新校验目标父级类型、路由路径和同级排序。
- 删除、移动和类型变更必须在事务内更新引用关系。
- 列表排序使用 `order_num ASC, menu_id ASC` 保证稳定。

### 15.2 路由契约

- 一级内部目录的路由由后端模型转换为带 `/` 的路径。
- 一级内部菜单可能转换为菜单框架路由，不能由表单根据层级自行改写。
- HTTP(S) 地址根据 `is_frame` 区分外链与内链组件。
- 未配置组件时，后端根据目录层级返回 `Layout`、`ParentView` 或 `InnerLink`。
- 页面表单保存原始资源字段；动态路由接口负责输出前端路由协议。

### 15.3 唯一性与引用

- 同一父级下菜单名称是否唯一由产品规则确认，至少需要避免无法区分的同名同类型节点。
- 路由名称、完整路由地址和权限字符的唯一性由后端校验并返回具体冲突对象。
- 角色、租户套餐只引用菜单 ID，不在菜单表单中直接维护角色列表。
- 菜单是平台级资源，不在请求体提交租户 ID。

### 15.4 并发与审计

- 编辑接口应携带 `updatedAt` 或版本号做乐观并发控制。
- 并发冲突时保留用户输入，并提供“查看最新配置”而不是直接覆盖。
- 操作日志至少记录节点 ID、操作类型、变更前后摘要和影响数量。
- 前端不提交 `create_by`、`create_dept`、`update_by`、`created_at`、`updated_at`。

## 16. 权限设计

| 页面能力 | 权限标识             |
| -------- | -------------------- |
| 查看列表 | `system:menu:list`   |
| 查看详情 | `system:menu:query`  |
| 新增节点 | `system:menu:add`    |
| 编辑节点 | `system:menu:edit`   |
| 删除节点 | `system:menu:remove` |

- 页面路由权限和页面内按钮权限都必须校验。
- 前端权限显隐不能替代后端鉴权。
- 级联删除沿用删除权限时，后端仍需额外执行系统保护和引用约束校验。
- 没有列表权限时不加载树；没有详情权限时编辑入口不展示。
- 菜单管理自身的菜单节点是保护资源，避免管理员删除后无法恢复入口。

## 17. 接口建议

当前后端只有模型和初始化数据，下列均为目标契约。

### 17.1 菜单列表

```http
GET /system/menu/list?menuName=菜单&status=0&menuType=C
```

建议响应为扁平列表，由 `parentId` 构树；若节点量较大则增加 `parentId` 懒加载参数。响应保持本项目 `code/msg/data` 业务信封：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "menuId": 100,
      "menuName": "系统管理",
      "parentId": 0,
      "orderNum": 1,
      "path": "system",
      "component": null,
      "queryParam": null,
      "isFrame": 1,
      "isCache": 0,
      "menuType": "M",
      "visible": "0",
      "status": "0",
      "perms": null,
      "icon": "setting",
      "remark": "",
      "hasChildren": true,
      "createTime": "2026-08-05 09:30:00",
      "updateTime": "2026-08-05 09:30:00"
    }
  ]
}
```

### 17.2 详情与选择树

```http
GET /system/menu/{menuId}
GET /system/menu/treeSelect?excludeMenuId={menuId}
GET /system/menu/{menuId}/impact
```

- 详情返回可编辑原始字段和 `updatedAt`。
- 选择树排除自身及后代，服务端保证不会形成循环。
- 影响接口返回子节点、角色、套餐和保护状态摘要。

### 17.3 新增与修改

```http
POST /system/menu
PUT /system/menu/{menuId}
```

请求体使用 camelCase API 边界，服务端映射到 snake_case 模型。不同类型不适用的字段应提交 `null` 或由服务端统一归一化，不能保留历史脏值。

### 17.4 删除

```http
DELETE /system/menu/{menuId}
POST /system/menu/cascade-delete
```

级联删除请求示例：

```json
{
  "menuIds": [100, 101, 102],
  "expectedUpdatedAt": {
    "100": "2026-08-05T09:30:00"
  }
}
```

服务端应自行重新展开后代并校验最终集合，不能信任前端提供的子节点列表。

### 17.5 错误语义

| 场景         | 建议业务消息                               |
| ------------ | ------------------------------------------ |
| 父级不存在   | 上级菜单已被删除，请刷新后重试             |
| 形成循环     | 上级菜单不能选择当前节点或其下级           |
| 权限字符冲突 | 权限标识已被“用户查询”使用                 |
| 节点有子级   | 当前菜单包含 8 个子节点，不能直接删除      |
| 节点被引用   | 当前菜单被 3 个角色和 1 个租户套餐使用     |
| 并发修改     | 菜单配置已被其他管理员更新，请对比最新内容 |
| 系统保护     | 该菜单是系统保护资源，不能删除或停用       |

## 18. 数据状态

### 18.1 首次加载

- 查询区和工具栏保持可见。
- 表格显示与真实行结构一致的骨架屏，不用整块旋转图标遮挡页面。
- 加载期间禁用会重复提交的新增和删除操作。

### 18.2 空状态

- 无任何菜单：显示“尚未配置菜单资源”，有新增权限时提供“新增根节点”。
- 查询无结果：显示“未找到匹配的菜单”，提供“清空筛选”。
- 无权限：展示权限说明，不把 403 伪装成空数据。

### 18.3 错误与局部错误

- 首屏失败在表格区域展示原因和重试。
- 子节点加载失败只影响该分支。
- 保存失败保留抽屉和表单值，定位到第一个错误字段。
- 权限失效或登录过期交给全局认证处理，同时避免重复 Toast。

### 18.4 成功反馈

- 新增：`已新增“菜单管理”`，定位并短暂高亮新节点。
- 修改：`“菜单管理”已更新`，保留展开和筛选状态。
- 删除：`已删除“菜单管理”`，刷新父节点子级状态。
- 级联删除：`已删除 2 个目录、5 个菜单和 18 个按钮权限`。

## 19. 无障碍与可用性

- 树表展开按钮使用原生按钮并提供 `aria-expanded`。
- 键盘可以聚焦查询、工具栏、树节点和行操作。
- 状态、类型和显示属性不能只靠颜色表达。
- 图标按钮必须有可见 Tooltip 和无障碍名称。
- 抽屉打开后焦点进入标题或第一个字段，关闭后回到触发按钮。
- 错误提示与字段通过 `aria-describedby` 关联。
- 权限字符使用等宽字体但保持至少 12px，并允许键盘复制。
- 动效尊重 `prefers-reduced-motion`。

## 24. 原型说明

HTML 原型覆盖以下交互：

- 菜单名称、状态和类型筛选。
- 树节点展开、收起、展开全部和收起全部。
- 新增根节点、新增子节点和编辑抽屉。
- 目录、菜单、按钮切换后的动态字段。

## 25. 最终版布局补充

最终版原型保留第 24 节树表版，不覆盖原文件，并增加以下主从布局：

```text
目录 / 菜单树
  → 选中目录：右侧显示目录详情 + 直属菜单
  → 选中菜单：右侧显示菜单详情 + 按钮权限列表
  → 按钮权限只在所属菜单被选中时加载
```

最终版的取舍：

- 左侧路由树只放目录和菜单，不再混入按钮节点，降低大规模权限点对树浏览的干扰。
- 目录节点在选中或悬停时出现新增子菜单按钮；页面菜单的按钮权限从右侧列表新增。
- 右侧详情保留编辑、删除和字段摘要，不要求管理员在宽表中横向定位配置。
- 选中目录时，按钮权限列表替换为直属菜单概览；选中页面菜单时才显示按钮权限。
- 保留抽屉式新增/编辑和删除影响确认，避免参考页紧凑布局牺牲复杂表单与危险操作说明。

该布局作为当前推荐实现方向；第 24 节树表版继续作为全局资源检索和批量治理模式的备选设计。
