## 2. 架构结论

客户端管理维护的不是普通用户，而是允许接入认证系统的“端”：

```text
PC 后台 / Android / iOS / 小程序
  → 使用稳定 clientId 标识端
  → 配置该端允许的授权方式
  → 配置设备类型和令牌时长
  → 启用或停用该端的新登录能力
```

职责边界：

- 前端负责筛选、分页、表单校验、敏感字段遮罩、危险操作确认和结果反馈。
- `ClientService` 负责列表、详情、导出和登录前的客户端授权校验。
- `ClientAdminService` 负责新增、修改、状态变更和批量删除的事务边界。
- 认证模块负责判断服务端是否真正实现某种授权方式；客户端页面只决定某个端是否开通该方式。
- 字典模块提供授权类型和设备类型文案，页面不硬编码服务端业务枚举。
- 审计模块记录新增、修改、导出、状态变更和删除，前端不提交审计字段。

页面采用：

```text
查询区 + 分页表格
  + 新增/编辑客户端抽屉
  + 客户端详情抽屉
  + 停用/启用确认弹窗
  + 删除确认弹窗
  + 敏感导出确认弹窗
```

## 3. 已知事实、假设与根因

### 3.1 已知事实

- 已实现列表、详情、新增、修改、状态切换、批量软删除和 xlsx 导出接口。
- 当前所有接口暂由超级管理员门禁代管，正式权限点尚未接入。
- `clientId` 在新增时由服务端按 `md5(clientKey + clientSecret)` 生成，新增请求不允许指定。
- 编辑 `clientKey` 或 `clientSecret` 时不会重算 `clientId`，避免已发布客户端失效。
- `clientKey` 在未删除数据中全表唯一，冲突返回 `409`。
- 授权类型以字符串数组提交，服务端去重后保存为逗号分隔字符串。
- 当前认证实现支持 `password`、`sms`、`email`；字典还包含 `xcx`、`social` 等扩展值。
- 状态 `0` 为正常，`1` 为停用。
- `activeTimeout` 和 `timeout` 单位均为秒，`-1` 表示永不过期。
- 停用或删除不会立即让现有会话下线，只会阻止后续登录；当前会话最长可能持续到刷新令牌失效。
- `clientSecret` 当前明文存储、明文响应且会进入导出文件。

### 3.2 设计假设

- 首期页面仅面向超级管理员，不增加租户筛选。
- 授权类型和设备类型由字典接口加载；原型使用现有种子值演示。
- 列表默认按主键倒序，后续实现必须只使用接口允许的排序字段。
- 页面可以查看密钥，但默认遮罩，并把显示、复制和导出视为敏感操作。

### 3.3 症状与根因区分

| 表面现象 | 根因 | 页面处理 |
| --- | --- | --- |
| 修改 key 后 clientId 未变化 | clientId 是已分发的稳定端标识，不是实时派生展示值 | 编辑页明确标注“不随 key/密钥修改而变化” |
| 停用后已登录用户仍在线 | 会话中不持续校验客户端状态 | 确认弹窗说明“仅阻止新登录” |
| 令牌时长配置后可能不生效 | 认证签发仍使用全局配置 | 字段旁显示“当前后端尚未消费该配置”提示 |
| 导出包含明文密钥 | v1 契约沿用 RuoYi 导出字段 | 导出前二次确认并限制权限 |

## 4. 页面目标

1. 让管理员快速定位一个接入端及其当前状态。
2. 清楚判断每个端允许使用哪些登录方式。
3. 安全地新增和维护客户端凭据，不误解 `clientId` 的生命周期。
4. 在停用、删除、导出前明确理解影响范围。
5. 对后端暂未生效的令牌配置给出真实提示，不制造已生效的错觉。

## 6. 主页面布局

### 6.1 桌面端

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 客户端管理                       管理接入认证系统的应用端与登录能力         │
├────────────────────────────────────────────────────────────────────────────┤
│ 客户端 ID [________]  客户端 Key [_______]  状态 [全部⌄] [查询] [重置]    │
├────────────────────────────────────────────────────────────────────────────┤
│ 客户端列表  共 4 项          [新增客户端] [批量删除] [导出] [刷新]        │
├────────────────────────────────────────────────────────────────────────────┤
│ □ 客户端       设备      授权方式             令牌策略       状态   操作   │
│ □ PC 管理端     PC        密码/短信/邮件/社交   30 分钟/7 天   正常   ···    │
│ □ Android App  Android   密码/短信/社交        30 分钟/7 天   正常   ···    │
└────────────────────────────────────────────────────────────────────────────┘
```

- 页面使用全宽工作区，默认内边距 24px。
- 查询区和表格位于同一业务容器，通过分隔线建立层级，不嵌套卡片。
- 客户端识别列固定左侧，操作列固定右侧。
- 密钥不直接作为列表列；详情和编辑中默认遮罩。
- 单行只显示“查看”“编辑”和更多菜单，停用、启用、删除进入更多菜单。

### 6.2 响应式

- `992px - 1199px`：隐藏完整 clientId，仅显示前 8 位和后 6 位；授权类型允许换行。
- `< 768px`：查询区改为纵向，表格横向滚动；保留客户端、设备、状态和操作列。
- 新增和编辑抽屉在窄屏占满宽度，但令牌策略仍保持上下分组，避免横向压缩输入。

## 7. 查询设计

| 字段 | 参数 | 控件 | 规则 |
| --- | --- | --- | --- |
| 客户端 ID | `clientId` | 输入框 | 精确匹配，最长 64 字符 |
| 客户端 Key | `clientKey` | 输入框 | 精确匹配，最长 32 字符 |
| 状态 | `status` | 下拉框 | 全部、正常 `0`、停用 `1` |

交互规则：

- 查询时去除输入首尾空格并回到第 1 页。
- 重置清空筛选、排序和页码后立即重新查询。
- 筛选条件同步至 URL，返回页面时恢复。
- 不提供客户端密钥筛选，避免形成密钥猜测入口。

## 8. 列表设计

| 列 | 数据来源 | 展示规则 |
| --- | --- | --- |
| 选择 | `id` | 支持当前页全选和批量删除 |
| 客户端 | `clientKey`、`clientId` | key 为主标题，clientId 使用等宽字体和中间省略 |
| 设备类型 | `deviceType` | 显示字典文案；空值显示“未指定” |
| 授权方式 | `grantTypeList` | 标签展示，超过 3 个显示 `+N` |
| 令牌策略 | `activeTimeout`、`timeout` | 转为分钟、小时、天；`-1` 显示“永不过期” |
| 状态 | `status` | 正常/停用状态标记，不使用易误触的行内开关 |
| 操作 | - | 查看、编辑、更多 |

默认排序：`id desc`。可选排序字段仅限接口允许的 `id`、`clientId`、`clientKey`、`status`。

## 9. 新增与编辑

### 9.1 字段

| 字段 | 必填 | 校验与行为 |
| --- | --- | --- |
| 客户端 Key | 是 | 1-32 字符；唯一；建议使用小写字母、数字、`-`、`_` |
| 客户端密钥 | 是 | 1-255 字符；默认密码框；支持显示/隐藏 |
| 授权方式 | 是 | 1-10 项；每项匹配 `^[a-z][a-z0-9_]*$` |
| 设备类型 | 否 | 最长 32 字符；优先使用字典选项 |
| Token 活跃超时 | 是 | 秒；`-1` 或 `0..2147483647` |
| Token 固定超时 | 是 | 秒；`-1` 或 `0..2147483647` |
| 状态 | 是 | 正常或停用 |

### 9.2 clientId 规则

- 新增表单不展示可编辑的 `clientId` 字段。
- 新增成功后，在结果提示和详情中展示服务端生成的 `clientId`。
- 编辑时以只读形式展示 `clientId`，并提示修改 key 或密钥不会改变它。

### 9.3 授权方式规则

- 使用复选标签，不使用自由文本逗号输入。
- 字典中存在但服务端尚未实现的授权方式显示“需后端支持”提示。
- 至少选择一种授权方式。
- 页面提交 `grantTypeList` 数组，不提交拼接后的 `grantType`。

### 9.4 令牌时间输入

- UI 使用“数值 + 单位”组合控件，提交前统一换算为秒。
- 快捷值：30 分钟、2 小时、1 天、7 天、30 天、永不过期。
- 当活跃超时大于固定超时且二者都不是 `-1` 时给出警告，但不擅自修改值。
- 现阶段显示提示：后端已保存该配置，但认证签发仍可能使用全局时长。

## 10. 详情抽屉

详情展示：

- 客户端 Key、clientId、设备类型和状态。
- 授权方式及每种方式的支持状态。
- 活跃超时和固定超时的原始秒数与可读时长。
- 客户端密钥默认遮罩，点击“显示 10 秒”后短暂可见。
- “复制 clientId”和“复制密钥”分别提供明确按钮；复制密钥触发安全提示。

详情不展示虚构的创建时间、更新时间或操作者，因为当前 `ClientResponse` 不返回这些字段。

## 11. 状态变更

状态变更不使用表格内开关。

停用确认文案必须包含：

- 将阻止该客户端发起新的登录。
- 已建立的会话不会立即失效。
- 恢复为正常后客户端可再次登录。

请求体：

```json
{ "clientId": "...", "status": "1" }
```

启用操作同样确认目标客户端，但无需危险色主按钮。

## 12. 删除

- 单行和批量删除均使用 `DELETE /system/client/{ids}`。
- 批量删除路径使用逗号分隔主键，不使用 clientId。
- 删除为软删除，但页面按不可恢复操作表达，因为没有恢复接口。
- 任一目标已不存在时服务端整批不删，页面保留选择并提示刷新列表后重试。
- 删除后只阻止新登录，不会立即清理现有会话。

## 13. 导出

- 导出使用当前筛选条件，不带分页参数。
- 服务端导出全部命中数据并返回 `客户端管理.xlsx`。
- 导出文件包含明文客户端密钥，点击导出后必须二次确认。
- 确认文案说明文件应按敏感凭据管理，不应通过公开渠道传输。
- 导出请求期间禁用重复提交；文件流成功后提示完成。

## 14. 权限与安全

目标权限点：

| 能力 | 权限点 |
| --- | --- |
| 查看列表 | `system:client:list` |
| 查看详情 | `system:client:query` |
| 新增 | `system:client:add` |
| 修改与状态变更 | `system:client:edit` |
| 删除 | `system:client:remove` |
| 导出 | `system:client:export` |

正式权限模块接入前，页面入口和接口均只对超级管理员开放。前端权限显隐不能替代后端鉴权。

## 15. 状态与反馈

- 初始加载：表格骨架屏，查询控件可操作。
- 空结果：显示“没有符合条件的客户端”，保留重置筛选按钮。
- 首次为空：显示“尚未创建客户端”和新增入口。
- `409`：定位客户端 Key 字段并提示已存在。
- `404`：提示数据已变化，关闭抽屉并刷新列表。
- `422`：映射到具体字段；无法映射时展示请求参数错误摘要。
- 网络错误：保留筛选和表单内容，允许重试。
- 保存成功：关闭抽屉、刷新当前页；新增成功同时提供查看 clientId 入口。

## 16. 接口契约

| 能力 | 方法与路径 | 关键数据 |
| --- | --- | --- |
| 列表 | `GET /system/client/list` | `clientId`、`clientKey`、`status`、分页、排序 |
| 详情 | `GET /system/client/{id}` | 主键 |
| 新增 | `POST /system/client` | `ClientSaveRequest` |
| 修改 | `PUT /system/client` | `ClientUpdateRequest`，包含主键 `id` |
| 状态 | `PUT /system/client/changeStatus` | `clientId`、`status` |
| 删除 | `DELETE /system/client/{ids}` | 逗号分隔主键 |
| 导出 | `POST /system/client/export` | 当前筛选和排序，不含分页 |

列表响应核心结构：

```ts
interface ClientItem {
  id: string | number;
  clientId: string | null;
  clientKey: string | null;
  clientSecret: string | null;
  grantType: string | null;
  grantTypeList: string[];
  deviceType: string | null;
  activeTimeout: number;
  timeout: number;
  status: '0' | '1';
}
```

## 17. 验收标准

1. 可以按 clientId、clientKey、状态查询并正确分页。
2. 新增时不能输入 clientId，成功后显示服务端生成值。
3. 编辑 key 或密钥后，页面不宣称 clientId 会变化。
4. 授权方式至少选择一项，并以数组提交。
5. 列表、详情和表单中的密钥默认不明文展示。
6. 停用和删除前明确说明现有会话不会立即失效。
7. 导出前明确提示文件包含明文密钥。
8. 批量删除部分目标失效时不清空选择，并提示整批未执行。
9. 页面不展示当前响应中不存在的创建时间和更新时间。
10. 原型在桌面与移动宽度下无文本重叠，抽屉、弹窗和表格可操作。

## 18. 已知风险与后续项

- 客户端密钥明文存储和导出属于高风险现状，后续应定义真实认证协议、哈希或加密存储及密钥轮换机制。
- `activeTimeout`、`timeout` 目前可能未参与令牌签发，页面只能如实提示，不能把保存成功等同于策略生效。
- 停用和删除不会踢出现有会话；要实现立即失效，需要会话持久化 clientId 并增加按客户端清理能力。
- `clientId` 目前没有数据库唯一索引，应用层生成规则不能防止直接改库造成重复。
- 权限点尚未接入，正式上线前必须从超级管理员门禁迁移到细粒度权限。
