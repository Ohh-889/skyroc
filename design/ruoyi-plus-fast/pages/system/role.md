## 2. 架构结论

角色是用户与系统资源之间的授权集合，不是岗位、部门或用户标签：

```text
用户与角色多对多关联
  → 角色菜单与按钮权限
  → 角色数据范围
  → 当前用户可访问的路由、操作和业务数据

岗位
  → 描述用户在组织中的任职位置
  ≠ 角色权限
```

页面职责：

- 前端负责角色检索、分页、多选、权限分区、危险变更确认、权限显隐和结果反馈。
- 角色管理用例负责租户隔离、名称与权限字符唯一性、系统角色保护、菜单授权、数据范围授权和事务边界。
- 菜单模块提供当前租户可授权的菜单与按钮树，角色页面不自行拼装资源树。
- 部门模块提供数据范围部门树，角色页面不自行计算组织祖先或下级范围。
- 用户模块维护 `sys_user_role` 关联，负责已分配和未分配用户查询。
- 认证与权限模块负责角色变更后的权限缓存失效和在线会话处理。
- 操作日志记录新增、编辑、授权、停用、成员变更和删除，前端不提交审计字段。

页面采用：

```text
查询区 + 角色分页表格
  + 新增/编辑角色抽屉
  + 功能权限分区
  + 数据范围弹窗
  + 成员管理抽屉
  + 删除确认弹窗
```

角色列表是主工作区。基础信息和菜单权限放在新增/编辑抽屉中；数据范围与成员分配是两个独立任务，不塞进同一个超长表单。保存前提供授权摘要，避免管理员只看见树节点而无法判断实际影响。

## 3. 已知事实与设计假设

### 3.1 RuoYi 前端事实

参考页面已经包含：

- 按角色名称、权限字符、状态和创建时间查询。
- 分页表格展示角色名称、权限字符、显示顺序、状态和创建时间。
- 新增、单选修改、多选删除、导出、状态修改、数据权限和分配用户。
- 新增/编辑字段包括角色名称、权限字符、角色顺序、状态、菜单权限和备注。
- 菜单权限树支持展开/折叠、全选/全不选和父子联动。
- 数据权限支持全部数据、自定义、本部门、本部门及以下、仅本人、部门及以下或本人六种范围。
- 自定义数据范围通过部门树选择，支持父子联动。
- 分配用户跳转至独立页面 `/system/role-auth/user/{roleId}`。
- 超级管理员角色 `roleId = 1` 不显示普通编辑、删除、数据权限和分配用户入口。

本文以这些能力确认业务边界，不复制 Element Plus 的视觉样式、行内开关和多个 500px 居中弹窗。

### 3.2 RuoYi 控制器事实

| 能力           | 方法与路径                                     | 权限                 |
| -------------- | ---------------------------------------------- | -------------------- |
| 角色列表       | `GET /system/role/list`                        | `system:role:list`   |
| 角色详情       | `GET /system/role/{roleId}`                    | `system:role:query`  |
| 新增角色       | `POST /system/role`                            | `system:role:add`    |
| 修改角色       | `PUT /system/role`                             | `system:role:edit`   |
| 修改数据范围   | `PUT /system/role/dataScope`                   | `system:role:edit`   |
| 修改状态       | `PUT /system/role/changeStatus`                | `system:role:edit`   |
| 删除角色       | `DELETE /system/role/{roleIds}`                | `system:role:remove` |
| 导出角色       | `POST /system/role/export`                     | `system:role:export` |
| 角色选项       | `GET /system/role/optionselect`                | `system:role:query`  |
| 已分配用户     | `GET /system/role/authUser/allocatedList`      | `system:role:list`   |
| 未分配用户     | `GET /system/role/authUser/unallocatedList`    | `system:role:list`   |
| 取消单个授权   | `PUT /system/role/authUser/cancel`             | `system:role:edit`   |
| 批量取消授权   | `PUT /system/role/authUser/cancelAll`          | `system:role:edit`   |
| 批量选择用户   | `PUT /system/role/authUser/selectAll`          | `system:role:edit`   |
| 角色部门树回显 | `GET /system/role/deptTree/{roleId}`           | `system:role:list`   |
| 角色菜单树回显 | `GET /system/menu/roleMenuTreeselect/{roleId}` | 菜单查询权限         |

控制器还明确：

- 新增和修改都校验角色名称、权限字符唯一性。
- 修改、状态变更、数据权限和用户授权前校验角色数据范围。
- 系统角色通过 `checkRoleAllowed` 保护，不能按普通角色修改。
- 修改角色后清理该角色的在线用户，使新权限按后端策略生效。
- 写操作使用重复提交保护并记录操作日志。
- 删除支持多个角色 ID；实际是否允许删除需继续由服务检查用户占用和系统角色约束。

### 3.3 当前 FastAPI 事实

当前 `skroc-fast/app/modules/role` 已有：

- 租户隔离且逻辑删除的 `sys_role` 模型。
- `role_name`、`role_key`、`role_sort`、`data_scope`、菜单/部门父子联动、状态和备注字段。
- `sys_role_menu` 与 `sys_role_dept` 关联模型。
- 查询用户有效角色菜单、查询角色菜单回显、检查菜单是否被角色使用和删除菜单绑定的内部服务。
- 菜单模块已提供 `GET /system/menu/roleMenuTreeselect/{roleId}`，返回菜单树和角色勾选项。

当前尚未具备：

- 角色列表、详情、新增、修改、状态、删除、导出和选项 HTTP 接口。
- 角色菜单、部门数据范围和用户成员的完整写入用例。
- `data_scope` 对业务查询的真实过滤逻辑；当前只是模型字段。
- 角色权限缓存失效、在线会话刷新和受影响用户通知策略。
- `system:role:*` 权限门禁和管理员可授权范围校验。

因此 HTML 是交互设计原型，不能描述为已经对接角色 CRUD 或真实授权。

### 3.4 设计假设

- 首期沿用 RuoYi 字段和单数接口路径，不另建一套角色契约。
- 角色名称在当前租户内唯一，权限字符 `roleKey` 在当前租户内唯一。
- `roleKey` 是稳定的程序识别符，创建后默认不可编辑；确需变更时作为高风险操作单独确认。
- 前端使用后端返回的 `superAdmin` 保护标记，不在操作组件中重复写死 `roleId = 1`。
- 管理员只能授予自己拥有且当前租户套餐允许的菜单和按钮权限。
- 新角色不能无提示地默认“全部数据”，必须使用明确且可见的安全默认范围。
- 当前界面不在编辑抽屉重复配置数据范围；新角色使用“仅本人”安全默认值，再通过独立数据范围弹窗调整。
- 状态不使用行内开关；停用会影响多个用户，必须展示影响人数并确认。
- 权限变化的会话生效策略由后端统一处理，前端只展示返回的影响摘要。
- 列表保持 `SysRoleVo` 原始字段，不逐行请求菜单树或成员接口补充汇总数量。

## 4. 页面目标

页面需要让有权限的管理员：

1. 快速看清每个角色的权限字符、数据范围、成员规模、状态和保护属性。
2. 通过名称、权限字符、状态和创建时间定位角色。
3. 查看角色完整详情，不把只读查看和编辑操作混在一起。
4. 创建或修改角色，并分区配置基础信息、菜单权限和按钮权限。
5. 独立配置数据范围，明确“能做什么”和“能看到什么”是两件事。
6. 查看、添加或移除角色成员，不与用户档案编辑混在一起。
7. 在停用、删除和高风险授权前看到受影响用户与阻塞原因。
8. 在并发变化、权限越权、系统角色保护或接口失败时得到可执行反馈。

- 页面使用全部可用宽度，最大内容宽度与菜单、部门管理保持一致。
- 页面内边距 24px；紧凑模式使用 16px。
- 统计概览为紧凑信息条，不使用营销式大卡片或装饰图表。
- 查询区和表格区使用弱边框容器，不叠加强阴影。
- 角色列固定左侧，操作列固定右侧；表格最小宽度 1120px。
- 权限摘要和数据范围都显示文字，不只用颜色、图标或数字表达。

### 6.2 中等宽度

- `992px - 1199px` 隐藏创建时间和排序列。
- 权限摘要合并为“菜单 N / 按钮 N”，成员数保留。
- 低频工具栏操作收进“更多”，行操作保留编辑和授权入口。
- 操作列固定右侧，表格允许横向滚动。

### 6.3 窄屏

- `< 768px` 统计概览改为两列，查询字段单列排列。
- 表格维持最小宽度并横向滚动，不拆成难以横向比较的卡片流。
- 新增/编辑和成员抽屉占满屏幕；权限树与摘要纵向排列。
- 数据范围弹窗占满可用宽度，自定义部门树可独立滚动。
- 危险操作仍需确认，不因窄屏省略影响说明。

## 7. 查询设计

| 条件     | 控件         | 请求字段                    | 规则                                |
| -------- | ------------ | --------------------------- | ----------------------------------- |
| 角色名称 | 文本输入框   | `roleName`                  | 模糊匹配，去首尾空格，最多 30 字符  |
| 权限字符 | 文本输入框   | `roleKey`                   | 模糊匹配，去首尾空格，最多 100 字符 |
| 状态     | 单选下拉框   | `status`                    | 全部、正常 `0`、停用 `1`            |
| 创建时间 | 日期范围选择 | `params[beginTime/endTime]` | 开始时间不得晚于结束时间            |

交互规则：

- 点击查询或在文本输入框按 Enter 执行请求，并将页码重置为 1。
- 修改筛选值不自动请求，避免列表频繁刷新。
- 重置清空条件、日期范围、页码和行选择，重新加载完整列表。
- 查询状态、页码和每页条数写入 URL，返回页面时恢复工作上下文。
- 已生效的低频条件以筛选标签展示，不能在“更多筛选”收起后不可见。
- 无结果时显示“没有找到符合条件的角色”，并提供重置入口。

## 8. 角色概览与表格

### 8.1 概览指标

| 指标           | 口径                                       |
| -------------- | ------------------------------------------ |
| 角色总数       | 当前租户未删除角色数，不受当前列表筛选影响 |
| 停用角色       | 当前租户状态为停用的角色数                 |
| 自定义数据范围 | `dataScope = 2` 的角色数                   |
| 系统保护角色   | 后端返回 `superAdmin = true` 的角色数      |

指标接口失败不阻断角色列表；单个指标显示 `—` 和重试提示，不伪造为 `0`。

### 8.2 列定义

| 列       | 展示规则                                     | 默认显示 |
| -------- | -------------------------------------------- | -------- |
| 选择     | 系统角色不可选择；表头全选只选当前页可操作项 | 是       |
| 角色     | 角色名称和系统保护标记；超长省略并 Tooltip   | 是       |
| 权限字符 | 原始 `roleKey`，使用等宽字体展示             | 是       |
| 数据范围 | 六种范围文字                                 | 是       |
| 排序     | 显示 `roleSort`，按排序值和角色 ID 稳定排序  | 否       |
| 状态     | 正常、停用，使用状态点和文字                 | 是       |
| 创建时间 | `YYYY-MM-DD HH:mm`                           | 是       |
| 操作     | 编辑、权限、数据范围、成员、启停和删除       | 是       |

- 系统角色保留完整可读性，使用“系统内置”标签和锁图标说明保护原因。
- 停用角色不整行置灰；状态、成员和历史授权仍需要可读。
- 功能权限和成员数量不在列表逐行计算，避免菜单树和成员接口形成 N+1 请求。
- 页码切换、刷新和查询后清空选择，避免对不可见旧数据执行批量操作。
- 列表不得为每行单独请求菜单树、部门树或成员列表。

### 8.3 分页与选择

- 使用服务端分页，默认每页 10 条，可切换 20、50、100 条。
- 表头全选只影响当前页且排除系统角色和无权限项。
- 单选时可使用工具栏“编辑”；多选时编辑禁用并显示原因。
- 批量删除仅提交当前已选 ID，不实现跨页隐式全选。

## 9. 工具栏、行操作与权限

| 操作      | 权限                 | 行为与限制                                   |
| --------- | -------------------- | -------------------------------------------- |
| 新增角色  | `system:role:add`    | 打开新增抽屉                                 |
| 编辑角色  | `system:role:edit`   | 系统角色不可编辑；列表单选或行内进入         |
| 功能权限  | `system:role:edit`   | 打开角色抽屉的权限分区                       |
| 数据范围  | `system:role:edit`   | 打开独立弹窗，系统角色不可修改               |
| 成员管理  | `system:role:edit`   | 打开成员抽屉，分别处理已分配和未分配用户     |
| 启用/停用 | `system:role:edit`   | 先请求影响摘要，再确认                       |
| 批量删除  | `system:role:remove` | 至少选择一项；系统角色和已占用角色由后端阻止 |
| 导出      | `system:role:export` | 使用后端审计导出，不用前端 CSV 冒充          |
| 刷新      | 列表查看权限         | 保留查询条件，清空行选择并刷新               |
| 列设置    | 列表查看权限         | 角色、状态和操作列不可隐藏                   |

- 无权限的操作不展示；业务条件不满足的操作展示禁用状态和原因。
- 操作列直接显示“编辑”和“授权”，其他动作进入更多菜单。
- 系统角色不通过隐藏整行回避问题，而是明确显示“受保护”及原因。
- 状态修改不使用行内开关，避免一次误触立即影响所有成员。

### 9.1 角色详情抽屉

“详情”和“编辑”是两个独立任务。点击详情后通过 `GET /system/role/{roleId}` 获取完整信息，以只读抽屉展示：

- 角色 ID、角色名称、权限字符、显示顺序和状态。
- 数据范围、菜单父子联动、部门父子联动。
- 创建时间和备注。
- 通过角色菜单树接口计算的已授权菜单、按钮数量；该计数只在详情打开时请求，不进入列表 VO。
- 系统保护角色的保护说明。

非系统保护角色可从详情底部进入编辑；系统保护角色只显示关闭操作。

## 10. 新增与编辑角色抽屉

抽屉宽度桌面端 `760px`，窄屏占满。使用“基础信息 / 功能权限 / 变更摘要”三个分区，分区导航保持可见。

### 10.1 基础信息

| 字段     | 请求字段   | 必填 | 规则与说明                                      |
| -------- | ---------- | ---- | ----------------------------------------------- |
| 角色名称 | `roleName` | 是   | 最多 30 字符；当前租户内唯一                    |
| 权限字符 | `roleKey`  | 是   | 最多 100 字符；建议小写英文和连字符；租户内唯一 |
| 显示顺序 | `roleSort` | 是   | 大于等于 0 的整数                               |
| 状态     | `status`   | 是   | 正常 `0`、停用 `1`                              |
| 备注     | `remark`   | 否   | 最多 500 字符，显示剩余字数                     |

规则：

- 新增默认状态为正常、显示顺序为 0。
- 权限字符旁明确说明它是程序识别符，不是菜单权限字符串。
- 权限字符允许按 RuoYi 现有契约编辑，但必须提示它可能影响代码判断和外部集成。
- 修改为停用时先展示当前成员数和会话影响，不在普通表单保存中静默停用。
- 打开编辑抽屉前请求详情，不把列表行当作完整详情。
- 数据范围不在编辑抽屉修改，统一使用独立的数据范围弹窗，避免 `dataScope` 与 `deptIds` 分两次产生中间状态。

### 10.2 功能权限

```text
功能权限
├── 左侧：可授权资源树
│   ├── 按菜单或按钮名称搜索
│   ├── 目录、菜单、按钮类型标签
│   ├── 展开 / 收起
│   └── 父子联动设置
└── 右侧：已选摘要
    ├── 菜单 N 项
    ├── 按钮 N 项
    ├── 父子联动状态
    └── 相比保存前新增 / 移除
```

- 资源树只包含当前管理员可授予且租户套餐可用的节点。
- 搜索命中按钮时保留目录和菜单祖先路径。
- 父子联动默认开启；关闭后允许精确勾选，但必须解释父节点与子节点的实际保存语义。
- 半选节点用于视觉表达，提交时按后端契约合并完整选中与半选 ID。
- “全选”属于高风险操作，需要再次确认并显示资源数量。
- 权限被其他管理员并发删除或停用时，保存应返回具体失效节点并保留其他编辑内容。

### 10.3 变更摘要

保存前展示：

- 基础信息变化。
- 新增与移除的菜单、按钮数量，最多列出 5 个关键权限。
- 高风险权限变化，例如角色、用户、菜单、租户和审计管理权限。
- 权限生效可能影响已有成员会话；没有影响预检接口时不展示伪造人数。
- 权限生效策略和操作日志说明。

保存期间禁用重复提交。成功后关闭抽屉、刷新当前页并定位角色；失败时保留表单、树选择和滚动位置。

## 11. 数据范围设计

数据范围使用独立弹窗，标题包含角色名称和权限字符。

| 值  | 范围             | 页面解释                                             |
| --- | ---------------- | ---------------------------------------------------- |
| `1` | 全部数据权限     | 可访问当前租户内全部受数据权限约束的数据             |
| `2` | 自定数据权限     | 仅访问选中部门及后端定义的关联范围                   |
| `3` | 本部门数据权限   | 仅当前用户所属部门                                   |
| `4` | 本部门及以下     | 当前部门及其全部下级部门                             |
| `5` | 仅本人数据权限   | 仅当前用户本人创建、负责或归属的数据，以接口定义为准 |
| `6` | 部门及以下或本人 | 本部门及以下数据与本人数据的并集                     |

交互规则：

- 六种范围使用单选卡片，不只显示抽象数字。
- 选择“自定数据权限”后显示部门树，其他范围不显示部门树并清除待提交 `deptIds`。
- 部门树支持搜索、展开/收起、全选/取消和父子联动。
- 停用部门保留历史可见性但不可新增选择；已授权的失效部门显示警告。
- 从宽范围改为窄范围时展示受影响成员数和访问收缩提示。
- 从窄范围改为“全部数据”属于高风险提升，必须二次确认。
- 保存成功后刷新列表的数据范围摘要，并按后端策略使缓存或会话失效。

## 12. 成员管理设计

成员管理使用右侧抽屉，顶部固定显示角色名称、权限字符、状态和当前成员数。

```text
角色成员
├── 已分配（默认）
│   ├── 用户名 / 姓名 / 手机号查询
│   ├── 部门筛选
│   ├── 当前成员表格
│   └── 单个 / 批量移除
└── 添加成员
    ├── 未分配用户查询
    ├── 当前页多选
    └── 批量加入角色
```

- 已分配和未分配使用后端两个分页接口，不在前端加载全部用户后求差集。
- 添加或移除后只刷新受影响分页和成员计数，不重载整页。
- 不允许管理员移除导致自己失去最后一个管理角色，具体由后端判定。
- 停用角色可查看历史成员，但不允许新增成员。
- 系统角色是否允许成员变更由后端保护标记决定，不写死角色 ID。
- 批量操作失败时返回逐项结果或原子失败策略，页面必须明确采用哪一种。

## 13. 状态变更与删除

### 13.1 停用角色

停用确认展示：

- 角色名称和权限字符。
- 当前成员数与在线用户数。
- 停用后菜单、按钮和数据权限不再生效。
- 会话是立即失效、下次请求刷新还是下次登录生效。

若后端无法提供在线用户数，显示“在线会话影响待后端确认”，不能写成 0。

### 13.2 单个删除

删除确认展示角色名称、权限字符、成员数和系统保护状态：

- 系统角色不允许删除。
- 已分配用户时默认不允许删除，提供“前往成员管理”入口。
- 删除同时清理角色菜单和角色部门绑定，但不得删除菜单、部门或用户本身。
- 删除后不可恢复；需要保留审计记录。

### 13.3 批量删除

- 确认弹窗展示角色数量和前 5 个角色名称。
- 系统角色不可进入选择集合。
- 推荐原子语义：任一角色不存在、越权、被占用或受保护时整批不删除。
- 失败时返回阻塞角色及原因，不只提示“删除失败”。
- 成功后清空选择；当前页为空且不是第 1 页时回退一页。

## 14. 权限与安全边界

- 列表、详情、写操作、导出和成员查询分别校验权限，不能只靠前端隐藏按钮。
- 租户隔离必须覆盖 `sys_role`、`sys_user_role` 的用户关系，以及通过角色 join 的关联表查询。
- `sys_role_menu` 和 `sys_role_dept` 自身没有租户列，所有写入和删除必须先校验角色属于当前租户。
- 管理员不能授予自己没有的菜单和按钮，也不能越过租户套餐可用资源范围。
- 权限字符不能直接拼接成 SQL、路由或动态表达式。
- 系统角色保护必须由后端返回并校验，前端的锁图标只是提示。
- 角色修改、数据范围、成员授权、状态和删除均需记录操作日志。
- 权限变更后的缓存失效与会话策略属于后端安全边界，不能依赖用户重新登录碰运气。

## 15. 状态设计

### 15.1 加载

- 首次加载使用表格骨架屏，保留表头和布局高度。
- 统计、列表和筛选选项独立加载，单块失败不清空其他内容。
- 编辑、数据范围和成员抽屉先显示局部骨架，再渲染详情。

### 15.2 空状态

- 无角色：说明“当前租户还没有可管理角色”，有权限时提供新增入口。
- 查询无结果：展示当前条件摘要和重置入口。
- 权限树为空：区分“无可授权资源”和“资源加载失败”。
- 未分配用户为空：说明当前所有可选用户都已拥有该角色。

### 15.3 错误与并发

- `401`：进入统一登录失效流程。
- `403`：说明缺少的操作权限，不用模糊“请求失败”。
- `404`：角色已被删除，关闭抽屉并刷新列表。
- `409`：名称、权限字符重复，或角色在编辑期间发生变化；定位到字段或显示差异。
- `422`：展示字段级校验错误。
- `5xx` / 网络错误：保留查询、选择和表单内容，提供重试。
- 保存前角色版本已变化时，不静默覆盖；提示刷新详情或查看冲突。

## 16. 可访问性

- 所有输入有可见标签和错误关联，权限字符说明可通过键盘获取。
- 图标按钮必须有可访问名称和 Tooltip，目标区域至少 `32 × 32px`。
- 状态、系统保护和风险级别同时使用文字，不只依赖颜色。
- 抽屉和弹窗使用焦点陷阱；关闭后焦点返回触发按钮。
- `Escape` 关闭最上层浮层；有未保存变更时先确认。
- 权限树支持方向键移动、空格勾选和可读的半选状态。
- 筛选结果、保存成功和错误通过非打断式状态区播报。

## 17. 响应与性能

- 查询条件变化不自动触发请求；点击查询后取消旧请求，防止乱序覆盖。
- 列表使用服务端分页和白名单排序。
- 菜单树、部门树按租户和资源版本缓存，角色保存后按需失效。
- 资源树节点较多时支持搜索和虚拟滚动；不能默认展开整棵大树。
- 成员列表使用服务端分页，不把全租户用户加载到浏览器。
- 批量授权提交 ID 列表，后端统一校验，不逐个发送 N 次写请求。

## 18. 接口建议

### 18.1 列表项

```ts
interface RoleListItem {
  roleId: number;
  roleName: string;
  roleKey: string;
  roleSort: number;
  dataScope: '1' | '2' | '3' | '4' | '5' | '6';
  menuCheckStrictly: boolean;
  deptCheckStrictly: boolean;
  status: '0' | '1';
  remark: string | null;
  createTime: string | null;
  flag: boolean;
  superAdmin: boolean;
}
```

该结构与 `SysRoleVo` 和当前 React `RoleItem` 保持一致。功能权限数量仅在详情打开时通过菜单树计算；成员数量不进入列表，避免 N+1 请求。

### 18.2 影响摘要

状态、权限提升、数据范围扩大和删除前建议提供统一预检：

```text
GET /system/role/{roleId}/impact?action=disable|delete|permission|dataScope
```

返回成员数、在线会话数、阻塞原因、高风险变化和版本号。若不新增接口，则对应写接口失败响应必须包含同等可执行信息。

### 18.3 并发与事务

- 角色基础信息和菜单绑定应在同一事务保存。
- 自定义数据范围和 `sys_role_dept` 应在同一事务保存。
- 新建角色需要同时配置数据范围时，后端应提供原子创建用例，避免“角色已创建但数据范围保存失败”。
- 写请求携带版本号或更新时间，后端拒绝覆盖过期数据。
- 删除角色时软删除角色并清理关联表；用户关联处理策略必须明确。

## 19. 验收标准

### 19.1 视觉与交互

- 页面与菜单、部门、岗位管理使用一致的侧栏、顶栏、间距、色板和表格密度。
- 能完成查询、重置、分页、单选、多选、列设置和刷新。
- 能打开新增/编辑抽屉，并清楚区分基础信息、功能权限和变更摘要。
- 能打开数据范围弹窗，六种范围文字清楚，自定义范围可选择部门。
- 能打开成员管理抽屉，区分已分配和添加成员。
- 系统角色、停用角色和高风险权限都有文字说明。

### 19.2 业务

- 名称和权限字符唯一性由后端校验。
- 系统角色不能被普通编辑、停用或删除。
- 管理员不能授予自己没有或套餐未开放的权限。
- 权限、数据范围和成员写入均具备租户隔离、事务和操作日志。
- 角色变化后权限缓存和在线会话按明确策略更新。
- 删除、停用和权限提升前展示真实影响；接口失败不伪造成功。

### 19.3 可访问性与响应式

- 仅使用键盘可以完成查询、打开抽屉、选择权限和关闭弹窗。
- 状态和风险不只通过颜色表达。
- 桌面、中等宽度和窄屏下主操作可用，浮层不溢出视口。
- `200%` 缩放下无关键操作丢失。

## 20. 实施边界

本次交付：

- 角色管理页面规格。
- 可直接打开的独立 HTML 交互原型。
- React 角色列表、详情、编辑、数据范围和成员管理界面。

不包含：

- FastAPI 角色 CRUD、授权、数据范围与成员接口实现。
- 权限缓存、在线会话失效、导出和操作日志对接。
- 修改现有信息架构与页面注册表中的复数路径。

后续实现时必须先补齐真实接口和安全边界，再把原型交互接入服务端；不能把原型中的本地反馈描述为授权成功。
