# Skyroc Admin Design System

## 1. 文档信息

- 适用产品：Skyroc Admin
- 适用应用：`apps/ruoyi-plus-fast`
- 当前终端：Web 管理后台
- 版本：0.1
- 日期：2026-07-28
- 状态：初版

本文定义 Skyroc Admin 的基础视觉语言和 Web 页面设计约束。页面规格和设计稿应优先使用本文定义的语义，而不是直接复制某个组件运行时生成的颜色值。

## 2. 实现来源

设计与代码按以下层级对应：

| 层级            | 当前实现                                            | 职责                         |
| --------------- | --------------------------------------------------- | ---------------------------- |
| 基础令牌        | `@skyroc/ui-tokens`                                 | 颜色、间距、圆角、字号和字重 |
| 颜色算法        | `@skyroc/color`                                     | 色板生成和颜色处理           |
| Ant Design 映射 | `@skyroc/adapter-antd-theme`、`@skyroc/antd-theme`  | 将主题设置映射为组件令牌     |
| 后台主题        | `@skyroc/web-admin-theme`                           | 明暗模式、主题预设和布局尺寸 |
| UI 组件         | `@skyroc/web-ui`、`@skyroc/web-ui-antd`、Ant Design | 页面实际组件                 |

实施规则：

1. 不在业务页面中直接创建新的全局颜色体系。
2. 优先使用语义 Token，不直接使用 `primary-6` 等色阶名称表达业务含义。
3. 主题切换通过现有主题设置完成。
4. 设计稿中的组件状态需要映射到现有组件 Token。
5. 本文与运行时变量不一致时，先确认是设计变更还是实现漂移，不在页面中局部覆盖。

## 3. 设计原则

### 3.1 专业

使用清晰、准确的层级和反馈。管理页面不使用过度娱乐化的插图、文案和动画。

### 3.2 克制

颜色主要用于操作、状态和信息层级。一个页面不应同时出现多个竞争注意力的高饱和主色。

### 3.3 高效

高频操作保持紧凑，筛选、表格和批量操作优先考虑连续工作效率。

### 3.4 可信赖

删除、停用、权限变更和系统配置等高风险操作必须说明影响，并提供明确结果。

### 3.5 一致

相同任务使用相同页面模式、组件状态和反馈方式，但不强迫所有业务页面采用完全相同的信息密度。

## 4. 色彩

### 4.1 核心语义色

| 语义    | 默认颜色     | 用途                         |
| ------- | ------------ | ---------------------------- |
| Primary | `#6366F1`    | 主要操作、选中状态、品牌强调 |
| Info    | `#0EA5E9`    | 中性信息、说明和进行中状态   |
| Success | `#10B981`    | 成功、启用、正常             |
| Warning | `#F59E0B`    | 警告、待处理和需要关注       |
| Error   | `#F43F5E`    | 错误、失败和危险操作         |
| Link    | 跟随 Primary | 文本链接和可导航文本         |

使用限制：

- Success、Warning 和 Error 只表达对应状态，不作为装饰色。
- 删除、停用等危险操作使用 Error。
- Primary 不替代状态色。
- 状态不能只依赖颜色，还需要图标、文字或形状。
- 同一区域中最多保留一个主要操作。

## 6. 字体与排版

### 6.1 字体

```text
-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
"Helvetica Neue", Arial, "Noto Sans", sans-serif,
"Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol",
"Noto Color Emoji"
```

代码字体：

```text
"SFMono-Regular", Consolas, "Liberation Mono", Menlo,
Courier, monospace
```

### 6.2 基础字号

- 默认字号：14px。
- 默认行高：1.5，基础文本约 21px。
- 强调字重：600。
- 正文字重：400。

### 6.3 产品文字层级

| 角色          | 字号 | 建议行高 | 字重 | 用途                         |
| ------------- | ---- | -------- | ---- | ---------------------------- |
| Caption       | 12px | 16px     | 400  | 辅助说明、时间、表格次要信息 |
| Body          | 14px | 21px     | 400  | 默认正文、表格、表单         |
| Body Strong   | 14px | 21px     | 600  | 重要字段和局部强调           |
| Large Body    | 16px | 24px     | 400  | 引导说明和重点内容           |
| Section Title | 18px | 25px     | 600  | 卡片和页面区块标题           |
| Page Title    | 26px | 33px     | 600  | 页面主标题                   |
| Display Small | 32px | 39px     | 600  | 登录页或关键数据             |
| Display       | 42px | 49px     | 600  | 少量品牌场景                 |

后台业务页面通常不使用 42px 以上字号。更大的运行时字号只作为底层能力，不作为常规页面规范。

### 6.4 文本规则

- 页面只能有一个主标题。
- 表单标签使用 14px，不使用全大写英文。
- 表格主要内容使用 14px，辅助内容使用 12px。
- 链接需要通过颜色、Hover 或下划线等方式保持可识别。
- 数字指标需要统一小数位、千分位和单位。
- 禁用文本仍需满足基本可读性，不能只降低到不可辨识的透明度。

## 7. 间距

### 7.1 基础单位

- 基础单位：4px。
- 所有常规间距优先使用 4px 的倍数。

### 7.2 间距等级

| Token | 数值 | 常见用途                 |
| ----- | ---- | ------------------------ |
| 0.5   | 2px  | 极小视觉修正，谨慎使用   |
| 1     | 4px  | 图标内部、紧密元素       |
| 2     | 8px  | 图标与文字、紧凑控件     |
| 3     | 12px | 表单项内部、列表紧凑间距 |
| 4     | 16px | 默认内容间距             |
| 5     | 20px | 中等区块                 |
| 6     | 24px | 卡片内边距、区块间距     |
| 7     | 28px | 特殊排版                 |
| 8     | 32px | 大区块分隔               |
| 10    | 40px | 页面头部和大区块         |
| 12    | 48px | 大范围结构间距           |
| 16    | 64px | 品牌页和空状态           |

常用业务页面间距：

```text
8 / 12 / 16 / 20 / 24 / 32
```

### 7.3 页面间距

- 默认页面内边距：24px。
- 紧凑页面：16px。
- 卡片默认内边距：16px 或 24px。
- 页面标题与内容：16px。
- 主要区块之间：24px。
- 表单项垂直间距：16px。
- 查询条件之间：12px 或 16px。

## 8. 圆角

### 8.1 圆角等级

| 等级    | 数值   | 用途                   |
| ------- | ------ | ---------------------- |
| XS      | 2px    | 小型标签、内部细节     |

| Default | 6px    | 按钮、输入框、选择器   |
| LG      | 8px    | 卡片、弹窗、下拉浮层   |
| XL      | 12px   | 大型品牌卡片和特殊容器 |
| 2XL     | 24px   | 非后台常规场景         |
| Full    | 9999px | 胶囊标签、圆形操作     |

### 8.2 组件圆角

| 组件       | 默认圆角          |
| ---------- | ----------------- |
| 输入框     | 6px               |
| 按钮       | 6px               |
| 大号输入框 | 8px               |
| 大号按钮   | 8px               |
| 选择器     | 6px               |
| 表格外容器 | 8px               |
| 普通卡片   | 8px               |
| 弹窗       | 8px               |
| 抽屉       | 0，按进入方向贴边 |
| 标签       | 4px 或 Full       |
| 登录卡片   | 8px               |

同一容器内的子元素圆角不得大于外层容器圆角。

## 9. 控件尺寸

| 尺寸    | 高度 | 适用场景                           |
| ------- | ---- | ---------------------------------- |
| XS      | 16px | 仅底层特殊场景，不作为常规输入控件 |
| Small   | 24px | 紧凑表格内的小型操作               |
| Default | 32px | 默认后台表单和工具栏               |
| Large   | 40px | 登录、关键表单和主操作             |

规则：

- 同一操作区优先使用相同高度。
- 登录页输入框和主按钮使用 40px 高度与 8px 圆角。
- 常规查询表单使用 32px。
- 不使用 24px 输入框承载复杂文本输入。
- 图标点击目标应保证可操作性，不等同于视觉图标尺寸。

## 10. 边框与分隔

- 默认边框：1px Solid。
- 默认控件边框：`#C6C6C8`。
- 弱分隔线：`#F0F0F0`。
- 聚焦状态使用 Primary 外轮廓，不只改变边框颜色。
- 卡片优先使用背景、弱边框或轻阴影之一，不同时强化三种层级。
- 表格行主要使用弱分隔线，不使用过深网格。

| -------- | ---------------------------------------------------------------------------------------------------------- | ------------------- |

| Elevated | `0 6px 16px 0 rgba(0, 0, 0, 0.08), 0 3px 6px -4px rgba(0, 0, 0, 0.12), 0 9px 28px 8px rgba(0, 0, 0, 0.05)` | 下拉、Popover、弹窗 |
| Header   | `0 1px 2px rgb(0, 21, 41, 0.08)`                                                                           | 固定顶栏            |
| Sider    | `2px 0 8px rgb(29, 35, 41, 0.05)`                                                                          | 侧边栏              |
| Tab      | `0 1px 2px rgb(0, 21, 41, 0.08)`                                                                           | 页签栏              |

阴影不用于表达选中、错误或成功状态。

### 12.4 页面宽度类型

| 页面类型           | 宽度规则                   |
| ------------------ | -------------------------- |
| 数据列表和权限配置 | 使用可用宽度               |
| 工作台             | 最大 1440px，居中          |
| 详情页             | 建议 1200px 内             |
| 单列表单           | 建议 720px 至 960px        |
| 登录卡片           | 桌面约 400px，窄屏约 300px |
| 错误和空状态       | 居中，限制正文宽度         |

### 12.5 响应式原则

- `>= 1200px`：完整侧边栏和桌面布局。
- `992px - 1199px`：允许自动收起侧边栏，减少页面边距。
- `768px - 991px`：采用紧凑布局，筛选区域允许折叠。
- `< 768px`：只保证登录、异常页和明确声明支持的轻量页面；复杂表格不承诺完整移动体验。

当前产品不将“Web”自动等同于完整手机端后台。

### 13.2 Dark

- 深色表面。
- 保留品牌和状态语义。
- 适合夜间和低照度环境。
- 所有页面上线前需要单独检查对比度、图表和插图。

### 13.3 Shadcn

- Primary：`#18181B`。
- 背景以中性灰为主。
- 圆角：8px。
- 侧边栏：240px。
- 适合更克制、中性的视觉方向。

### 13.4 Azir

- Primary：`#78A878`。
- 使用冷静、低饱和绿色方向。
- Info：`#89B989`。
- Success：`#99C299`。
- Warning：`#D4BB9D`。
- Error：`#C49A9A`。

该预设会弱化反馈色区分，使用前需要验证状态辨识度和无障碍对比度。

### 13.5 Compact

- 只调整布局密度。
- 继承当前颜色主题。
- 侧边栏 180px、顶栏 48px、页签 36px。
- 隐藏页脚和部分顶部功能。

Compact 是密度变体，不是独立品牌主题。

## 14. 动效

| 等级   | 时长  | 用途                          |
| ------ | ----- | ----------------------------- |
| Fast   | 100ms | Hover、Pressed 和小型状态变化 |
| Medium | 200ms | 下拉、Popover、折叠           |
| Slow   | 300ms | 弹窗、抽屉和页面区域切换      |

规则：

- 动效服务于状态变化和空间关系，不用于持续吸引注意力。
- 页面切换默认使用轻量 Fade Slide。
- 登录表单切换可以使用位移、透明度和轻微模糊。
- 加载状态避免大面积持续动画。
- 应为减少动态效果偏好保留降级方案。

## 15. 图标

- 菜单和通用操作优先使用 Iconify 图标。
- 同一页面保持一致的线性或填充风格。
- 图标不能替代所有文字，陌生操作需要文字标签或 Tooltip。
- 状态图标必须与状态文字同时出现。
- 常规操作图标建议 16px。
- 菜单图标建议 18px 至 20px。
- 空状态和异常页插图属于插图系统，不作为普通功能图标使用。

## 16. 常用组件规则

### 16.1 按钮

- 一个操作区最多一个 Primary 按钮。
- 次要操作使用 Default 或 Text。
- 删除和不可逆操作使用 Danger。
- 提交中显示 Loading 并阻止重复提交。
- 只有图标的按钮需要 Tooltip 和可访问名称。

### 16.2 表单

- 标签、控件和帮助信息保持稳定对齐。
- 必填标记不代替字段说明。
- 校验错误显示在对应字段附近。
- 提交失败后保留用户输入。
- 长表单按业务含义分组，不按数据库字段分组。

### 16.3 表格

- 表头使用清晰、简短的业务名称。
- 第一列通常承担对象识别。
- 状态列使用文字和状态标识。
- 单行操作不超过三个；更多操作进入下拉菜单。
- 加载时尽量保留已有数据，避免整个页面闪烁。
- 区分首次空数据和筛选无结果。

### 16.4 卡片

- 卡片用于表达明确的信息组，不用于给每个小区域增加边框。
- 同级卡片保持相同内边距。
- 工作台卡片优先使用 16px 或 24px 内边距。
- 不在一张卡片中混合过多不相关指标。

### 16.5 弹窗和抽屉

- 简短确认和小型表单使用弹窗。
- 需要上下文对照的复杂编辑可以使用抽屉。
- 长流程和独立任务使用页面。
- 危险操作弹窗必须写明对象和影响。
- 关闭前检查未保存更改。

## 17. 状态规范

每个页面至少考虑：

- 首次加载。
- 局部刷新。
- 首次空数据。
- 筛选无结果。
- 请求失败。
- 无权限。
- 对象不存在。
- 提交中。
- 提交成功。
- 提交失败。
- 部分成功。

状态反馈优先级：

```text
字段错误 → 表单内提示
局部操作结果 → Message
需要持续关注的结果 → Notification
阻塞操作或高风险确认 → Modal
整页不可用 → 页面级状态
```

## 18. 无障碍

- 正文和背景对比度至少满足 WCAG AA 的常规文本要求。
- 焦点状态必须清晰可见。
- 所有功能可通过键盘完成核心操作。
- 图标按钮具有可访问名称。
- 表单错误与对应字段建立关联。
- 不只使用红绿区分成功和失败。
- 弹窗打开后管理焦点，关闭后返回触发元素。
- 深色、灰度和色弱模式下仍需保证状态可识别。

## 19. App 布局

当前产品范围只包含 Web 管理后台，暂不在本文中定义 App 布局。

如果后续增加 App，应单独建立移动端规范，至少定义：

- 安全区。
- 页面左右间距。
- 导航栏和底部导航。
- 触控目标尺寸。
- 列表和卡片密度。
- 键盘与表单。
- iOS 和 Android 差异。
- Web 与 App 共享的语义 Token。

不得将 Web 页面机械缩小为 App 页面。
