# Skyroc Admin 设计决策记录

## 1. 目的

本目录用于记录会长期影响产品、设计或实现的重要决定，避免只在聊天记录中保留结论。

普通页面细节不需要创建决策记录。只有存在多个合理方案、选择会影响多个模块，或者未来容易反复讨论时才记录。

## 2. 需要记录的事项

适合创建决策记录：

- 正式采用静态还是动态路由。
- 是否保留多页签。
- 首期是否完整支持暗色主题。
- 业务页面优先使用哪套 UI 组件。
- 新增编辑使用页面、抽屉还是弹窗的全局规则。
- 角色权限和数据范围采用什么交互模型。
- 最低支持屏幕宽度。
- 登录是否使用验证码或多因素认证。

不需要创建决策记录：

- 单个按钮文案。
- 单个页面的普通字段顺序。
- 不影响其他页面的局部间距。
- 已由现有设计系统明确规定的组件样式。

## 3. 文件命名

```text
001-use-dynamic-routes.md
002-keep-multi-tabs.md
003-business-ui-component-boundary.md
```

编号按创建顺序递增，标题使用简短英文短语。

## 4. 状态

| 状态   | 含义                 |
| ------ | -------------------- |
| 提议   | 正在讨论，尚未生效   |
| 已确认 | 已作为后续工作的约束 |
| 已废弃 | 不再适用             |
| 已取代 | 被新的决策记录替代   |

## 5. 模板

```md
# ADR-001 决策标题

## 状态

提议

## 日期

YYYY-MM-DD

## 背景

需要解决的问题、当前限制和相关事实。

## 候选方案

### 方案 A

- 优点：
- 缺点：

### 方案 B

- 优点：
- 缺点：

## 决定

最终选择的方案。

## 原因

为什么该方案更适合当前产品和技术条件。

## 影响

- 对产品范围的影响。
- 对页面设计的影响。
- 对代码实现的影响。
- 对后续迁移的影响。

## 关联内容

- 关联文档。
- 关联页面。
- 关联代码。
```

## 6. 维护规则

1. 已确认记录不直接重写结论。
2. 结论变化时新增记录，并将旧记录标记为“已取代”。
3. 页面规格引用决策记录，不重复复制完整背景。
4. 决策确认后同步更新受影响的范围、信息架构和页面注册表。
