# HTML 原型规范

HTML 原型是能独立查看和操作的设计稿，不是生产页面，也不是只有一张静态截图的布局。

## 页面独立性

- 每个真实页面必须有独立目录和 `index.html`。
- 用户要求多个页面时，每个文件直接打开都应呈现完整页面壳层。
- 不使用 Tab、查询参数或隐藏区块冒充独立页面。
- 页面间需要互通时使用相对链接，并保证离线静态服务下可访问。

## 产品一致性

优先使用 `design/ruoyi-plus-fast/design-system.md` 的语义：

- 页面背景、容器、边框、文字、主色和反馈色使用 CSS 变量。
- 默认字号、间距、圆角、表格密度和抽屉尺寸与相邻原型协调。
- 同一页面最多保留一个主要操作。
- 删除、停用和配置变更必须说明影响。
- 图标优先使用内联 SVG，不依赖图标字体或外部 CDN。

不要因为通用模板而牺牲业务辨识度。树形资源、文件预览、密钥配置、日志时间线等任务可以采用不同主工作区。

## 页面结构

完整管理页面通常包括：

1. 侧边栏和品牌区。
2. 顶部工具栏和已打开页签。
3. 页面标题、说明和上下文。
4. 可选的概览指标。
5. 查询区。
6. 表格、树、卡片或其他主工作区。
7. 分页或加载更多。
8. 新增/编辑/详情抽屉。
9. 危险操作确认弹窗。
10. 成功、警告和错误反馈。

只保留业务真正需要的部分，不为了齐全而堆组件。

## 交互要求

以下可见控件必须有合理反馈：

- 查询和重置改变列表或条件摘要。
- 新增、编辑和详情打开对应浮层。
- 浮层的关闭按钮、遮罩和 Escape 行为一致。
- 保存执行基础校验并反馈结果。
- 删除、停用等危险操作先确认，再更新演示状态。
- 刷新、复制、列设置、展开筛选等按钮不能无响应。
- 页面间导航指向真实存在的相对路径。

原型数据可以在内存中变化，但应明确“原型不会提交真实数据”。

## 响应式要求

至少设计三个宽度：

| 场景 | 建议宽度 | 重点                                   |
| ---- | -------- | -------------------------------------- |
| 桌面 | 1440px   | 完整信息密度和主要工作流               |
| 窄屏 | 1024px   | 侧栏、筛选和表格压缩策略               |
| 手机 | 390px    | 单列、全屏抽屉、触控尺寸和无页面级溢出 |

手机端允许主表格区域内部横向滚动，但页面本身不能出现不可控横向溢出。高频操作保留，低频操作收进更多菜单。

## 可访问性基线

- 根元素包含 `lang="zh-CN"`、字符集和 viewport。
- 所有按钮显式声明 `type="button"` 或 `type="submit"`。
- 纯图标按钮有 `aria-label`。
- 当前导航使用 `aria-current="page"`。
- 抽屉和弹窗使用 `role="dialog"` 或 `alertdialog`、`aria-modal` 和可访问标题。
- Toast 使用 `role="status"` 或 `aria-live`。
- 键盘焦点可见。
- 状态不能只用颜色表达。
- 动画尊重 `prefers-reduced-motion`。

## 技术边界

- 默认使用原生 HTML、CSS 和 JavaScript，确保单文件可查看。
- 不调用真实写接口，不嵌入真实 Token 或密钥。
- 可以使用当前仓库已有本地资产；避免外部网络依赖。
- 原型中的字段、状态和提示语必须与 PRD 对齐。
- HTML 不是 React 生产实现，不要声称已完成接口接入。
