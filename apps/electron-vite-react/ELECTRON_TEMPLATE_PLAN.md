# Electron 桌面应用模板功能规划

## 1. 模板定位

该模板不是把 Web 后台直接装进 Electron，而是提供一个适合继续开发真实桌面产品的基础工程。模板重点解决以下问题：

- React 渲染进程与 Electron 主进程的安全通信。
- 桌面应用常见的窗口、文件、通知、快捷键和更新能力。
- 登录模式与纯本地模式并存。
- 清晰的路由、页面壳层、设置体系和错误处理。
- 可直接复用的测试、打包和发布流程。

默认示例产品定义为“桌面工作台”：用户可以登录同步数据，也可以完全离线地管理本地工作区和后台任务。实际项目可以保留基础设施，替换业务页面。

## 3. 页面与功能板块

### 3.1 应用启动与身份认证

#### 登录页 `/login`

用于需要云端账号、跨设备同步或团队协作的产品。

- 账号与密码登录。
- 记住账号。
- 忘记密码入口。
- 登录失败、网络异常和服务不可用提示。
- 无需登录进入本地模式。
- 后续可扩展手机号、验证码、扫码或第三方登录，但不作为模板首版必需能力。

#### 启动恢复

- 读取本地会话和用户偏好。
- 恢复上次打开的工作区与窗口大小。
- 会话有效时直接进入工作台。
- 无网络但存在本地数据时允许离线进入。
- 启动失败时展示可恢复的错误页，而不是白屏。

### 3.2 桌面应用主框架

所有业务页面使用统一的桌面应用壳层：

- 顶部标题栏：应用名称、当前工作区、窗口操作区。
- 左侧导航：工作台、文件、任务、通知、设置。
- 主内容区：承载当前路由页面。
- 状态区：网络状态、同步状态、后台任务和版本更新提示。
- 全局命令面板：搜索页面、文件和常用操作。
- 响应式收缩：小窗口下折叠侧边栏，保证最低可用尺寸。

如果采用无边框窗口，需要为 macOS、Windows 分别处理拖拽区域、红绿灯按钮和窗口控制按钮；首版可继续使用系统原生标题栏以降低复杂度。

### 3.3 工作台 `/workspace`

工作台用于展示模板的整体能力，而不是堆放无关统计卡片。

- 最近工作区。
- 最近打开的文件。
- 正在运行或最近完成的后台任务。
- 同步与网络状态。
- 应用版本和可用更新提示。
- 创建工作区、打开目录、导入文件等快捷操作。
- 新用户空状态与示例数据切换。

### 3.4 工作区与文件 `/workspace/files`

用于展示 Electron 最核心的本地文件能力。

- 选择并打开本地目录。
- 最近目录列表。
- 文件树、搜索、刷新和基础预览。
- 新建、重命名、移动和删除文件前的确认。
- 在系统文件管理器中显示文件。
- 使用系统默认应用打开文件。
- 拖拽文件进入应用。
- 文件访问失败、路径失效和权限不足提示。

模板只提供安全、通用的文件操作，不预设编辑器、网盘或媒体管理等具体业务。

### 3.5 任务中心 `/tasks`

用于承载下载、上传、导入、导出、扫描和同步等后台任务。

- 进行中、已完成、失败三个视图。
- 任务进度、速度、剩余时间和状态说明。
- 暂停、继续、取消、重试和清理记录。
- 应用退出前提示仍在运行的任务。
- 任务完成后发送桌面通知。
- 关闭窗口后可按产品配置继续在后台运行。

自动更新下载也应复用统一的进度交互，但更新状态与普通业务任务保持独立。

### 3.6 通知中心 `/notifications`

- 系统通知和应用内通知统一记录。
- 未读数量、全部已读和清空。
- 点击通知跳转到相关页面或任务。
- 更新完成、任务失败、同步冲突等重要事件分级展示。
- 允许用户在设置中关闭非关键通知。

### 3.7 原生能力示例 `/examples`

该页面用于向模板使用者演示能力，正式产品可以整页删除。

- 系统文件选择与保存对话框。
- 剪贴板读写。
- 打开外部链接。
- 桌面通知。
- 系统信息与应用版本读取。
- IPC 请求、响应和主进程主动推送。
- 新窗口或辅助窗口。
- 全局快捷键和应用内快捷键。
- 自定义协议链接唤起应用。

每个示例需要同时说明平台支持情况和所需权限，避免让演示代码直接演变成不安全的生产接口。

### 3.8 设置 `/settings`

设置页按职责拆分，不使用一个超长表单。

#### 通用

- 开机启动。
- 关闭主窗口时退出或最小化到托盘。
- 默认工作区和下载目录。
- 启动时恢复上次页面。

#### 外观

- 浅色、深色、跟随系统。
- 主题色。
- 字体大小或界面缩放。
- 减少动画。

#### 语言

- 界面语言切换。
- 日期、时间和数字格式跟随语言环境。

#### 快捷键

- 展示默认快捷键。
- 修改可配置快捷键。
- 检测快捷键冲突。
- 恢复默认值。

#### 通知与后台

- 任务完成通知。
- 更新通知。
- 后台运行策略。
- 托盘行为。

#### 数据与隐私

- 查看数据存储位置。
- 清理缓存和日志。
- 导入、导出用户配置。
- 退出登录并清理云端会话。
- 删除本地数据前二次确认。

### 3.9 关于与更新 `/settings/about`

- 应用名称、图标、当前版本和构建信息。
- 检查更新。
- 更新说明、下载进度、取消下载和重启安装。
- 官网、文档、问题反馈和开源许可证入口。
- 复制诊断信息，但不包含 Token、密码或个人文件内容。

### 3.10 错误与恢复页面

- `404`：路由不存在，提供返回工作台入口。
- `403`：当前账号或本地权限不足。
- `500`：渲染进程页面异常，可重试或重启应用。
- 离线状态：说明哪些功能仍然可用。
- 工作区丢失：允许重新定位目录或移除失效记录。
- 崩溃恢复：重新打开上次工作区，并避免反复进入导致崩溃的页面。

## 4. Electron 原生能力

### 4.1 窗口与生命周期

- 单实例运行，第二次启动时聚焦已有窗口。
- macOS 点击 Dock 图标后重新创建窗口。
- 保存并恢复窗口尺寸、位置和最大化状态。
- 主窗口、设置窗口和辅助窗口的统一创建方法。
- 新窗口默认禁止任意网页弹出。
- 外部 HTTPS 链接交给系统浏览器处理。
- 退出、隐藏到托盘和后台任务之间有明确策略。

### 4.2 系统集成

- 系统托盘和托盘菜单。
- 原生应用菜单。
- 文件打开与保存对话框。
- 系统通知。
- 剪贴板。
- 应用内及全局快捷键。
- 自定义协议和文件关联。
- 开机启动。
- 网络在线状态与电源状态变化。

功能必须按 macOS、Windows、Linux 分别标注支持情况，不能假设三个平台行为完全一致。

### 4.3 数据与持久化

按敏感程度区分存储位置：

- 普通偏好：主题、语言、窗口状态、最近工作区。
- 业务缓存：任务记录、离线数据、文件索引。
- 敏感信息：Token、刷新凭据等交给系统安全存储，不写入普通 JSON 或 localStorage。
- 日志：按日期滚动，限制大小，允许用户清理。

配置需要包含版本号与迁移策略，应用升级后不能因为字段变化导致无法启动。

### 4.4 自动更新

- 启动后延迟检查，不阻塞首屏。
- 用户可以手动检查更新。
- 展示新版本号和更新说明。
- 手动开始、取消和重试下载。
- 下载完成后选择立即重启或稍后安装。
- 开发环境明确提示自动更新只在打包应用中可用。
- 更新失败不影响当前版本继续使用。

## 5. 路由与页面结构

渲染进程继续使用 TanStack Router 的文件路由和 Hash History。Electron 没有专用页面路由框架，Hash 模式能够保证打包后通过 `file://` 打开页面时刷新和深层路由正常工作。

建议目录：

```text
src/pages/
├── __root.tsx
├── index.tsx
├── loading.tsx
├── error.tsx
├── not-found.tsx
├── (auth)/
│   ├── layout.tsx
│   └── login.tsx
└── (app)/
    ├── layout.tsx
    ├── workspace/
    │   ├── index.tsx
    │   └── files.tsx
    ├── tasks.tsx
    ├── notifications.tsx
    ├── examples.tsx
    └── settings/
        ├── index.tsx
        └── about.tsx
```

路由职责：

- `(auth)` 只承载未登录或会话失效页面。
- `(app)` 提供统一桌面壳层和会话检查。
- 页面负责布局与交互编排，业务逻辑放入对应 `features`。
- 主进程不感知前端业务路由，只负责窗口和系统能力。

## 6. IPC 与安全边界

正式模板不应把完整的 `ipcRenderer` 暴露给页面。推荐按能力暴露类型明确的 API：

```text
window.desktop.app.getInfo()
window.desktop.dialog.openDirectory()
window.desktop.file.readText(path)
window.desktop.notification.show(options)
window.desktop.update.check()
window.desktop.window.minimize()
```

必须遵守以下约束：

- 保持 `contextIsolation: true`。
- 默认关闭 `nodeIntegration`。
- preload 只暴露白名单方法，不暴露任意频道的 `send`、`invoke`、`on`。
- 主进程校验每个 IPC 参数、文件路径和 URL。
- 监听事件的方法返回取消订阅函数，避免页面重复绑定。
- IPC 请求和返回类型由主进程、preload、渲染进程共享。
- 禁止加载不可信远程页面；确有需要时使用隔离窗口和严格权限策略。
- 日志和错误上报自动移除凭据、用户文件内容等敏感信息。

现有 `open-win` 示例启用了不安全的 `nodeIntegration` 和关闭上下文隔离，只能作为待替换的示例，不能作为生产实现保留。

## 7. UI 组件与设计原则

- 基础组件优先使用仓库内的 `@skyroc/web-ui`，保持模板品牌和设计系统统一。
- 复杂数据表格、日期范围等业务组件只有在明确需要时再引入 Ant Design，避免模板默认同时维护两套视觉体系。
- 交互密度按照桌面应用设计，不直接复制移动端大间距布局。
- 导航、表单、空状态、错误状态和反馈提示保持统一。
- 键盘可以完成核心操作，并提供清晰的焦点样式。
- 支持浅色、深色、系统主题以及高对比度可读性。
- 小窗口下功能仍可使用，不以隐藏关键操作换取视觉完整。

## 8. 工程基础设施

### 开发体验

- 主进程、preload、渲染进程分别进行 TypeScript 检查。
- 开发环境支持热更新、F12 和右键打开开发者工具。
- 环境变量区分公开渲染变量与仅主进程可见变量。
- 提供明确的 IPC 类型和新增原生能力示例。

### 测试

- Vitest 覆盖纯函数、状态逻辑和关键组件行为。
- Playwright Electron 覆盖启动、路由、登录、本地模式和核心 IPC。
- E2E 使用独立 `userData`，避免污染用户真实配置。
- 文件操作测试使用临时目录，完成后清理。
- 更新流程至少验证“无更新、发现更新、下载失败、下载完成”四类状态。

### 打包与发布

- 使用 electron-builder 生成平台安装包。
- 分别维护 macOS、Windows、Linux 图标与构建配置。
- 生产发布需要代码签名；macOS 还需要公证。
- CI 构建产物、校验文件和更新元数据。
- 发布前执行类型检查、单元测试、E2E 和打包冒烟测试。
- 版本号、更新渠道和回滚策略必须明确。

## 10. 模板首版不包含的内容

以下能力不适合作为通用模板的默认负担：

- 完整后台管理系统、权限菜单和大型数据表格体系。
- 强绑定某个服务端的登录接口和业务数据结构。
- 内置聊天、音视频、地图或 AI 等垂直业务。
- 默认启用多窗口、插件市场和复杂进程管理。
- 为展示技术而引入多套状态管理、请求库或 UI 组件库。

这些能力可以作为独立示例或可选模块添加，但不进入模板最小核心。

## 11. 总体验收清单

- [ ] 全新克隆后能够使用仓库标准命令安装、开发、测试和打包。
- [ ] 开发与生产环境均能从任意 Hash 路由正确启动。
- [ ] 用户可以登录，也可以在没有网络和账号的情况下使用本地模式。
- [ ] 所有原生能力通过类型安全的 preload 白名单访问。
- [ ] 普通渲染页面无法直接调用 Node.js 或任意 IPC 频道。
- [ ] 窗口、主题、语言和常用目录能够安全持久化。
- [ ] 文件访问失败、网络中断、任务失败和更新失败都有明确恢复路径。
- [ ] 自动更新不阻塞应用启动，失败后不影响现有版本使用。
- [ ] macOS、Windows、Linux 的差异有说明并经过目标平台验证。
- [ ] 单元测试、Electron E2E、类型检查和打包检查全部通过。
