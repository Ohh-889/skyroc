# PRD 产物规范

PRD 是实现依据，不是页面截图说明。内容应让产品、设计、前端和后端能够对齐同一个范围。

## 必要章节

### 1. 文档信息

包含页面族、页面 ID、页面名称、路由、终端、优先级、状态、日期和关联资料。

### 2. 架构结论

用简洁文字或文本图说明：

- 模块在系统中的位置。
- 前端、后端、基础设施和相邻模块的职责边界。
- 为什么拆成当前这些页面。

### 3. 已知事实与设计假设

必须分开写：

- Java 前端和控制器事实。
- 当前 FastAPI 事实。
- 当前 React 事实。
- 设计假设、接口缺口和风险。

如果字段只存在于参考系统，不要直接放入“当前接口字段”。

### 4. 页面清单与目标

每个页面列出：

- 页面 ID、名称和路径。
- 主要使用者。
- 核心任务。
- 页面内浮层。
- 与其他页面的导航关系。

### 5. 信息架构和布局

使用树形文本和桌面端线框描述页面层级。多个页面分别描述，不把全部结构混成一个大图。

### 6. 字段与数据展示

分别定义：

- 查询字段。
- 表格列及格式。
- 新增/编辑字段、必填、默认值和校验。
- 详情展示字段。
- 状态、字典、空值和敏感字段显示规则。

### 7. 交互与状态

至少覆盖：

- 首次加载、刷新、搜索、重置和分页。
- 新增、编辑、详情和关闭未保存表单。
- 批量操作、权限不足和受保护数据。
- 删除、停用、密钥轮换等危险操作。
- 空数据、加载中、局部失败、整体失败和重试。
- 成功反馈及数据刷新策略。

### 8. 接口与权限

使用表格列出：

| 页面能力 | HTTP 方法与路径 | 请求 | 响应 | 权限 | 当前状态 |
| -------- | --------------- | ---- | ---- | ---- | -------- |

“当前状态”使用：已实现、部分实现、未实现、需要确认。接口路径和权限必须重新从当前源码确认。

### 9. 响应式与可访问性

说明：

- 宽屏、常规桌面、窄屏和手机的布局变化。
- 表格如何滚动或转为摘要卡片。
- 抽屉在小屏是否全屏。
- 键盘焦点、可访问名称、状态是否只依赖颜色。

### 10. 验收标准

验收项应可观察，例如：

- 用户能从列表进入详情并返回原查询状态。
- 删除受保护记录时显示阻塞原因且不改变列表。
- 390px 宽度下没有页面级横向溢出。

避免“体验良好”“布局美观”等不可验证表述。

## 写作规则

- 先给结论，再展开证据。
- 中文业务名后保留必要的代码字段名。
- 使用完整路径或相对链接指向实际资料。
- 明确区分原型行为与真实后端行为。
- 不粘贴大段后端源码，只提取契约和约束。
- 发现参考系统与当前系统冲突时，写清取舍原因。
